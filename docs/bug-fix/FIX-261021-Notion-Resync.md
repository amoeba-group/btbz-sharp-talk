# FIX-261021 — 같은 Notion 페이지를 새 소스로 다시 연결하면 동기화가 실패

## 증상 (스테이징 go2joy, 10/19~10/20)
Go2Joy 담당자가 Notion 소스를 삭제하고 다시 만들자, 새 소스 #18의 동기화가 매번 실패했다.

```
Duplicate entry '4-counsel-page:8968fee0bb548347a35e01756b4cc89c' for key 'kb_documents.uk_kb_extkey'
```

그 사이 Hotel Admin 가이드 전문(#2501, 2.5만 자)과 Notion FAQ(#3599)는 원래 소스가 삭제되면서 비활성화됐고, 다시 연결해도 살아나지 않았다. AI는 가이드 전문 없이 요약 문서와 G3 안내 문서로만 답하고 있었다.

## 원인
- `kb_documents`의 문서 키 고유 제약은 `(tenant_id, doc_group, external_key)`로 **테넌트 단위**다.
- 동기화(`SourceSyncService.sync`)는 기존 문서를 **이 소스의 문서**(`source_id = 현재 소스`)에서만 찾는다.
- 소스를 삭제하면 그 소스의 문서는 비활성으로 남고 키(Notion 페이지 ID)도 그대로다.
- 같은 페이지를 새 소스로 연결하면 기존 행을 못 찾아 INSERT → 고유 키 충돌 → 동기화 전체가 예외로 실패한다.

## 수정
이 소스에서 문서를 못 찾으면 같은 키를 가진 행을 한 번 더 찾는다.

| 기존 행 | 처리 |
|---|---|
| 비활성 | 새 소스로 옮기고(`source_id`) 내용 갱신·다시 활성화 (`adopted` 집계, 리비전 기록) |
| 활성이지만 소스가 삭제됨 | 위와 같음 |
| 활성 + 살아 있는 다른 소스 소유 | 그 페이지만 건너뜀, `failed`+1, `error`에 "Already synced by another live source … (source #n #문서id)" |
| 활성 + 수동 작성 문서(`source_id` NULL) | 건너뜀(운영자가 쓴 문서는 덮어쓰지 않음) |

다른 페이지의 동기화는 계속 진행된다. 스키마 변경 없음, UI 변경 없음(기존 동기화 이력 화면의 오류 칸에 사유가 보인다).

## 테스트
- `source-sync.service.spec.ts` +4건: 삭제 소스의 비활성 행 인수, 소스가 사라진 활성 행 인수, 살아 있는 다른 소스 행은 건너뛰고 나머지 진행, 수동 문서 보호
- API 전체 239 suites / 2363 tests 통과, tsc 통과

## 예방 패턴
고유 제약의 범위(테넌트)와 조회 범위(소스)가 다르면, "삭제 후 재생성"에서 반드시 충돌한다. 소프트 삭제(비활성)로 남기는 행이 고유 키를 쥐고 있다면 upsert 조회도 같은 범위로 해야 한다.
