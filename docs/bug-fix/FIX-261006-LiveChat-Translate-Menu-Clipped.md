# FIX-261006 — 라이브챗 번역 메뉴가 대화창 상단에 잘려 2개 언어만 보임

- 보고: `https://shoptalk.amoeba.site/live-chat?c=714` (go2joy, 메시지 2건) — 고객 메시지의 번역 아이콘을
  누르면 언어 목록 중 2개만 노출
- 범위: 콘솔 `apps/web/src/domain/live-chat/LiveChatPage.tsx` (UI 한 곳, API·스키마 무관)

## 원인
번역 팝오버가 `absolute bottom-full` — **항상 아이콘 위로** 열린다. 그런데 부모가 대화 스레드
(`overflow-y-auto` 스크롤 박스)라서 박스 밖으로 나간 부분이 잘린다. 메뉴 높이는 제목 + 6개 언어
≈ 180px. 메시지가 스레드 상단에 있으면(메시지 2건짜리 c=714의 첫 고객 메시지) 위쪽 여유가 수십 px뿐이라
**아래쪽 끝 두 줄만** 보였다. 메시지가 많아 스크롤이 내려간 대화에선 위쪽 여유가 충분해 드러나지
않았고, 메시지가 적은 대화(또는 스레드 첫 메시지)에서만 재현된다.

같은 모양의 선례: 지식 문서 목록 팝오버(PR #397) — "Table overflow가 absolute를 클리핑 → fixed".

## 수정
- 팝오버를 `fixed`(뷰포트 좌표)로 렌더하고, 클릭 시 아이콘의 `getBoundingClientRect()`로 위치 계산
  (`anchorTranslateMenu`).
- 위쪽에 메뉴 높이만큼 여유가 있으면 기존처럼 **위로**, 없으면 **아래로** 연다. 좌우는 화면 안으로 보정.
- 스레드가 스크롤되면 메뉴를 닫는다(fixed 메뉴가 메시지에서 떨어져 떠 있지 않게).
- DOM 위치는 그대로(행의 자식) → 기존 hover/focus 표시 규칙·언어 선택 동작 불변.

## 검증
- `tsc` web 통과, 웹 빌드 통과.
- 스테이징 배포 후 c=714(go2joy 콘솔)에서 번역 메뉴가 위로 열리며 6개 언어 전부 노출 ✅

## 예방 패턴
**스크롤 박스 안의 팝오버·드롭다운은 `absolute`로 두지 않는다.** 목록·스레드처럼 `overflow`가 걸린
컨테이너 안에서는 `fixed` + 앵커 rect + 공간에 따른 상하 반전. 항목 수가 늘어나는 메뉴(언어·상태)는
처음엔 맞아도 목록이 길어지는 순간 잘린다 — 높이를 항목 수로 계산할 것.
