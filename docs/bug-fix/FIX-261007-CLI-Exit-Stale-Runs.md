# FIX-261007 — CLI가 끝나도 종료되지 않음 · 중단된 회귀 실행이 영원히 "실행 중"

## 1. `kb:reindex`·`kb:import` CLI가 완료 후 종료되지 않음
- **현상**: 2026-10-07 go2joy FAQ 재임베딩 때 `kb:reindex`가 "✅ KB reindex complete"를 출력한 뒤 돌아오지 않았다(수동으로 프로세스 종료).
- **원인**: CLI가 전체 앱 컨텍스트(`NestFactory.createApplicationContext(AppModule)`)를 띄우면, 각 모듈의 타이머(동기화 스케줄러·스윕 22곳)도 함께 시작한다. 이 타이머가 이벤트 루프를 붙잡아 `app.close()` 뒤에도 프로세스가 끝나지 않았다.
  같은 이유로 **CLI 실행 중에 스케줄 작업이 한 번 더 돈다**. go2joy 첫 채점 실행 때 상품 동기화가 모든 테넌트에 대해 한 차례 추가로 시도됐다(실패 로그만 남고 데이터 영향 없음).
- **수정**: `database/cli-exit.ts` `closeAndExit(app)` — 최대 5초 동안 정상 종료를 시도하고 `process.exit(code)`. `kb-reindex`·`kb-import`에 적용(`verify-*`는 이미 exit 처리됨).
- **미수정(알려진 한계)**: CLI 중 스케줄러 중복 실행. 전역 스케줄러 차단 스위치를 넣으려면 22개 파일을 고쳐야 해서 이번 범위에서 뺐다. CLI는 짧게 끝나고 동기화 작업은 멱등이라 영향은 중복 시도 1회다.

## 2. 서버 재시작으로 중단된 회귀 실행이 "실행 중"으로 남음
- **원인**: 콘솔 회귀 실행은 백그라운드로 돈다(PLN-261007 R7). 그 사이 API가 재시작되면 실행 행이 `running`인 채로 남는다 → 화면이 계속 폴링하고 실행 버튼이 비활성화된다.
- **수정**: `GoldenService.onModuleInit` — 부팅 시 1시간 넘게 `running`인 실행을 `aborted`로 닫는다(60문항 실행 ≈ 10분). 화면에 "중단됨(서버 재시작)" 배지(6개 언어)를 표시한다. 실패해도 부팅은 막지 않는다.

## 3. 데이터 정정 (같은 날)
- go2joy 회귀 세트 I2의 기대 사실 `01/7/2025` → `7/2025`. 첫 채점 실행(#10, Hotel Partner)에서 유일한 실패였는데, 원인은 답변이 같은 날짜를 `01/07/2025`로 쓴 것이었다(판정 기준 문제). 결과는 **통과 40 · 실패 1 · 판정 없음 3** — 정정 후 기준으로는 41/41 통과에 해당한다.

## 재발 방지
- 앱 컨텍스트를 띄우는 스크립트는 `closeAndExit`로 끝낸다.
- 백그라운드 작업 상태 행에는 "고아 상태 정리" 경로를 함께 둔다.
- 기대 사실은 서식이 흔들리는 값(날짜·숫자 구분자)이면 변하지 않는 핵심부만 적는다.
