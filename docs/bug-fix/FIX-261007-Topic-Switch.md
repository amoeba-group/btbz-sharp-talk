# FIX-261007 — 주제를 바꾼 질문의 검색이 이전 주제에 끌려감

- 발견: 2026-10-01 실트래픽 점검(go2joy 대화 664, 메시지 17816)
- 관련: FIX-260806 A2(검색어에 이전 고객 발화), PLN-260929 S8(검색어에 직전 AI 발화 추가)

## 현상
고객이 "How do I create a front desk staff account…?"를 묻고 답을 받은 뒤 **"How do I process a guest check-in?"** 으로 주제를 바꿨다.
AI는 신뢰도 0.77로 "체크인 처리 방법에 대한 정보가 없습니다"라고 답했다. KB에는 `Video 21 — Processing a check-in`이 있다.

## 원인 (실측)
검색어는 "이전 고객 발화 2개 + 직전 AI 발화 + 현재 발화"다. API 컨테이너에서 Voyage+Qdrant를 직접 호출해 비교했다.

| 검색어 | top-1 | 결과 |
|---|---|---|
| A2(변경 전): 이전 질문 + 현재 | 0.66 | staff 계정 문서 |
| S8(현재): + 직전 AI 답변 | 0.77 | staff 계정 문서(더 강하게) |
| 현재 발화만 | 0.55 | **체크인 문서** |

이전 주제를 덧붙이는 장치는 주제어가 없는 후속 발화("2대", "예약 진행")를 살리기 위한 것이다. 하지만 **새 주제의 질문**에서는 이전 주제가 검색을 지배한다.
S8이 이 경향을 강화했고(0.66→0.77), 신뢰도가 높으니 핸드오프도 일어나지 않았다.

## 수정
`RagService.answer`: 문맥 검색어가 현재 발화와 다르면 **현재 발화만으로도 한 번 더 검색**해 합친다(`mergeOwnFirst`).
- 현재 발화 결과 상위 3건 → 문맥 결과 → 현재 발화 나머지 순, 문서 id로 중복 제거, 6건 상한
- 주제를 바꾼 질문은 자기 문서를 확보한다. 주제어 없는 후속 발화는 자기 검색 결과가 빈약하므로 문맥 결과가 나머지 자리를 채운다.
- 비용: 후속 턴당 검색 1회(임베딩 1회) 추가. 첫 턴과 콘솔 단발 질의(문맥 검색어 없음)는 1회 그대로다.

## 재발 방지 패턴
- **검색어를 보강할 때는 원래 질문만으로 한 검색도 결과에 남긴다.** 보강은 더하는 것이어야 하고, 원래 검색을 대체하면 안 된다(그룹 선호 S9의 "편향 없는 상위 보존"과 같은 원리).
- 맥락 보강을 바꾸면 "주제 전환" 케이스를 반드시 실측한다. 후속 발화만 시험하면 이 결함이 통과한다.
