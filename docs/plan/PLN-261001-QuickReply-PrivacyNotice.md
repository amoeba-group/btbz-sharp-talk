## 1. ① 빠른 답변 버튼

### 1-1. 고치는 것 두 곳 (역할이 다르다)

| 지점 | 변경 | 성격 |
|---|---|---|
| **서버** `scenario.service.handle()` | 스크립트가 없는 액션(`message` 포함)은 404 대신 **일반 채팅 메시지로 처리** + `logger.warn` | 모든 클라이언트를 한 번에 덮는 **안전망** |
| **콘솔 미리보기** `PreviewPanel.tsx` | 칩 클릭을 액션별로 분기 — 스크립트 액션만 `/chat/scenario`, 나머지는 **`/chat/message`** | 위젯과 같은 동작을 미리보기에서도 |

서버만 고쳐도 404는 사라지지만, 그러면 미리보기는 "시나리오 턴"으로 계속 포장한다.
미리보기만 고치면 구 위젯·SDK·다음 클라이언트가 같은 404를 다시 만난다. **둘 다 한다.**

### 1-2. 서버 폴백이 "조용한 성공"이 되지 않게

```ts
const builtIn = SCENARIOS[action];
if (!builtIn) {
  // 설정 오류(없는 액션)와 의도된 메시지 버튼이 같은 모양으로 들어온다. 둘 다
  // 답을 주되, 흔적은 남긴다 — 4xx는 서버 로그에 안 남아서 지금까지 이 404는
  // 운영자에게만 보였고 우리에겐 보이지 않았다.
  this.logger.warn(`scenario action "${action}" has no script — answering as a chat message`);
  return this.chatService.handleAsMessage(session, labelOrMessage);
}
```

- `message`는 **정상 경로**, 그 외 미지 액션은 **경고**. 로그 문구를 하나로 두되, 알려진
  `message`는 debug·그 외는 warn으로 가른다.
- 응답 모양은 기존 `ScenarioTurnResult`를 유지한다 — 호출자는 시나리오 응답을 기대하고 있다.

### 1-3. 버튼이 보낼 문장 (D2)

```ts
export interface ScenarioButton {
  id: string;
  label: string | LocalizedText;
  action: string;
  enabled: boolean;
  /** `message` 액션이 보낼 문장. 비우면 라벨을 보낸다(기존 동작). */
  message?: string | LocalizedText;   // ← 신설
}
```

- 라벨과 **같은 자료형**(문자열 또는 언어별 맵)을 쓴다. 해석도 같은 `scenarioLabelText`.
- 비어 있으면 라벨 — 지금 go2joy의 네 버튼은 **아무것도 하지 않아도 지금과 같이 동작**한다.
- 위젯은 `doSend(resolve(button.message) || button.label)`, 서버 폴백도 같은 우선순위.
- 저장은 기존 `tenant_ai_config.scenario_buttons`(json) 안이라 **스키마 변경 없음**.

## 2. ③ 개인정보 안내 문구 (D3 = C)

### 2-1. 어디서 와서 어디로 가나

지금: 문구 6줄이 **위젯 i18n에 6언어 하드코딩**.
앞으로: **서버가 고지 문구를 내려준다.** 위젯 i18n의 문구는 **서버가 아무 말도 하지 않을 때의
최후 폴백**으로만 남긴다(구 위젯 호환).

```
프로필 문구(플랫폼, 6언어)          ← commerce | lodging | generic
        ↓  테넌트가 채운 줄만 덮어씀
테넌트 덮어쓰기(언어별, 비면 프로필) ← tenants.privacy_notice_copy
        ↓
session/ensure 의 privacyNotice 에 실려 위젯으로
```

### 2-2. 데이터

```sql
-- sql/261001-tenant-privacy-notice-copy.sql
ALTER TABLE `tenants`
  ADD COLUMN `privacy_profile` varchar(16) DEFAULT NULL AFTER `consent_notice_version`,
  ADD COLUMN `privacy_notice_copy` json DEFAULT NULL AFTER `privacy_profile`;
```

```jsonc
// privacy_notice_copy — 채운 줄만 존재한다(빈 값은 아예 저장하지 않는다)
{ "KO": { "items": "수집 항목: 채팅 메시지, 예약 조회 내역, 기본 기기 정보" },
  "EN": { "items": "What we collect: your chat messages, booking lookups, basic device info" } }
```

- 프로필 NULL = `commerce_enabled`로 추론(1→commerce, 0→generic). **기존 테넌트는 설정 없이도
  오늘과 같은 문구**를 보고, 숙박 테넌트는 프로필만 바꾸면 된다.
- 문구 키는 위젯이 이미 쓰는 6개: `title · body · items · purpose · retention · aiProcessor`.
- 정규화·병합은 `packages/types/src/common/privacy-notice-copy.ts`(순수 함수)에 두고
  서버·테스트가 같은 코드를 쓴다 — `widget-access`·`widget-theme`와 같은 패턴.

### 2-3. 프로필 문구 (플랫폼이 6언어 유지)

| 키 | commerce(현행) | lodging | generic |
|---|---|---|---|
| items | 채팅 메시지, **주문 조회 내역**, 기기 정보 | 채팅 메시지, **예약 조회 내역**, 기기 정보 | 채팅 메시지, 기기 정보 |
| purpose | 문의 응대 및 **고객 지원** | 문의 응대 및 **숙박 이용 지원** | 문의 응대 |
| title·body·retention·aiProcessor | 공통(지역·보관기간은 기존대로 보간) | | |

### 2-4. 재동의 (D5 = 운영자 선택)

문구 저장 화면은 **버전을 올릴지 묻는다**. 체크하면 `consent_notice_version`이 올라가고
기존 동의자 전원이 다시 묻는다(이미 있는 `noticeOutdated` 경로). 체크하지 않으면 문구만 바뀐다.

```

│ 개인정보 처리방침 URL [ https://…                         ] │

│ 동의 안내 버전        [ 2026-07 ]   ⚠ 미설정                │
```

### 2-5. 폴백 순서 (빈 칸이 빈 고지가 되지 않게)

```
테넌트 덮어쓰기[언어][키]  →  프로필 문구[언어][키]  →  프로필 문구[EN][키]
```

언어 하나만 채우고 나머지를 비워도, 다른 언어 방문자는 **프로필 문구**를 본다 — 빈 줄이 아니라.

## 3. 단계

| 단계 | 내용 | 스키마 |
|---|---|---|
| **P1** | 서버 폴백 + 콘솔 미리보기 분기 + 회귀 테스트 | 없음 |
| **P2** | 버튼 `message` 필드(타입·콘솔 편집기·위젯/서버 해석) | 없음(json 내부) |
| **P3** | 고지 문구: 프로필 문구 테이블 + 병합 함수 + `privacyNotice()`가 문구를 싣기 + 위젯이 서버 문구 우선 | SQL 1건 |
| **P4** | 콘솔 개인정보 안내 화면(프로필·덮어쓰기·버전 체크·미설정 경고) + i18n 6언어 | 없음 |

P1은 단독으로 배포 가능하고, **그것만으로 보고된 404가 사라진다.**

## 4. 사이드 임팩트

| 대상 | 영향 | 조치 |
|---|---|---|
| 기존 `message` 버튼(go2joy 4개) | 서버·미리보기 모두 답을 주게 된다. 위젯 동작은 **불변** | 없음 |
| 스크립트 액션(`delivery_status` 등) | 경로 불변 — 폴백은 `SCENARIOS`에 없을 때만 | 회귀 테스트로 고정 |

| **고지 문구를 서버가 내려주기 시작** | 구 위젯은 새 필드를 무시하고 번들 문구를 쓴다(추가형) | 계약은 optional |

| 모더레이션·AI | 무관 | — |
| 통계 | 버튼 클릭 이벤트(`analytics.scenarioClick`)는 그대로 | — |

## 5. 테스트 계획 (TCR-261001)

- **서버**: `message` → 메시지로 처리되고 응답 모양이 시나리오 턴 / 미지 액션 → 같은 처리 + **warn 1회** /
  스크립트 액션 → 기존 경로 그대로(회귀) / 버튼 `message` 우선순위(있으면 문장, 없으면 라벨)
- **문구 병합**: 덮어쓰기 > 프로필 > 프로필 EN / 빈 문자열은 덮어쓰기로 치지 않음 / 프로필 NULL일 때
  `commerce_enabled`로 추론 / 알 수 없는 프로필 값은 generic
- **콘솔**: 미리보기에서 `message` 칩 → `/chat/message` 호출(네트워크 단언) · 스크립트 칩 → `/chat/scenario` /
  버전 체크 해제 시 버전 불변, 체크 시 증가
- **위젯**: 서버 문구가 오면 그것을, 없으면 번들 문구를(구 위젯 호환)
- **실측(스테이징)**: go2joy 테넌트에서 버튼 4개 전부 눌러 답이 오는지, 숙박 프로필로 바꾼 뒤 고지에
  "예약 조회"가 나오는지

## 6. 명시적으로 안 하는 것

- 고지 문구 **전면 자유 편집**(REQ D3-B). 프로필 밖의 새 줄 추가·삭제는 범위 밖이다.
- 법무 검토 워크플로(승인자·이력). 덮어쓰기 책임은 콘솔 문구로 고지하는 선까지.
- 시나리오 **스크립트 자체**를 테넌트가 새로 만드는 기능(기존 `scenario_overrides`로 편집만).
