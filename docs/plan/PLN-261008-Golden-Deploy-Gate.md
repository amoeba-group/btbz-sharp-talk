# PLN-261008 — 배포 후 FAQ 회귀 자동 채점 (R7 후속, D2)

- 근거: PLN-261007-Golden-Graded-Regression D2("배포 전 자동 실행은 후속"), RPT-261007-Golden-Graded-Regression §5
- **UI 변경 없음.** **스키마 변경 없음.**
- 상태: **승인 대기**

## 1. 목표와 범위
- 스테이징에 배포한 직후, 지정한 테넌트·에이전트의 채점 세트를 **자동으로 한 번 돌리고**, 실패가 있으면 **dev@amoeba.group으로 메일**을 보낸다.
- "배포 전"이 아니라 **배포 후**다. 채점은 새 코드가 떠 있어야 의미가 있고, CI에는 실 AI·DB가 없다.
- 실패해도 **자동 롤백하지 않는다**(판정은 사람이). 배포 스크립트의 종료 코드도 바꾸지 않는다(배포 성공·채점 실패를 구분해 보고).

## 2. 단계
### S1 — CLI `npm run golden:gate` (`src/database/golden-gate.ts`)
- 환경변수 `GOLDEN_GATE` = `tenantId:aiAgentId[,tenantId:aiAgentId…]` (예: `4:10`). 비어 있으면 아무것도 하지 않고 종료(기본 꺼짐)
- 대상마다 `GoldenService.run(…, { aiAgentId, label: 'deploy gate <sha>' })`를 **동기**로 실행 → 직전 실행과 `compare`
- 판정: **실패 문항이 1개 이상**이거나 **회귀(통과→실패)** 가 있으면 "실패"
- 결과 요약(통과/실패/회귀 문항과 빠진 사실)을 표준출력과 메일(`AI_ALERT_EMAIL ?? dev@amoeba.group`)로 보낸다. 전부 통과하면 메일 없이 한 줄 로그만 남긴다
- 끝은 `closeAndExit`로(FIX-261007)

### S2 — 배포 스크립트 연결 (`docker/staging/deploy-staging.sh`)
- 기존 단계 뒤에 추가: API 컨테이너가 `healthy`가 될 때까지 대기(최대 120초) → `docker exec … node dist/database/golden-gate.js`
- **백그라운드(nohup)** 로 실행해 배포를 붙잡지 않는다(44문항 ≈ 8~10분). 로그는 `/tmp/golden-gate-<sha>.log`
- 프로덕션 스크립트에는 넣지 않는다(프로덕션은 아직 실 트래픽·키 없음 — 키 등록 후 별도 결정)

### S3 — 설정
- 스테이징 `.env.staging`에 `GOLDEN_GATE=4:10`(go2joy · Hotel Partner)을 추가한다
- env 템플릿 4종에 `GOLDEN_GATE=`(빈 값 = 꺼짐)를 추가한다(CI 템플릿 게이트)
