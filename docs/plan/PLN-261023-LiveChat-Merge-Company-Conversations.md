## 2. 데이터 (SQL `sql/261023-merged-rooms-company.sql`, 선적용)
```sql
ALTER TABLE merged_rooms MODIFY customer_id BIGINT NULL;
ALTER TABLE merged_rooms ADD COLUMN company_id BIGINT NULL;
ALTER TABLE merged_rooms ADD UNIQUE KEY uq_mroom_tenant_company (tenant_id, company_id);
```
- 기존 방(현재 스테이징·프로덕션 모두 0개)은 그대로 둔다. 롤백은 UNIQUE 삭제 → 컬럼 삭제 → `customer_id NOT NULL`이다.

## 3. 단계
- **S1 판정 확장**: 세션의 기업(`sessions.company_id` ∪ 그 세션 대화의 `company_id`)이 같은 세션을 후보에 넣는다(`matchedBy: 'company'`). 방 찾기는 `customer_id IN (…) OR company_id IN (…)`. 통합하면 방에 기준 기업도 기록한다. 자동 가입도 같은 판정을 쓴다. 게스트(고객·기업 모두 없음)는 여전히 E5105다.
- **S2 이전 대화 모달**: 행마다 체크박스(이미 같은 방이면 "통합됨"), 하단에 자동 추가 체크와 [선택한 대화 통합(N)]. 기존 `POST merged-rooms`에 선택한 대화들의 세션 id를 보낸다. 서버는 같은 고객 또는 같은 기업인지 다시 확인한다. 행 클릭으로 그 대화를 여는 동작은 유지한다.
- **S3 문구**: `company.earlier`·`company.earlierTitle` 6개 언어, `merge.matchedBy.company` 추가.
