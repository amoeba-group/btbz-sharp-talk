## 3. 단계별 작업

### S1. 탭 분리 (프런트만)
- 새 파일 `SettingsHandoffPage.tsx`: `HandoffSection`만 렌더링한다.
- `SettingsBasicPage.tsx`: `HandoffSection`을 뺀다.
- `SettingsLayout.tsx`: `TABS`의 2번째에 `{ to: '/settings/handoff', labelKey: 'settingsHandoff', code: 'settings_basic' }`을 넣는다(D1·D2).
- `AppRouter.tsx`: `path: 'handoff'`를 추가한다.
- 링크 갱신: 상담원 연결로 가는 기존 링크·안내 중 `/settings/basic`을 가리키는 것을 찾아 `/settings/handoff`로 바꾼다(grep).
- nav i18n `settingsHandoff` 6개 언어.

### S2. 카테고리 저장소·API
- **SQL** `sql/261024-routing-categories.sql`
  - `routing_categories(id BIGINT PK, tenant_id BIGINT, code VARCHAR(64), name VARCHAR(100) NULL, sort_order INT DEFAULT 0, created_at, updated_at, UNIQUE uq_rcat_tenant_code(tenant_id, code))`
  - 기본 5개 INSERT(D4): 지역 값을 하나라도 가진 테넌트를 SELECT로 골라 넣는다. 멱등(`INSERT IGNORE`).
  - `migrations:manifest` 갱신.
- 엔티티 `ai-engine/entity/routing-category.entity.ts`: nullable 컬럼에 명시적 `type`, `bigintTransformer`.
- `RoutingCategoryService`(ai-engine 모듈)
  - `list(tenantId)`
  - `create(code, name)`: 코드를 `canonicalRegion`으로 정규화하고 `^[a-z0-9_]{1,64}$`를 검사한다. 중복이면 E5108.
  - `update(id, {name, sortOrder})`: 일괄 처리.
  - `remove(id)`: 사용처를 검사한다. 규칙 `regions`, `units.regions`, `job_labels.regions`, `companies.region` 중 하나라도 쓰면 E5107과 사용처 목록을 돌려준다.
  - `usage(tenantId)`: 모달의 "사용처" 칸.
  - `codes(tenantId)`: 검증용.
- 컨트롤러 `routing-categories`
  - `GET`: `@Auth()`. 응답에 사용처 수를 포함한다.
  - `POST`, `PATCH`(일괄), `DELETE /:id`: `@RequireCapability(AI_SETTINGS_MANAGE)`.
  - 모두 감사 로그 `routing_category.*`를 남긴다.
- 오류 코드(다음 빈 번호): E5107 `ROUTING_CATEGORY_IN_USE`, E5108 `ROUTING_CATEGORY_DUPLICATE`, E5109 `ROUTING_CATEGORY_NOT_FOUND`. 6개 언어 메시지를 추가한다.
- 검증 교체(G4)
  - `unit.request.ts`와 `company.request.ts`의 `@IsIn(REGION_CODES)`를 형식 검사(`canonicalRegion` 형태)로 바꾼다.
  - 존재 여부는 서비스에서 `codes(tenantId)`와 대조한다. 없는 코드는 E5109.
  - 라벨 regions도 같은 방식으로 한다.
- **라우팅 매칭은 바꾸지 않는다**(`handoff-router.service.ts`). 규칙의 `regions` 코드와 세션 `region`을 정규화해서 비교하는 방식은 지금과 같다.

### S3. 화면
- 훅 `useRoutingCategories()`(React Query 키에 tenantKey)와 변경 훅. 성공·실패 토스트를 띄운다.
- `RoutingRulesEditor.tsx`
  - prop으로 `categories: {code, name}[]`를 받는다.
  - `REGION_CODES` 순회 2곳(칩, 카테고리별 후보)을 목록으로 바꾼다.
  - 목록에 없는 저장값은 지금처럼 "기타: 코드"로 보인다.
  - 머리글에 [카테고리 관리] 버튼. `AI_SETTINGS_MANAGE`일 때만 보인다.
- 새 파일 `RoutingCategoriesModal.tsx`: 와이어프레임 2-3.
- `RegionScopeEditor.tsx`(사용자 화면): 선택지를 카테고리 목록으로, 제목을 "담당 카테고리"로 바꾼다.
- `CompaniesPanel.tsx`: 지역 선택지와 표시를 카테고리 목록으로 바꾼다. 칸 이름 "지역"은 유지한다(D5).
- **표시 이름 규칙**
  - `name`이 있으면 그 값을 쓴다.
  - `name`이 비어 있고 코드가 기본 5개 중 하나면 기존 i18n 이름(북부 등)을 쓴다.
  - 둘 다 아니면 코드를 그대로 보여준다.
  - 기본 5개를 SQL로 넣을 때 `name`은 NULL로 둔다. 그래야 언어를 바꿔도 이름이 번역된다.
- i18n 6개 언어
  - `aiSetting.handoff.routing.title`, `regions`, `any`, `assignee.byRegion*` 문구에서 "지역"을 "카테고리"로 바꾼다.
  - `users.scope*`도 같은 방식으로 바꾼다.
  - 새 키 `handoff.routing.categories.*`(모달)를 추가한다.
  - `i18n:check`를 실행한다.
