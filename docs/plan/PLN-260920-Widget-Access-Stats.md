## 1. 설계 요지

접속 로그 테이블을 새로 만들지 않습니다. **`sessions` 행이 이미 노출 1건**이므로
(REQ §1.1), 그 행에 **URL과 열람 횟수**를 채우면 세 축(전체·에이전트별·URL별) × 세
지표(노출·접속·대화)가 **단일 테이블 GROUP BY**로 나옵니다.

| 지표 | 정의 | 소스 |
|---|---|---|
| **노출** | 위젯 iframe 로드 | `COUNT(sessions)` |
| **접속(횟수)** | 패널을 연 횟수 | `SUM(sessions.open_count)` |
| **접속(고유)** | 패널을 한 번이라도 연 세션 | `COUNT(open_count > 0)` |
| **대화** | 대화가 생성된 세션 | `conversations.session_id` 조인 |

전환율은 **고유 세션 기준**(REQ §3.3b): 열람률 = 접속(고유)/노출, 대화 전환율 =
대화/접속(고유).

> **왜 이벤트 테이블이 아닌가**: 열람 시각별 분석(시간대·재열람 간격)을 원하면 이벤트
> 테이블이 맞지만, 이번 요구(세 축 × 카운트)에는 세션당 카운터로 충분하고 쓰기·보존·
> 조인 비용이 모두 낮습니다. 시각 분석이 필요해지면 그때 이벤트 테이블을 별건으로.

## 3. 단계

### S1 — 접속(열람) 수집
- 스키마: `sessions.open_count` INT NOT NULL DEFAULT 0, `first_opened_at` DATETIME NULL.
- API: `POST /session/opened { session_token }` — `open_count` +1, 최초에만
  `first_opened_at` 기록. `@Public()`(위젯 경로), 세션 토큰으로만 식별.
- 위젯: `Widget.tsx`의 **기존 전환 감지 지점**에서 호출(신규 감지 로직 없음).
  **fire-and-forget** — 실패해도 위젯 동작에 영향 없음(await 금지).
- 남용 가드: 세션당 상한(예: 50) 초과 시 서버가 조용히 무시 — 한 세션이 통계를
  왜곡하지 못하게.
- 미리보기(`channel='preview'`)는 수집·집계 모두 제외.

### S2 — 노출 URL 수집
- 스키마: `sessions.landing_path` VARCHAR(255) NULL.
- `EnsureSessionRequest`에 `landing_path?: string` 추가.
- **정규화는 서버에서**(클라이언트를 믿지 않음): `scheme://host/pathname`만 남기고
  쿼리·해시 폐기, 255자 컷, 파싱 실패 시 NULL.
- 위젯은 이미 가진 값을 전달 — `readTrafficSource().landingPage`(GA4용으로 이미 파싱
  중)를 `ensureSession`에 함께 넘김. **신규 수집 채널 없음.**

### S3 — 집계 API
- `GET /analytics/access?start&end` — 기존 breakdown 라우트와 동일 패턴
  (`analytics-breakdown.service.ts`에 메서드 추가).
- 반환: `{ totals, daily[], byAgent[], byPath[] }`, 각 항목이 노출·접속횟수·접속고유·
  대화를 함께 가짐. `byPath`는 상위 20 + `others` 합계.
- 0 나눗셈 가드, 삭제된 에이전트는 기존 관례대로 `삭제된 에이전트 (#id)`.

### S4 — 화면
- `SECTIONS`에 `access` 추가(질문 분석 다음), `LOG_BACKED_SECTIONS`에도 추가
  (보존기간 안내가 자동으로 붙음).
- `AccessSection.tsx` 신설 — 깔때기 타일 + 추이 + 표 2개(§2).
- i18n 6개 로케일, `npm run i18n:check` 통과 필수.

### S5 — 검증·배포
- 단위: URL 정규화(쿼리 제거·비URL·초과길이), 열람 카운트(중복 전환 무시·상한·
  preview 제외), 집계(전환율 분모=고유 세션·상위 N+others·NULL 에이전트 라벨).
- **SQL 선적용 → 코드 배포**(§6). 스테이징 실데이터로 화면 확인.
- TCR/RPT 작성.

## 4. 측면 영향

- `sessions`는 페이지 로드마다 쓰기가 일어납니다. 컬럼 3개 추가는 값 쓰기 수준이고,
  집계용 인덱스는 1개만 추가합니다.
- **`ensure`는 위젯의 첫 요청이라 실패하면 위젯이 죽습니다** — URL 파싱은 전부
  try/catch, 실패 시 NULL 저장.
- `POST /session/opened`는 **열람 시에만** 발생(노출의 4% 수준) — 트래픽 부담 미미.
- 기존 6개 섹션의 쿼리·정의는 건드리지 않습니다(탭 추가만).
- 동의(consent) 게이트와 무관: 세션 행 자체가 이미 동의 전에 생성되며, 수집값은
  PII가 아닌 운영 카운터입니다(GA4와 달리 마케팅 추적이 아님).

## 7. 범위 밖

- 열람 **시각**별 분석(시간대별 열람, 재열람 간격) — 이벤트 테이블이 필요, 별건.
- URL 패턴화(`/products/:handle`) — 1차는 경로 전체 + 상위 N (O2).
- 소급 채우기 — 불가.
- GA4 수치와의 일치 보장 — GA4는 동의 게이트 뒤라 모수가 다릅니다.

확인해 주시면 바로 착수합니다.
