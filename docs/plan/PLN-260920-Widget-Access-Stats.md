## 1. 설계 요지

접속 로그를 새로 만들지 않습니다. **`sessions` 행이 이미 위젯 노출 1건**이므로
(REQ §1.1), 빠진 축인 **URL 한 컬럼만** 채우면 세 축이 모두 기존 테이블에서 나옵니다.

| 축 | 소스 | 신규 필요 |
|---|---|---|
| 전체 | `sessions` 기간 집계 | 없음 |
| 에이전트별 | `sessions.ai_agent_id` (+`idx_sessions_tenant_agent`) | 없음 |
| URL별 | `sessions.landing_path` | **컬럼 1개 + 인덱스** |
| 참여율 | `conversations.session_id` 조인 | 없음 |

## 3. 단계

### S1 — URL 수집 (백엔드·위젯)
- `sessions.landing_path` VARCHAR(255) NULL 추가(+ `(tenant_id, landing_path)` 인덱스).
- `EnsureSessionRequest`에 `landing_path?: string` 추가(snake_case, 선택).
- **정규화는 서버에서**(클라이언트를 믿지 않음): `scheme://host/pathname`만 남기고
  쿼리·해시 폐기, 255자 컷, 유효 URL이 아니면 NULL.
- 위젯은 이미 가진 값을 보냅니다 — `readTrafficSource().landingPage`(GA4용으로 이미
  파싱 중)를 `ensureSession`에 함께 전달. **신규 수집 채널을 만들지 않습니다.**
- 미리보기 세션(`channel='preview'`)은 수집·집계 모두 제외.

### S2 — 집계 API
- `GET /analytics/access?start&end` — 기존 breakdown 라우트와 동일 패턴
  (`analytics-breakdown.service.ts`에 메서드 추가).
- 반환: `{ totals: {impressions, engaged, rate}, daily[], byAgent[], byPath[] }`.
- `byPath`는 상위 20 + `others` 합계. 정렬은 노출 내림차순.
- 참여율 = `engaged / impressions` (0 나눗셈 가드).
- **기존 "대화 수" 정의와 충돌하지 않도록** `engaged`는 "세션에 conversation이 1건
  이상"으로 정의하고 응답 필드명에 명시(해결/미해결 정의와는 무관한 축).

### S3 — 화면
- `SECTIONS`에 `access` 추가(질문 분석 다음), `LOG_BACKED_SECTIONS`에도 추가
  (보존기간 안내 문구가 자동으로 붙습니다).
- `AccessSection.tsx` 신설 — 타일 4개 + 추이 + 표 2개(§2).
- i18n 6개 로케일 키 추가, `npm run i18n:check` 통과 필수.

### S4 — 검증·배포
- 단위: 정규화(쿼리 제거·비URL·초과길이·preview 제외), 집계(참여율·상위 N+others·
  NULL 에이전트 라벨).
- **마이그레이션 선적용 후** 배포(§5), 스테이징에서 실데이터로 화면 확인.
- TCR/RPT 작성.

## 4. 측면 영향

- `sessions`는 쓰기 빈도가 높습니다(페이지 로드마다 1행). **컬럼 추가는 값 하나 더
  쓰는 수준**이고 인덱스는 집계용 1개만 — 기존 쓰기 경로에 의미 있는 부담 없음.
- `ensure`는 위젯 첫 요청이라 **실패하면 위젯이 죽습니다.** URL 파싱은 전부 try/catch로
  감싸 실패 시 NULL 저장(수집 실패가 위젯을 멈추게 해서는 안 됨).
- 기존 6개 섹션의 쿼리·정의는 건드리지 않습니다(탭 추가만).

## 5. Migration

| 항목 | 내용 |
|---|---|
| SQL | `sql/260920-sessions-landing-path.sql` |
| 내용 | `ALTER TABLE sessions ADD COLUMN landing_path VARCHAR(255) NULL AFTER channel;` + `ADD INDEX idx_sessions_tenant_path (tenant_id, landing_path)` |
| 적용 순서 | **SQL 선적용 → 코드 배포** (구 코드 + 새 컬럼 = 안전 / 새 코드 + 구 스키마 = 500) |
| 스테이징 | [ ] 적용 |
| 프로덕션 | [ ] 적용 (별도 승인) |
| 롤백 | `DROP INDEX idx_sessions_tenant_path ON sessions; ALTER TABLE sessions DROP COLUMN landing_path;` (수집만 중단, 기존 데이터 무영향) |

## 6. 범위 밖

- **패널 열람 횟수**(O1): 서버에 미기록. 필요하면 신규 이벤트 수집이 추가로 필요 —
  별건 권장.
- **URL 패턴화**(O2, `/products/:handle`): 1차는 경로 전체 + 상위 N.
- 소급 URL 채우기: 불가(수집 시작일 이전 노출에는 URL 없음).
- GA4 연동과의 수치 일치 보장: GA4는 동의 게이트 뒤에서만 동작하므로 애초에 모수가
  다릅니다. 화면에 GA4 대조를 내세우지 않습니다.
