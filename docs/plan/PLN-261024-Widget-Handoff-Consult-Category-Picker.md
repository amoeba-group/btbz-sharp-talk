## 1. 결정 사항 (권장안 ★)

| # | 결정 | 선택지 | 권장 |
|---|---|---|---|
| D1 | AI 인계(B 경로)에서 선택 시점 | (a) 바로 호출하고, 고르면 재라우팅 / (b) 고를 때까지 호출 보류(시간 제한 후 기본 라우팅) | ★(a). 호출을 늦추지 않는다. 고객이 카드를 무시해도 지금과 같다. (b)는 보류 타이머와 스케줄러가 필요하고, 고객이 창을 닫으면 지연이 그대로 남는다. |
| D2 | 재라우팅 조건 | 아직 아무도 수락하지 않은 대기 대화에서 첫 선택 1회만 | ★권장. 이미 배정된 대화의 담당자를 고객 선택으로 바꾸지 않는다. |
| D3 | 고객 선택과 서명 region의 관계 | (a) 규칙 조건은 둘 중 하나와 맞으면 통과, 담당자 배정은 고객 선택 우선 / (b) 고객 선택이 region을 대체 | ★(a). go2joy의 "지역" 규칙(서명 region)이 그대로 동작하고, "업무 종류" 상담카테고리가 함께 쓰인다. |
| D4 | 직전 상담원 우선(`preferPreviousAgent`) | (a) 고객이 고르면 건너뛰고 그 상담카테고리 규칙을 따름 / (b) 계속 직전 상담원 우선 | ★(a). 고객이 "결제"를 골랐는데 지난번 예약 담당이 받는 것은 선택의 의미가 없다. 고르지 않으면 지금처럼 직전 상담원 우선이다. |
| D5 | 고객에게 보일 이름 | (a) 기본 이름 + 언어별 이름(선택 입력) / (b) 이름 하나 | ★(a). 위젯은 6개 언어다. 언어별 이름이 없으면 기본 이름, 그다음 내장 이름, 그다음 코드 순으로 쓴다. |
| D6 | 노출 기본값 | 기존 행(go2joy 5개) = 노출 안 함 / 새로 만들 때 = 노출함(추가 줄의 체크박스로 끌 수 있음) | ★권장. 배포만으로는 어느 위젯도 바뀌지 않는다. 새로 만드는 것은 대부분 고객용이다. |
| D7 | 카드의 "건너뛰기" | 항상 표시 | ★권장. 고르지 않으면 지금처럼 연결된다. |

## 3. 단계별 작업

### S1. 스키마 (SQL 먼저 적용)
`sql/261024-consult-category-visibility.sql`:
- `routing_categories`
  - `ADD visible TINYINT(1) NOT NULL DEFAULT 0`. 기존 행은 0이 된다(D6).
  - `ADD names JSON NULL`: 언어별 이름 `{en,es,vi,ja,zh,ko}`.
- `conversations`
  - `ADD consult_category VARCHAR(64) NULL`
  - `ADD consult_category_at DATETIME(6) NULL`
- 엔티티 2곳에 nullable `type`을 명시한다. `migrations:manifest`를 갱신한다.

### S2. API
- `RoutingCategoryService`
  - `create`에 `visible`(기본 true, D6)과 `names`를 받는다.
  - `update` 항목에 `visible`과 `names`를 추가한다.
  - 응답에 `visible`과 `names`를 넣는다. 감사 metadata에 변경 내역을 남긴다.
  - `visibleFor(tenantId, language)`: 위젯용 `[{code, label}]`. 표시명은 D5 순서로 해석하고, 내장 5개 이름은 서버 측 사전으로 해석한다.
  - `isVisible(tenantId, code)`: 위젯 입력 검증용.
- 위젯 설정(ensure 응답, `session.mapper`)에 `consultCategories: [{code,label}]`를 넣는다. 노출 0개면 빈 배열이다.
- **A 경로**: `EscalateRequest.category_code?`
  - 노출함 코드면 대화에 저장하고 시스템 줄을 남긴다.
  - 그 값을 `routingContext.consultCategory`로 넘겨 라우팅한다. D4에 따라 직전 상담원 우선을 건너뛴다.
  - 그 밖의 값은 무시하고 `logger.warn`.
- **B 경로**: `POST /chat/consult-category {conversation_id, category_code}` (`@Public`, 세션 토큰)
  - 소유를 검사하고, 노출 코드인지 검사한다(아니면 E5109).
  - 저장하고 시스템 줄을 남긴다.
  - 대화가 `waiting`이고 `agent_id`가 없으며 첫 선택이면 재라우팅한다. ESCALATION 이벤트를 다시 발행하고 `reason: 'category_selected'`를 붙인다(D2).
  - 응답은 `{ rerouted: boolean }`.
- `sendMessage` 응답에 `handedOff: boolean`을 추가한다. 이번 턴에 인계가 일어났는지 위젯이 알 수 있게 하기 위해서다.
- 라우터(`handoff-router.service.ts`)
  - `RoutingContext.consultCategory?`를 추가한다.
  - 규칙 regions 조건은 `[region, consultCategory]` 중 하나와 맞으면 통과한다(D3).
  - 담당자 배정(`resolveRegionAssignees`)은 consultCategory를 먼저, 다음 province, 다음 region 순으로 본다. 공용 함수(`packages/types` routing-assignee)에 선택 인자를 추가한다.
  - 로그에 `category=…`를 남긴다.
- 사용처 집계와 삭제 거부에 `conversations.consult_category`는 넣지 않는다. 기록용이고, 삭제해도 과거 대화에는 코드로 남는다.
- 오류 코드는 새로 만들지 않는다(E5109 재사용).
- 상담원 콘솔 대화 상세 응답에 `consultCategory`(코드, 표시명)를 넣는다.

### S3. 위젯
- `services/chatService`: `escalate(token, convId, categoryCode?)`, `chooseConsultCategory(...)`.
- 새 카드 `ConsultCategoryCard.tsx`: 칩 + [건너뛰기]. 위젯 테마 토큰과 반경 토큰을 쓰고 `radius:check`를 통과해야 한다.
- `ChatTab`
  - A 경로 4곳(버튼, `agent_connect`, `connect_agent`, 문의 카드)을 `requestAgent()` 하나로 모은다.
  - 노출 상담카테고리가 있으면 `setInline('consultCategory', mode:'before')`, 없으면 바로 `escalate()`.
  - B 경로는 `send()` 결과의 `handedOff`가 참이고 목록이 있으면 `mode:'after'` 카드를 띄운다.
  - 고르면 `chooseConsultCategory`, 건너뛰면 카드를 닫는다.
  - 한 대화에서 고른 뒤에는 다시 띄우지 않는다.
- 위젯 i18n 6개 언어: `chat.consultCategory.title`, `.titleAfter`, `.skip`. 시스템 줄 문구는 서버가 세션 언어로 만든다(sysMsg).

### S4. 콘솔
- 명칭 "카테고리"를 "상담카테고리"로 바꾼다. 대상: aiSetting·users의 #727 키, 6개 언어.
- 관리 모달
  - 노출 토글
  - 언어별 이름 펼침
  - 추가 줄의 "고객에게 노출" 체크(기본 켬)
  - 안내 문구
- 규칙 칩에 노출 표시를 붙인다.
- 라이브챗 대화 헤더에 `상담: X` 배지를 단다.

### S5. 문서·배포
- TCR과 RPT를 작성한다.
- SQL을 스테이징과 프로덕션에 먼저 적용한 뒤 배포한다.

## 4. 영향 분석

| 영역 | 영향 | 대응 |
|---|---|---|
| 기존 위젯 | 노출 0개면 변화 없음. 기존 행은 노출 안 함으로 시작(D6) | ensure 응답의 빈 배열 회귀 테스트 |
| 호출 지연 | A 경로는 고객이 고르는 동안 호출이 그만큼 늦다(의도된 동작). B 경로는 지연 없음(D1) | 카드에 [건너뛰기] |
| 중복 호출 | B 경로 재라우팅으로 두 번째 알림이 나갈 수 있다 | 미수락·첫 선택 1회로 제한(D2). 이벤트에 reason 구분 |
| 보안 | 숨김 코드나 다른 테넌트 코드를 주입할 수 있음 | 노출 코드만 허용, 대화 소유 검사, `@Public` 레이트리밋 기존 그대로 |
| 라우팅 | 조건이 넓어질 수 있음(region OR 선택) | 규칙에 선택값 코드를 넣은 경우에만 해당. 라우터 스펙에 OR 케이스 추가 |
| 직전 상담원 우선 | 고객이 고르면 적용하지 않음(D4) | 스펙 |
| 스키마 | 컬럼 4개 추가(기존 행 기본값만) | SQL 선적용, 실부팅 확인 |
| 롤백 | 코드를 되돌려도 컬럼은 남는다(무해) | 필요 시 `ALTER … DROP COLUMN` 4개 |

## 5. 테스트 계획
- **단위**
  - 노출·언어별 이름 저장과 표시명 해석(D5 순서)
  - escalate가 노출 코드만 받는지, 숨김 코드는 무시하는지
  - consult-category 엔드포인트: 소유 검사, 노출 검사, 미수락 첫 선택만 재라우팅, 배정된 대화는 기록만
  - 라우터 region OR 선택, 담당자 선택 우선, 직전 상담원 우선 건너뛰기
  - ensure 응답의 빈 배열과 언어별 해석
- **통합(로컬 HTTP + 위젯)**
  - A 경로: 카드 → 선택 → 규칙 담당자 호출(로그 rule), 시스템 줄
  - A 경로 건너뛰기: 지금과 같음
  - B 경로: AI 인계 → 카드 → 선택 → 재호출 1회 → 같은 대화에서 다시 골라도 재호출 없음
  - 노출 0개 테넌트: 카드 없음
- **화면**: 관리 모달 토글·언어별 이름, 위젯 카드(ko·vi·en), 콘솔 헤더 배지
