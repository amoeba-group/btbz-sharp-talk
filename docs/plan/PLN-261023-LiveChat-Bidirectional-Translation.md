## 1. 단계별 계획

### S1. 서버 — 발화자별 프롬프트 (T1·T2)
- `agent.service.ts` `translateMessage`: `message.senderType`으로 프롬프트 분기
  - `user` → 기존 문구 유지(캐시 호환)
  - `agent`/`ai` → "Translate the support reply into {lang}. Keep markdown, lists and links exactly. Output only the translation."
  - `system` → `VALIDATION_FAILED` 400 (UI도 버튼 미노출)
- 캐시 키 `msgtr:{id}:{lang}` 그대로(메시지 id가 발화자를 고정하므로 충돌 없음).
- 단위 테스트: sender별 system 프롬프트, system 메시지 거부, 교차 테넌트 404 유지.

### S2. 콘솔 — 상담원·AI 버블 번역 + 게이트 분리 (T1·T2)
- 액션열 분리: `TranslateButton`(모든 비-system 버블, 상태 무관) / 기존 3종(고객 버블, `msgActionsVisible`).
- 상담원·AI 버블: 버블 왼쪽(시각 옆) 호버 번역 버튼, 서브버블 우측 정렬. 팝오버는 기존 `anchorTranslateMenu`(fixed) 재사용.
- 인라인 번역 렌더 조건 `senderType==='user'` → `senderType!=='system'`, 정렬은 `outbound`로 분기.
  AI 번역 서브버블은 원문과 같이 `MessageBody`(markdown-lite)로 렌더, 고객 번역은 기존 평문.
- 번역 아이콘+언어 팝오버는 `renderTranslateControl(messageId)` 한 곳으로 모아 고객·답변 버블이 공유.

### S3. i18n · 검증
- i18n: 신규 키 없음 — 상담원·AI 버블도 기존 `msgActions.translate*` 키 재사용. `npm run i18n:check`.
- `npm run typecheck`, api 단위 테스트, **실부팅 확인**(`Nest application successfully started`).
- 로컬 실측: 베트남어 고객·AI·상담원 메시지 각 번역, 자동응답 중 대화 번역, 고객 위젯에 번역문이 노출되지 않음 확인.
- 문서: TCR-261023 → RPT-261023.
