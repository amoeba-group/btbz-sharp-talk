# PLN-260920 — 콘솔 PII 마스킹·열람 통제 도입 계획

- 근거: REQ-260920-PII-Masking-Privacy-Audit · PRV-002/005/040 · PCB-08
- UI 영향: **있음** — 고객 페이지, 라이브챗 고객 패널, 히스토리/통계의 고객 식별 칼럼, 감사 화면 필터. 와이어프레임 §4.
- 원칙: **서버가 마스킹한다.** 브라우저에 평문을 보내고 CSS로 가리는 방식은 통제가 아니다.
  평문은 "열람(reveal)"이라는 별도 요청으로만 나가고, 그 요청은 반드시 감사에 남는다.

## 1. 단계

### P1 — 기본 마스킹 (F-01·F-04, 코드 소)
| 층 | 변경 |
|---|---|
| common | `maskEmail`(기존, 미사용) 옆에 `maskPhone`·`maskName` 추가 — 서버 전용 유틸 `pii.util.ts`로 통일 |
| API | `customer.mapper.ts`가 기본적으로 마스킹된 값을 반환(`email: ab***@shop.com`, `phone: ***-**** -1234`, `name: 홍*동`). 목록 응답에서 `phone` 제거, `PATCH` 응답은 `{id,name,tier}`로 축소 |
| API | `/agent/customers/search`·라이브챗 고객 패널(`getContext`)도 동일 마스킹 |
| 콘솔 | 변경 없음(서버가 이미 마스킹한 값을 그대로 렌더) |

### P2 — 열람 경로와 감사 (F-02·F-03)
| 층 | 변경 |
|---|---|
| types/common | `CAPABILITY.CUSTOMER_PII_REVEAL` 신설 — 기본 부여: master·director (manager·staff 제외), 테넌트 `roles_permissions`로 조정 가능 |
| API | `GET /customers/:id/reveal`(신규) → 평문 1건 반환 + `customer.pii_revealed` 감사 기록(actor·대상 고객 id·마스킹된 이메일·ip·request_id), 분당 레이트리밋 |
| API | 목록 조회에도 `customer.list_viewed` 감사 1건(건수만, 개별 값 없음) |
| 콘솔 | 행 우측 눈 아이콘 → 클릭 시 그 행만 평문 5분, "열람 기록이 남습니다" 토스트. 권한 없으면 아이콘 비노출 |
| 라이브챗 | 고객 패널에 동일 버튼(상담 중 주문 확인용), 대화 열람 감사와 동일 형식 |

### P3 — 로그·전송 위생 (F-05·F-07)
| 층 | 변경 |
|---|---|
| 콘솔/API | 고객 검색을 쿼리스트링 → `POST /customers/search` 본문으로 이동(이메일이 URL·로그·브라우저 기록에 남지 않음) |
| 인프라 | nginx 로그 포맷에서 쿼리스트링 제거(`$uri`), 스테이징·프로덕션 동시 적용 |
| API | `gdrive-credential.service.ts:71` 감사 메타데이터 `maskPii` 적용 |

### P4 — 보존·최소화 확장 (F-06)
| 층 | 변경 |
|---|---|
| API | `moderation_logs.excerpt`·`agent_alerts.preview`를 보존 파기 대상에 추가(대화와 동일 창) |
| API | 신규 excerpt 저장 시 `scrubPii` 적용(모더레이션 판정은 원문으로, 저장본만 최소화) |
| 문서 | 데이터 인벤토리 G-1~G-7 갱신 |

### P5 — 운영·문서 (F-08, PCB-08)
- 프로덕션 `MFA_ENFORCE_FROM` 설정(사용자 결정 필요), 역할별 PII 접근 매트릭스 문서화, 분기 접근 재인증 절차 초안
- TCR/RPT 작성, 매뉴얼(설정·라이브챗 절)에 마스킹·열람 기록 안내 추가

## 2. 사이드 임팩트
- 상담원이 이메일로 주문을 찾던 흐름: 검색은 **블라인드 인덱스 정확 일치**라 마스킹 후에도 동작한다. 부분 검색은 마스킹된 결과만 보여주고, 필요 시 열람 버튼으로 확인.
- 고객 CSV 내보내기는 현재 존재하지 않는다(신규로 만들지 않는다 — 만들면 P2 감사·권한을 동일 적용).
- 감사 로그 증가량: 열람 1건당 1행. 기존 대화 열람 감사와 같은 규모.
- 마스킹 형식은 6개 언어 공통(문자 치환만, 번역 불필요).

## 3. 리스크
- 마스킹 기본화로 기존 사용자가 "정보가 사라졌다"고 느낄 수 있음 → 첫 배포 시 콘솔 안내 문구와 매뉴얼 동시 반영.
- 열람 권한을 director 이상으로 두면 매니저 상담 업무가 막힐 수 있음 → 테넌트별 조정 가능하게 하고, 기본값은 보수적으로.

## 5. 승인 요청

P1(기본 마스킹) → P2(열람 권한·감사) → P3(로그 위생) → P4(보존 확장) → P5(운영·문서) 순으로 진행해도 될지
확인 부탁드립니다. 결정이 필요한 선택지:

- (a) **열람 권한 기본값**: ① 마스터·디렉터만(보수적, 기본안) ② 매니저까지 포함(상담 편의)
- (b) **적용 범위**: ① 전 테넌트 일괄 ② 테넌트 설정으로 켜고 끄기(기본 켬)
- (c) **P4·P5 분리**: 보존 확장과 문서·계약 항목을 별도 요구사항으로 뺄지
