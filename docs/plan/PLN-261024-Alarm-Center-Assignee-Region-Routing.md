## 3. 단계별 작업

### S1. 스키마 (SQL 먼저 적용) — `sql/261024-alarm-center.sql`
- `agent_alerts`
  - `ADD rule_name VARCHAR(120) NULL`
  - `ADD consult_category VARCHAR(64) NULL`
  - `ADD KEY idx_alert_tenant_created(tenant_id, created_at)`
- `agent_alert_reads(id, tenant_id, alert_id, user_id, read_at)`, `UNIQUE(alert_id, user_id)`
- `user_alert_settings(user_id PK, tenant_id, popup VARCHAR(16) DEFAULT 'all', sound TINYINT DEFAULT 1, desktop TINYINT DEFAULT 0, email TINYINT DEFAULT 1, updated_at)`
- 엔티티 3개, `migrations:manifest`

### S2. API
- 알람 생성: `ruleName`, `consultCategory`를 이벤트에서 행으로 저장한다. 지금은 이벤트에만 있다.
- **메일**: 개인 설정 `email=0`인 사람에게는 개인 메일을 보내지 않는다. 운영 메일함 경로는 유지한다.
- `GET /agent/alerts`
  - 기존 팝업용: 범위를 테넌트 전체로 넓힌다(D1).
  - 같은 대화·사유의 형제 행을 하나로 묶고 `assignees: [{id,name}] | 'all'`을 붙인다.
  - 대화의 호텔·권역, 규칙, 상담카테고리, 나에게 배정 여부, 내가 읽었는지를 붙인다.
- `GET /agent/alerts/center`: 필터(scope, status, from/to, category)와 `page/size`로 이력을 조회한다.
- `POST /agent/alerts/:id/read`: 개인 읽음. `ack`는 배정자 또는 전원 알람일 때만 형제 행을 확인 처리한다(D2). 기존 ack 엔드포인트는 이 규칙으로 바뀐다.
- `GET/PUT /me/alert-settings`
- `POST /ai-config/routing/simulate`
  - 본문: 편집 중 규칙 + 문맥.
  - `HandoffRouterService`의 매칭·그룹 해석을 그대로 쓰는 dry-run이다. 알람은 만들지 않는다.
  - 규칙별로 맞음/건너뜀과 그 이유를 돌려준다.
  - 권한은 `AI_SETTINGS_MANAGE`.
- 모든 4xx는 `logger.warn`. 테넌트 검사.

### S3. 콘솔
- `EscalationAlarm`
  - 배정·규칙·상담카테고리·호텔 표시.
  - 개인 설정 반영: 팝업 범위, 소리(짧은 알림음, 자산은 `apps/web/public`), 데스크톱 `Notification`.
  - 닫기 = 읽음.
- 헤더 🔔: 읽지 않은 수(기존 10초 폴링 재사용)와 드로어.
- `/alerts` 페이지(라우트·nav는 `live_chat` 권한 공유)와 설정 모달.
- 규칙 편집기: 시뮬레이터 박스, 경고 3종(D7).
- i18n 6개 언어.

### S4. 문서·배포
- TCR과 RPT를 작성한다. SQL 선적용 후 스테이징 → 프로덕션 순으로 배포한다.
- go2joy 스테이징 규칙 보정 안내: 아래 예시를 RPT에 포함한다. 적용은 운영자가 하거나, 요청 시 내가 한다.
  - CS_South: cs + 권역 남부·중남부 → 팀 South × 라벨 cs
  - CS_North: cs + 권역 북부·중북부 → 팀 North × 라벨 cs
  - BS_*: 업무 라벨 'sa'를 빼고 담당자 라벨 sa로
  - 기본 규칙
  - South 팀원 초대 수락 필요

## 4. 영향 분석

| 영역 | 영향 | 대응 |
|---|---|---|
| 알람 노출 | 지정 알람이 다른 상담원에게도 보인다(요청) | 팝업 "내 배정만" 설정 |
| ack 의미 변경 | 비배정자의 닫기로는 재알림이 멈추지 않는다 | 의도된 동작(D2). 재알림 서비스는 기존 status 그대로 |
| 폴링 부하 | 목록 범위가 넓어진다(테넌트 전체, new만, 50건 제한 유지) | 인덱스 추가 |
| 메일 | 개인 메일 끄기 | 운영 메일함은 유지(누락 방지) |
| 시뮬레이터 | 라우터와 같은 함수를 쓴다(복제 금지) | 라우터 스펙 + 시뮬레이터 스펙 |
| 스키마 | 컬럼 2개 + 테이블 2개 | SQL 선적용, 실부팅 |
| 롤백 | 코드를 되돌려도 추가 컬럼·테이블은 무해 | DROP 문 PR에 기재 |
