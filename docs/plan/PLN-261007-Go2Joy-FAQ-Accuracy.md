## 1. 설계 요약
```
고객 턴 ─ scrubPii ─┐                 ┌─ KB 문서: 질문 관련 구간 선택(R3, 문서당 2,000자·총 9,000자)
AI 턴 ──(그대로, R1)┤→ 모델(이력+문맥)─┤
상담원 턴 ─ scrubPii┘                 └─ 규칙: "연락처 꼬리말은 시스템이 붙인다 — 직접 쓰지 마라"(R4, 꼬리말 켜진 경우)
          ↓ 답변(출력 한도 2,048, R4)
   모더레이션 mask 규칙 ─ 보호값(공식 연락처·계좌)은 건너뜀(R2)
          ↓
   + 테넌트 연락처 꼬리말(세션 언어 템플릿, R4)  → 고객
```

## 2. 단계

### S1 — R1: 대화 이력에서 AI 발화는 마스킹하지 않음
- `buildHistory`: `scrubPii`는 **user·agent 턴에만** 적용한다. AI 턴은 원문 그대로 둔다.
  근거: AI 턴이 받은 고객 정보는 이미 마스킹된 것이고, 주문 컨텍스트에서 연락처는 빠져 있다. AI 발화에 남는 번호·이메일은 KB 출처 값이다(대화 786의 077 789 2399).
- 상담원 턴은 고객 정보를 직접 쓸 수 있으므로 계속 마스킹한다.
- `replacePiiTokens`(S7 안전망)는 유지한다. 고객이 준 번호를 모델이 토큰으로 받는 경우에만 동작하게 된다.
- 테스트: AI 턴의 번호·이메일 보존, user·agent 턴 마스킹 유지, 대화 786 패턴 재현(이전 AI 답의 번호가 다음 답에 그대로 나온다).

### S2 — R2: 모더레이션 보호값(마스킹 예외)
- 보호값 = 테넌트 `answer_footer.protected[]`(직접 입력) + 꼬리말 본문에서 자동 추출한 이메일·전화·13~16자리 숫자.
- `ModerationService.mask`: 정규식 치환 전에 보호값을 자리표시자로 바꿔 두고, 치환 후 되돌린다. 단어·구문·정규식 규칙 모두에 적용된다.
- 보호값은 테넌트별로 캐시한다(규칙 캐시와 같은 TTL, 꼬리말 저장 시 무효화).
- 고객 입력에도 같은 예외가 적용되지만, 보호값은 테넌트가 공개한 공식 연락처라 노출 위험이 없다.
- 테스트: support@go2joy.vn·077 789 2399·19133261136016 보존, 다른 이메일·번호는 계속 마스킹, 보호값이 없으면 동작 불변.

### S3 — R3: 긴 문서는 질문 관련 구간을 넘김
- `SNIPPET_CHARS` 800 고정 → 문서당 **2,000자**(`RAG_SNIPPET_CHARS`, `envNumber`), 총 컨텍스트 **9,000자** 상한(`RAG_CONTEXT_CHARS`).
- 2,000자를 넘는 문서는 **구간 선택**: 문단(빈 줄·제목 단위)으로 나누고 질문 단어 일치 수로 점수를 매긴다. 첫 문단(질문 줄)은 항상 넣고, 점수 높은 문단을 원래 순서대로 예산까지 넣는다.
- FAQ 문서(대부분 1,600자 이하)는 통째로 들어간다 → C1(1,588자)의 "Chưa thanh toán"(830자)·전화번호 확인법(1,092자) 해결.
- 테스트: 2,000자 이하는 원문 전체, 긴 문서는 질문과 맞는 문단 포함·순서 유지·예산 준수, 총 상한 초과 시 뒤 문서부터 절삭.

### S4 — R4: 연락처 꼬리말 템플릿 + 출력 한도
- **스키마**: `tenant_ai_config.answer_footer` JSON `{ enabled: boolean, text: { EN?, KO?, VI?, JA?, ZH?, ES? }, protected: string[] }`
  (`sql/261007-answer-footer.sql`, 멱등 가드)
- **적용**: RAG 답변(지식 답변)에 모더레이션 **후** `\n\n` + 세션 언어 꼬리말(없으면 EN, 그것도 없으면 첫 번째 값)을 붙인다.
  꼬리말은 운영자가 쓴 고정 문구(시나리오 스크립트와 같은 지위)라 모더레이션 대상이 아니다. 비질문 답변·핸드오프 공지에는 붙이지 않는다.
- **프롬프트**: 꼬리말이 켜져 있으면 규칙을 추가한다 — "Do not end with contact details (email, phone, hotline, hours); the system appends them. Give contact details only when the customer asks how to reach support."
- **출력 한도**: RAG 답변 `maxTokens` 1,024 → **2,048**(`RAG_MAX_TOKENS`, `envNumber`). env 템플릿 4종에 키를 추가한다(CI 게이트).
- **API**: 기존 `GET/PUT /ai-config`에 `answer_footer` 필드를 추가한다(검증: 언어별 500자, 보호값 20개·각 100자).
- **콘솔**: AI 설정 화면에 "답변 연락처 꼬리말" 카드(§3). 저장 토스트, 6개 언어 i18n.

### S5 — R8: 데이터 정비 (go2joy, 스테이징)
- ✅ **완료(2026-10-07)**: D4 — #3362의 "T + 02 영업일" 문장에 #3363과 같은 구체 일정(1–15 → 17일, 16–말일 → 익월 2일, 주말·공휴일 → 다음 월요일)을 덧붙여 두 문서 서술을 맞췄다(재임베딩 완료)
- ⏳ **S4 배포 후**: go2joy 꼬리말 설정(VI·EN·KO: 이메일·Hotline 1900 638 838·Zalo 북부/남부·근무시간) + 보호값(support@go2joy.vn, 077 789 2399, 0931 836 836, 1900 638 838, 19133261136016)
  → FAQ 문서 40건 끝의 "Liên hệ hỗ trợ Go2Joy: …" 줄 제거 + 재임베딩(꼬리말과 중복되고 출력 토큰만 쓴다)
- ⏳ **G3 가이드 URL**: 가이드 문서 #2501의 출처는 내부 Notion 링크(`app.notion.com/p/…`)라 호텔이 열 수 있는지 알 수 없다 → **공개 URL을 받으면** FAQ 문서를 추가한다
- C1 문서 분할: S3(문서당 2,000자)로 해결되므로 하지 않는다

## 4. 영향
| 영역 | 영향 | 대응 |
|---|---|---|
| PII(R1) | AI 발화가 원문으로 모델에 재전송 | AI는 마스킹된 고객 정보만 받았으므로 새 노출은 없다. 상담원 턴은 계속 마스킹 |
| 마스킹 예외(R2) | 보호값은 고객 입력에서도 가리지 않는다 | 테넌트가 공개한 공식 값만, 개수·길이 제한 |
| 비용(R3·R4) | 입력 컨텍스트 최대 9,000자, 출력 최대 2,048토큰 | 상한 env화. 꼬리말 템플릿화로 출력 토큰 일부 상쇄 |
| 다른 테넌트 | R1·R3·출력 한도는 전 테넌트 적용. 꼬리말·보호값은 설정한 테넌트만 | 기본값(꼬리말 꺼짐) = 기존 동작 |
| 스키마 | `tenant_ai_config` 열 1개 | 스테이징·프로덕션 선적용, 롤백 = 열 DROP |
| 모더레이션 | 꼬리말은 모더레이션 대상 아님 | 운영자 작성 고정 문구(시나리오 스크립트와 동일 취급) |
