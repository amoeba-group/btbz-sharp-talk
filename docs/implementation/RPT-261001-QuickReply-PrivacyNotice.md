## 1. 무엇이 바뀌었나

| 단계 | 변경 |
|---|---|
| **P1** | `/chat/scenario`가 스크립트 없는 액션을 404 대신 **채팅 턴으로** 답한다. `message`는 debug, 그 외 미지 액션은 **warn**. 질문도 스크립트도 없으면 404 유지. 콘솔 미리보기는 칩을 액션별로 분기하고, 스크립트 보유 판정은 **서버가 주는 목록**을 쓴다 |
| **P2** | 버튼에 `message`(보낼 문장) 신설 — 라벨과 같은 자료형, 비우면 라벨. 콘솔 편집칸 + 6언어. **스키마 변경 없음**(기존 json 내부) |
| **P3** | 고지 문구를 서버가 내려준다. 프로필 3종(커머스·숙박·일반) 6언어 + 테넌트 줄 단위 덮어쓰기. 위젯 번들 문구는 **구 위젯용 최후 폴백**으로 강등 |
| **P4** | 콘솔: 프로필 선택 · 언어별 6줄 편집(플레이스홀더=프로필 원문) · **중요 변경 체크** · URL·버전 미설정 경고, 6언어 |

## 2. 구현 중 잡은 것 두 가지

**① 테스트가 내가 만든 회귀를 잡았다.** `delivery_status`는 `SCENARIOS`의 키가 아니라
`shipping_policy`로 매핑되는 **버튼 액션**이다. 폴백 판정을 해석 전에 두었더니 멀쩡한 배송
스크립트가 RAG 질문으로 바뀌었다. 지금은 `resolveScriptAction()`을 먼저 거친다. 이 매핑은
"콘솔과 런타임이 각각 반쪽만 알아서" 생긴 과거 사고의 산물인데, 같은 지점에서 또 미끄러졌다.

**② 계약을 넓히는 대신 빈 값을 쓴 자리.** 에이전트 모드에서는 `reply`가 null인데,
`ScenarioTurnResponse.reply`를 nullable로 바꾸면 **기존 클라이언트의 `res.reply.body`가 즉시
터진다**(이 변경이 구하려던 바로 그 클라이언트들이다). 그래서 빈 body로 싣고, 위젯은 빈 body를
렌더하지 않는다.

## 3. 안전장치

- **배포만으로 문구가 바뀌는 테넌트는 0**: 프로필이 NULL이면 `commerce_enabled`로 추론한다.
  커머스 테넌트는 오늘과 같은 "주문 조회 내역"을, 비커머스는 그 줄이 빠진 일반 문구를 받는다.
- **빈 줄 금지**: 채울 수 없는 키는 빈 문자열이 아니라 **생략**해서 보낸다. 위젯은 없는 키에
  자기 번들 문구를 쓴다 — 법적 고지에 빈 줄이 뜨는 일이 없다.
- **재동의는 선택**: 문구를 고쳐도 버전은 그대로다. 운영자가 "중요한 변경"을 체크할 때만 올라가고,
  모르는 버전 체계는 건드리지 않는다.
