## 0. 요약
- SharpTalk 쪽 1단계 기능(서명 검증, 호텔 = 기업고객, 대화 연속성, 지역 배정, 호텔 정보·객실 연동)은 **스테이징에 모두 배포되어 동작**합니다.
- 10/23 HA UAT 페이지를 점검한 결과, **위젯 임베드는 들어갔지만 서명이 없습니다.** 신원 패키지를 브라우저에서 만들고 `hash`가 `"testing"` 고정값입니다(1.2). 지금은 스테이징에서만 임시로 "서명 없는 로그인"을 받아 UAT를 진행하고 있으며, **운영에서는 이 방식이 거부됩니다.**
- 이 문서는 Go2Joy가 해야 할 일을 **작업 단위(WR)** 로 나누고, 담당·기한(제안)·완료 기준을 붙였습니다.
- **10/31 스테이징 오픈**에 필요한 것: WR-01 · WR-02 · WR-04 · WR-05 · WR-10 ~ WR-14.
- **운영 오픈**에 추가로 필요한 것: WR-20 ~ WR-23 · WR-30 · WR-31. 운영 서버(WR-20)를 받은 날부터 약 **7영업일**(설치 4일 + UAT 3일).

### 1.2 HA UAT 점검 결과 — 가이드 v1.3과 다른 점
HA UAT(`go2joy-ha-uat.go2joy.io`) 페이지의 임베드 코드(`window.sharptalkSignIn`)와 SharpTalk 스테이징 수신 로그로 확인했습니다.

| # | 항목 | 현재 HA | 가이드 v1.3 규격 | 결과 |
|---|---|---|---|---|
| D1 | 서명 | 브라우저에서 패키지를 만들고 `hash: "testing"` 고정 | **HA 서버**가 HMAC-SHA256으로 서명해 FE에 반환 | 운영에서 401 거부 |
| D2 | `userId` | `profile.value.userId`(로그인 ID) | **`"ha:" + userSn`**(바뀌지 않는 직원 번호) | 로그인 ID가 바뀌면 이전 대화가 끊김, 부킹 고객 ID와 충돌 가능 |
| D3 | 속성 키 | 5개 + `hotel_code`·`hotel_group_id`·`user_id`·`user_sn`·`district` | **5개만**(`hotel_id`·`hotel_name`·`province`·`region`·`role`) | 서명하면 모르는 키 때문에 401 |
| D4 | `region` | 성 이름(`provinceName`, 예: `Hồ Chí Minh`) | **권역 코드**(`north`·`north_center`·`south_center`·`south`·`central`) | SharpTalk이 임시로 성 이름을 권역으로 바꿔 받고 있음(10/23 배포) |
| D5 | `locale` | `localStorage.lang` → `vi`/`en`, 언어 변경 시 `setLocale` | 같음 | 정상 |
| D6 | 로그아웃 | `sharptalkSignOut()` → `logout` | 같음 | 정상(호출 위치 확인 필요) |
| D7 | 호텔 변경 시 재호출 | 확인 못 함 | 호텔 선택이 바뀔 때마다 `identify` 다시 호출 | UAT에서 확인(WR-04) |

## 3. 일정과 의존 관계
```
10/26(월)  WR-02 서명 키 결정 · WR-40 담당자
10/27(화)  WR-01 서명 엔드포인트 + T1~T5 · WR-10~14 팀·명단·기준·계정
           └ SharpTalk: secret 전달(당일), 콘솔 계정·배정 규칙 입력(반나절)
10/28(수)  WR-04 FE 임베드 수정 → identify 200 verified
10/29~30   WR-05 UAT 공동 점검 · WR-15 Notion 재연결
10/31(토)  스테이징 오픈 (HA UAT → SharpTalk 스테이징, 실제 상담원 응대)

운영 오픈 = WR-20 서버 수령일 + 약 7영업일
           SharpTalk 설치·go2joy 설정 이관 4일(WR-21·22·23 필요) → 운영 UAT 3일(WR-30·31 필요)
```
- 10/22였던 선행 기한이 지나 **10/31은 운영 오픈이 아니라 스테이징 오픈**입니다(PLN-261015 결정).
- WR-01과 WR-04 중 하나라도 늦으면 스테이징 오픈은 서명 없는 임시 방식으로만 가능합니다. 이 경우 실제 상담원 응대는 시작하지 않을 것을 권장합니다.

## 4. 완료 판정 — 스테이징 오픈
| 점검 | 기대 |
|---|---|
| HA 로그인 → 위젯 열기 | identify **200**, `identified {ok: true}`, 동의 안내 없음, 인사말에 직원 이름, 콘솔 라이브챗에 '검증됨' |
| 콘솔 › 고객 › 기업고객 | 호텔 1건(이름 · 성 · 권역), 연락처에 로그인 직원, 객실 유형이 호텔별 상품으로 |
| 호텔 선택 변경 | 새 호텔로 기업고객·대화가 바뀜 |
| 권역별 호텔 4곳으로 "상담원 연결" | WR-10 매핑대로 팀에 배정, 담당자 알림 |
| 로그아웃 후 위젯 | 게스트, 이전 대화 안 보임 |
| 패키지 값 하나를 재서명 없이 수정 | 401, 게스트 |

그 뒤 SharpTalk은 스테이징의 "서명 없는 로그인 임시 허용"을 끕니다.
