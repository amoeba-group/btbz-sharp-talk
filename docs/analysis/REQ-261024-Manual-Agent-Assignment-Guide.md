- 요청 원문:

  > 상담카테고리 설정, 상담원 팀과 라벨, 배정규칙 설정
  > 고객 상담요청 화면에서 배정되는 과정, 상담카테고리 선택, 배정규칙에 따른 담당상담원 알람, 화면 캡처 하여 사용자 매뉴얼 작성하여 /manual 에 게시한다.

## 1. AS-IS
- **배정 관련 설명이 흩어져 있다.**
  - 통합 사용자 매뉴얼 §2.3(위젯 카드), §4.4(알람), §14.1(상담카테고리·배정 규칙)
  - 지식·AI 매뉴얼 §5.1a(절차)
  - 팀·라벨 관리(사용자 화면)는 매뉴얼에 설명이 거의 없다.
- **처음부터 끝까지 따라 하는 순서가 없다.** 운영자가 "누구에게 배정되게 하려면 무엇을 어떤 순서로 설정하나"와 "고객이 요청하면 실제로 어떻게 흘러가나"를 한 흐름으로 볼 수 없다.
- **/manual에는 카드 01~06이 있다**(간단 세팅, 지식·AI, 통합, 연동 자격증명, 커스텀 위젯, 카페24). 각 카드에 ko/en/vi의 HTML과 MD 원문이 있다.
- **캡처가 부족하다.** #735로 상담원 연결 탭, 상담카테고리 관리, 알람 팝업, 알람센터, 위젯 카드 캡처는 있다. 팀·라벨 관리, 위젯 요청 시작부터 연결까지의 단계, 상담원 화면의 배정 결과 캡처는 없다.

## 2. TO-BE
새 매뉴얼 **"07 상담원 배정 가이드"**를 만든다. 순서는 **설정 → 고객 요청 → 배정 → 알람 → 응대**이고 단계마다 캡처를 넣는다.

1. **개념**: 상담카테고리, 팀, 라벨, 배정 규칙, 고객 정보(권역)의 관계를 그림 한 장으로 보인다.
2. **준비 1 — 상담원·팀·라벨**: 상담원 초대와 수락(배정 조건), 팀 만들기, 라벨, 사람에게 팀·라벨 지정
3. **준비 2 — 상담카테고리**: 만들기, 노출, 언어별 이름
4. **준비 3 — 배정 규칙**: 상담카테고리 + 고객 정보(권역) → 팀 × 라벨, 규칙 순서, 기본 규칙, **배정 확인**, 경고
5. **고객 화면 — 상담 요청**
   - A: 고객이 [상담원 연결]을 누르면 상담카테고리 카드가 나오고, 고르면 연결 안내가 나온다.
   - B: AI가 상담원에게 넘긴 직후 카드가 나오고, 고르면 다시 연결된다.
   - 건너뛰기
6. **배정 판단**: 서버가 규칙을 어떻게 고르는지(예시 표), 직전 상담원 우선과의 관계, 배정 가능한 상담원이 0명일 때
7. **상담원 화면 — 알람**: 배정된 상담원의 팝업, 다른 상담원의 팝업, 🔔, 알람센터, 확인 처리
8. **응대**: [상담 열기] → 라이브챗 대화(상담카테고리 배지·시스템 줄) → 수락
9. **알람 설정(개인)**
10. **문제 해결(FAQ)**: 카드가 안 나옴, 다른 팀으로 감, 모두에게 알람이 감, 초대 미수락 등
11. **체크리스트**

`/manual` 목록에 카드 07을 추가하고, 통합 매뉴얼 §14.1과 지식·AI 매뉴얼 §5.1a에서 링크한다.

## 3. 제약
- **캡처는 로컬 시연 데이터로 찍는다.** 가상의 호텔·상담원 이름을 쓰고 실제 고객 데이터는 쓰지 않는다. 캡처 뒤 로컬 데이터를 원래대로 되돌린다.
- **언어**: ko/en/vi 문서를 만든다. 캡처는 ko/en이고, vi 페이지는 기존 관례대로 en 이미지를 쓴다.
- **화면 문구는 실제 콘솔·위젯의 언어별 표기와 일치**해야 한다.
- 매뉴얼은 웹 컨테이너가 제공하므로 게시하려면 스테이징·프로덕션 배포가 필요하다. 코드·SQL 변경은 없다.
