# REQ-261024 — 설정: 상담원 연결 탭 분리 · 배정 규칙 "지역" → "카테고리" + 카테고리 관리

- 요청일: 2026-10-24
- 화면: `https://shoptalk.amoeba.site/settings/basic`
- 요청 원문:
  > 상담원 연결을 별도 탭메뉴로 분리
  > 배정 규칙 — 지역 × 업무
  > 지역명칭을 카테고리로 변경하고 카테고리 관리 기능 추가

## 1. AS-IS

### 1-1. 상담원 연결의 위치
- 기본 설정 탭(`/settings/basic`, `SettingsBasicPage.tsx`)에 카드 5개가 세로로 이어진다: AI 엔진, AI 사용량, 스토어, 지식 옵션, **상담원 연결**(`HandoffSection`).
- 상담원 연결은 카드 하나 안에 섹션 7개가 있고 저장 버튼은 하나다(585줄): 담당 상담원, 배정 규칙, 미수락 재알림, 운영시간·휴게, 업무 외 메일·안내, SLA, 정책 deny 목록.
- 이 카드가 페이지 길이의 대부분을 차지해서, 기본 설정에서 상담원 연결 항목을 찾으려면 아래로 한참 내려가야 한다.
- 설정 탭 목록은 `SettingsLayout.tsx`의 `TABS`에 있다. 각 탭은 메뉴 코드(`settings_basic` 등)로 테넌트 제공 여부를 판정한다.

### 1-2. 배정 규칙의 "지역"
- 규칙 편집기는 `RoutingRulesEditor.tsx`이고 제목은 "배정 규칙 — 지역 × 업무"다.
- **지역 칩은 고정 5개**다(`packages/types/src/common/region.ts`의 `REGION_CODES`): 북부·중북부·중부·중남부·남부.
  - Go2Joy(베트남) 호텔 관리자 앱이 서명해 보내는 `sessions.identity_attributes.region` 값과 맞춘다.
  - 테넌트가 이름을 바꾸거나 추가·삭제할 수 없다.
- 같은 고정 목록을 쓰는 곳:

| 위치 | 용도 | 검증 |
|---|---|---|
| 배정 규칙 `regions` | 세션 region이 이 중 하나일 때만 규칙 적용 | 없음(JSON) |
| 배정 규칙 "지역 담당자에게 배정"(`assigneeByRegion`) | 팀·라벨의 담당 지역과 세션 region이 맞는 상담원 호출, 권역별 후보 미리보기 | — |
| 사용자 화면 팀·라벨 "담당 지역"(`RegionScopeEditor`, `units.regions`, `job_labels.regions`) | 위 배정의 후보 | API `@IsIn(REGION_CODES)` |
| 고객 화면 기업 목록 지역(`CompaniesPanel`, `companies.region`) | 호텔의 지역 표시·필터·수정 | API `@IsIn(REGION_CODES)` |
| 지역표(성 → 지역, `handoff_config.provinceRegions`) | Go2Joy Province Feed로 성을 지역에 매핑 | — |

- 카탈로그에 없는 값이 저장돼 있으면 편집기에 "기타: 값"으로 보이고 지울 수 있다(조용히 버리지 않음).

### 1-3. 실데이터 (10/24 조회)

|---|---|---|---|
| 스테이징 go2joy(테넌트 4) | 1개 | 비어 있음(=전체) | 라벨 `consult` = 5개 전부 |

## 2. TO-BE

1. **설정 탭 분리**
   - 설정에 **[상담원 연결]** 탭(`/settings/handoff`)을 새로 만든다.
   - 기본 설정 탭에는 AI 엔진·사용량·스토어·지식 옵션만 남긴다.
2. **용어 변경**: 배정 규칙의 "지역"을 **"카테고리"**로 바꾼다.
   - 제목 "배정 규칙 — 카테고리 × 업무"
   - 칩 줄 이름 "카테고리", 빈 값 "전체 카테고리"
   - "카테고리 담당자에게 배정", "카테고리별 후보"
   - 팀·라벨 "담당 카테고리"
3. **카테고리 관리**: 테넌트가 카테고리를 직접 추가하고, 이름을 바꾸고, 순서를 바꾸고, 삭제한다.
   - 규칙 편집기·팀/라벨 담당 설정의 선택지는 고정 5개 대신 **테넌트 카테고리 목록**에서 나온다.
4. **기존 동작 유지**
   - go2joy의 5개 지역은 그대로 카테고리 5개로 옮겨진다(같은 코드).
   - 세션 매칭(서명된 `region` 값 ↔ 카테고리 코드)과 저장된 규칙·담당 범위는 바뀌지 않는다.

## 4. 사용자 흐름

1. 마스터가 설정 → **[상담원 연결]** 탭을 연다. 기존 상담원 연결 카드가 그대로 보인다.
2. 배정 규칙 머리글의 **[카테고리 관리]**를 누르면 모달이 열린다. 여기서 추가(코드·이름), 이름 변경, ↑↓ 순서 변경, 삭제를 하고 저장 토스트를 받는다.
3. 규칙의 "카테고리" 줄 칩이 즉시 새 목록으로 바뀐다. 규칙을 저장하는 것은 기존과 같다.
4. 사용자 화면의 팀·라벨 **담당 카테고리**도 같은 목록에서 고른다.
5. 고객 위젯 세션의 서명된 `region` 값이 카테고리 코드와 같으면 그 규칙이 적용된다(기존 매칭 그대로).

## 5. 제약

- **매칭 키는 코드다.** 호스트 앱이 보내는 값과 같아야 하므로 코드는 만들 때만 정하고 이후 바꿀 수 없다. 규칙·팀·라벨·기업이 코드로 참조한다. 이름은 언제든 바꿀 수 있다.
- **코드 정규화**: 저장·비교 모두 `canonicalRegion`(소문자, 공백·하이픈은 `_`, 별칭 접기)을 그대로 쓴다. "North Center"와 `north_center`는 같은 카테고리다.
- **세션 값의 출처는 그대로다**: 서명된 identify의 `region`이고, 없으면 지역표로 성에서 유도한 값이다. 서명 정보가 없는 테넌트(예: ivyusa)는 카테고리를 만들어도 세션 값이 없으므로 **카테고리 조건이 걸린 규칙은 맞지 않는다**. 비우면 "전체"인 것은 기존과 같다. 화면에 이 점을 안내한다.
- **멀티테넌시**: 모든 조회·변경은 `tenant_id`로 거른다. 다른 테넌트의 코드는 검증에서 존재하지 않는 값으로 처리한다.
- **스키마 변경**: 새 테이블을 추가하면 스테이징·프로덕션에 SQL을 먼저 적용해야 한다(`DB_SYNCHRONIZE=false`).
- **권한**
  - 카테고리 변경은 상담원 연결 저장과 같은 `AI_SETTINGS_MANAGE` 권한으로 한다.
  - 목록 조회는 같은 테넌트 사용자 누구나 할 수 있다. 사용자 화면의 팀·라벨 범위 편집과 고객 화면 기업 지역 표시에 필요하기 때문이다.
- **범위 밖**
  - 지역표(성 → 지역) 동기화는 Go2Joy 전용으로 그대로 둔다. 매핑 대상 코드는 카테고리 코드다.
  - 고객 정보 조건의 "지역(성)"(province)은 카테고리가 아니라 그대로 둔다.
