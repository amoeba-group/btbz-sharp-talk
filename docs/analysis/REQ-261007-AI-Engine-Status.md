## 1. AS-IS (2026-10-07 코드·DB 실측)

### 1-1. 테넌트 `/settings/basic` — `AiEngineCard` + `AiUsageCard`

| 항목 | 현재 |
|---|---|
| 내 엔진 | 추가·편집·삭제·기본값·**연결 테스트** 가능. 결과는 카드 하단 한 줄(일시적, 새로고침하면 사라짐) |
| 플랫폼 엔진 | **읽기 전용 목록**(자물쇠 아이콘). "내 엔진이 있으면 그쪽이 우선" 안내만 있다. **선택해서 적용할 방법이 없다** |
| 현재 어느 엔진이 실제로 답하는지 | **표시 없음.** 기능(chat·rag·moderation·summary·assist·coach)별 실효 엔진은 `GET /ai-settings`가 계산하지만(`resolveRouting`), 이 API를 쓰는 화면이 없다 |
| 건강 상태 | **없음.** 마지막 성공·실패·사유가 어디에도 저장되지 않는다 |
| 사용량 | `AiUsageCard`: 기간별 토큰 합계(기능/엔진/주체 축). `ai_usage_daily`에 `failures`·`stub_calls` 열이 있지만 **화면에는 실패 수가 나오지 않는다** |

### 1-2. 어드민 `/admin/ai-engines` — `AiEnginesPage`

| 항목 | 현재 |
|---|---|
| 목록 | 이름·프로바이더·모델·활성·키 유무·생성일. API(`GET /ai-engines`)는 **테넌트 엔진까지 전부** 반환하지만, 화면에는 테넌트 열이 없어 구분할 수 없다 |
| 연결 테스트 | **없음**(테넌트 화면에만 있음) |
| 상태·크레딧 | **없음** |
| 기본 엔진 | 지정 UI 없음. 스테이징 플랫폼 기본은 `Built-in Stub`(id 1), Anthropic(id 2)은 기본 아님 |

### 1-3. 백엔드

- **라우팅**: 기능별 명시 지정(`tenant_ai_settings`) → 상속(coach←rag/chat) → 테넌트 기본 → 플랫폼 기본(현재 스텁).
- **기능별 지정 API는 이미 플랫폼 엔진을 받는다**: `PUT /ai-settings/:function` — "platform-wide or own" 검증(`ai-setting.service.ts upsert`). 화면만 없다.
- **연결 테스트 분류**(`classifyTestFailure`): auth / model / rate_limit / unreachable. **크레딧 부족 분류가 없다.**
  게다가 `AnthropicAdapter`는 응답 본문을 로그에만 남기고 `Anthropic API error 400`만 던진다. 그래서 크레딧 부족이 **unreachable("엔드포인트를 확인하십시오")** 로 표시된다.
- **실패 기록**: `ai_usage_daily.failures`(일 단위 카운트)뿐이다. 사유와 시각은 없다.
- **폼 자동완성**: 키 필드에 `autoComplete="off"`가 이미 있었는데도 자동완성이 일어났다. Chrome은 비밀번호 필드의 `off`를 무시한다(`new-password`가 필요하다).
  endpoint는 일반 텍스트 필드라 "사용자명" 자리로 인식됐다. 서버도 endpoint가 URL인지 검증하지 않는다.

### 1-4. 실측 (2026-10-06~07, 스테이징)


### 2-2. 어드민 `/admin/ai-engines`
1. 엔진별 **연결 테스트** 버튼(플랫폼 엔진과 테넌트 엔진 모두).
2. 엔진별 **현재 상태**: 정상 / 크레딧 부족 / 인증 오류 / 모델 오류 / 한도 초과 / 연결 불가 / 미확인. 마지막 성공·실패 시각, 오늘 호출·실패 수를 함께 보여 준다.
3. **테넌트 열**: 플랫폼/테넌트명 구분. 테넌트 엔진의 장애를 운영자가 먼저 볼 수 있다(go2joy 사례).
4. **크레딧 부족 배너**: 크레딧 부족 엔진이 하나라도 있으면 페이지 상단에 경고와 조치 링크를 띄운다.

### 2-3. 공통(백엔드)
- 실제 호출 결과로 엔진별 **마지막 상태**(성공 시각, 실패 시각, 사유, 요약)를 기록한다. 연결 테스트 결과도 같은 곳에 기록한다.
- 실패 사유에 **`credit`(크레딧/쿼터 부족)** 를 추가한다: Anthropic `credit balance is too low`, OpenAI `insufficient_quota`.
- 어댑터 오류에 프로바이더 오류 유형과 메시지(시크릿 마스킹, 200자)를 포함한다.

## 5. 제약
- **비용 귀속**: 플랫폼 엔진 선택은 **Amoeba 키로 과금**된다. 테넌트가 아무 제약 없이 고를 수 있게 할지는 결정 사항(PLN D1).
- **스키마 변경**: 상태 기록용 열 추가 → `sql/` 마이그레이션, PR `## Migration`, 스테이징 선적용(`DB_SYNCHRONIZE=false`).
- 상태 기록은 응답 경로에 지연을 더하면 안 된다(`await` 금지, 실패해도 무시. 사용량 계측과 같은 원칙).
- 시크릿: 오류 요약은 `redactSecrets`를 거친다. API 키·비밀번호는 응답과 화면에 절대 노출하지 않는다.
- i18n: 6개 언어, `npm run i18n:check`.
- 범위 밖(별도 FIX 권장): **폴백 스텁 응답을 고객에게 보내지 않고 핸드오프** + **모더레이션 실패 시 차단**. 이번 장애의 고객 피해를 직접 막는 조치다(지난 보고의 수정안 1).
