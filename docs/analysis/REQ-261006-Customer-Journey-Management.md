# REQ-261006 — 동일인 대화 그룹핑 보강 + 고객여정관리

- 요청(2026-10-06): "상담대화창 다른 세션이지만 동일인인 경우 그룹핑하는 기능 — 아메바톡 타임라인과
  프로젝트(타임라인=운영자가 상담 중 확인한 정보로 동일인 묶기, 프로젝트=같은 회사·그룹 묶기).
  고객여정분석 및 고객여정관리 기능 구현(아메바톡 참조)."
- 관련 기존 작업: REQ/PLN/RPT-260824-LiveChat-Session-Grouping(PR #352),
  REQ/PLN/RPT-260825 고객여정분석 리포트(PR #375~#385)
- 참조 구현: 아메바톡 `~/Desktop/Site/ambTalkV2`

## 1. AS-IS — 이미 있는 것

| 기능 | 우리 (SharpTalk) | 아메바톡 |
|------|------------------|----------|
| 타임라인/프로젝트 그룹 | ✅ `chat_groups`(kind timeline\|project)·`chat_group_members`(**세션 단위**) — 라이브챗에서 다중 선택→그룹, 병합 피드, 1:1 발신, 설정·해제 | ✅ `atk_bound_chats`(conversation id 스냅샷 — 이후 새 대화는 그룹 밖) |
| 그룹 고객여정분석 | ✅ `journey_reports`·`journey_report_criteria` — 숫자는 코드, 서술은 AI(5A·매슬로우 가설), 비교 리포트, 기준 편집. 그룹 방 [고객여정분석] 패널 | ✅ AI 요약(funnel 6단계·매슬로우)·고객별 대시보드 위젯 25종 |
| 터치포인트 이벤트 | ✅ `cjm_events`(세션 시작→Awareness, 상품조회→Browse, 채팅→Inquiry, 주문→Purchase, 배송→Delivery, 리뷰→Post) — **콘솔 화면 없음**, 리포트 집계·고객 PWA 다이어리만 사용 | 대화 요약의 `timeline_events` |
| 고객 단위 여정 화면 | ❌ (`/customers`는 목록·검색·열람만) | ✅ `customer-journey/[customerId]` |
| 세그먼트(신규/활성/충성/이탈위험) | ❌ | ✅ 규칙 기반 `lifecycle_stage` |

**AS-IS 결론**: 요청의 앞 절반(타임라인·프로젝트 그룹핑, 여정 **분석**)은 8월에 이미 구현돼 스테이징·
프로덕션에 있다. 아메바톡보다 앞선 부분도 있다(세션 단위라 같은 사람의 이후 대화가 자동 유입,
숫자 검증형 리포트, 비교·기준 버전).

## 2. GAP — 실제로 비어 있는 것

| # | 갭 | 우리 | 아메바톡 |
|---|----|------|----------|
| G1 | **동일인 제안** — 같은 고객(customer_id·이메일)의 다른 세션을 상담 중에 알려주고 한 번에 묶기 | 신호(`sessions.customer_id`, `customers.email_hash`, 고객 연결 API)는 있으나 그룹핑에 안 씀 | 없음 |
| G2 | **여정 단계 관리** — 운영자가 이 고객(그룹)의 현재 단계를 지정·변경, 변경 이력 | 없음(이벤트·리포트는 읽기 전용) | 없음(AI·규칙이 쓰기만) |
| G3 | **다음 행동(할 일)** — 담당자·기한·완료가 있는 구조화된 후속 조치 | 리포트 본문 텍스트에만 | AI 추천 텍스트만 |
| G4 | **여정 보드** — 단계별 칸반으로 전체 고객(그룹) 현황 | 없음 | 없음 |
| G5 | **터치포인트 타임라인** — 그룹의 cjm_events·대화를 시간순 한 화면 | 데이터만 있음 | 있음(AI 이벤트) |
| G6 | 1명짜리 여정 — 그룹 최소 2세션 규칙(E5057) 때문에 세션이 하나뿐인 고객은 여정을 가질 수 없음 | 제약 | — |
| G7 | 프로젝트=회사 엔티티 | 그룹 이름으로 대체 | 없음 |

**"고객여정관리"(G2~G5)는 두 제품 모두에 없는 신규 기능**이다. 아메바톡을 따라 할 대상이 아니라
우리 데이터(그룹·cjm_events·리포트)를 토대로 새로 설계한다.

## 3. TO-BE

1. 상담 중 대화 헤더에 "이 고객의 다른 세션 N건" 제안 → [타임라인으로 묶기]/[기존 그룹에 추가]. 결정은 운영자(자동 병합 없음).
2. 그룹(타임라인=사람, 프로젝트=회사)마다 **여정 카드**: 현재 단계·담당자·다음 행동·단계 변경 이력.
3. **여정 보드**(신규 메뉴): 단계별 칸반, 카드 = 그룹, 단계 간 이동 = 단계 변경. 기한 지난 할 일 표시.
4. 그룹 방 여정 패널에 **터치포인트 타임라인**(cjm_events + 대화 시작·종료·CSAT) 추가, 기존 분석 리포트 유지.
5. 리포트가 제안한 다음 행동을 **할 일로 옮기는** 버튼(사람이 고름 — 자동 생성 안 함).

## 4. 사용자 흐름

```
상담원: 대화 열기 ─▶ "같은 고객의 다른 세션 2건" 배너 ─▶ [타임라인으로 묶기]
        └▶ 그룹 방 ─▶ 여정 패널: 단계 [Ask ▾] · 담당 · 할 일 + · 타임라인 · [분석 리포트]
매니저: 여정 보드 ─▶ 'Act' 열에서 기한 지난 카드 확인 ─▶ 카드 클릭 → 그룹 방
```

## 5. 제약

- 동일인 판정은 **제안까지만**. 묶기는 운영자 클릭(요청 문구 "운영자가 상담 시 확인한 정보로") — 오병합이 다른 고객의 대화를 보여주는 개인정보 사고가 되기 때문.
- 테넌트 격리(`tenant_id`), 제안 API는 같은 테넌트 세션만.
- 단계 목록은 테넌트별 편집 가능(쇼핑몰과 go2joy 같은 B2B는 단계가 다름).
- 기존 그룹·리포트 무회귀. 아메바톡과 다른 의도적 선택(세션 단위, 1:1 발신)은 유지.
- 하지 않는 것: AI가 단계를 자동 변경, 고객 점수화·등급, 개인 심리 프로파일링(리포트 원칙과 동일).
