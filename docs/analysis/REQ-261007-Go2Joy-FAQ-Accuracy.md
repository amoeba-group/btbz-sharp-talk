# REQ-261007 — Go2Joy 파트너 에이전트 FAQ 정합성 개선

- 요청(2026-10-07): 「Go2Joy 파트너 에이전트 FAQ 정합성 검증 리포트」(@김익용, 44문항: 일치 35·부분 6·불일치 1·미작성 2)를 참조해 개선 사항 정리
- 검증 대상: 스테이징 go2joy(tenant 4), 위젯 agent=hotel-partner(Joydesk), 대화 **786**(100메시지, 2026-10-07 16:04 KST~)
- 이 문서는 리포트의 각 이슈를 **코드·DB로 원인 확인**한 결과다. 추정은 추정으로 표기했다.

## 1. 이슈별 원인 (실측)

### I-1. 지원 이메일이 "▇▇▇"로 표시됨 — 50개 답변 중 48개 ✅ 원인 확정
- go2joy 모더레이션 규칙 **#18** `regex [\w.+-]+@[\w-]+\.[\w.-]+ → mask`, **scope=both**(고객 입력과 AI 출력 모두).
  고객 개인정보를 가리려고 만든 규칙이 **AI 출력의 공식 연락처**(support@go2joy.vn, KB 원문에 있음)까지 가린다.
- 같은 이유로 규칙 **#20** `\b\d{13,16}\b → mask`는 Go2Joy 수취 계좌번호 `19133261136016`(14자리)도 가린다(I-3의 2차 문제).

### I-2. 북부 Zalo/Hotline 077 789 2399가 "số điện thoại bạn đã cung cấp"로 치환됨 ✅ 원인 확정 (PLN-260929 결함)
- 대화 786 AI 답변의 시간순 패턴: 초반 **OK**(번호 정상) → 중반 **PHRASE**("bạn đã cung cấp", 21건) → 후반 **PARA**("số điện thoại hỗ trợ miền Bắc", 모델이 의역).
- 경로: AI 답변(번호 포함) → 다음 턴의 **대화 이력에 들어갈 때 `scrubPii`가 AI 발화까지 가림**(`077 789 2399` → `[PHONE]`.
  남부 `0931 836 836`은 가리지 않아 정상 노출됐다) → 모델이 `[PHONE]`을 그대로 따라 씀 → 안전망(S7) `replacePiiTokens`가 "고객이 제공한 번호"로 바꿈.
- 즉 **고객 PII 최소화(PRV Stage 5)를 AI 자신의 발화에도 적용한 것**이 원인이다. AI 발화에 있는 번호는 고객 정보가 아니라 KB 출처 값이다.
- 리포트의 "A2·B3·C2·D1·D3에서는 정상"은 대화 초반이었거나 KB 원문을 새로 인용한 경우다.

### I-3. D3 계좌정보 "문서에서 찾지 못했다" ✅ 원인 확정 (검색 순위)
- FAQ 문서 **#3361** 「Tôi (khách sạn) có thể thanh toán cho Go2Joy như nào?」가 있고 인덱싱도 정상이다(Qdrant point 존재, active).
  계좌·은행·수취인이 본문 376자 지점에 있어 잘림과도 무관하다.
- 질문이 문서 제목과 거의 같은데도 벡터 검색에서 **4위(0.521)** 였다. 위 3개는 "결제 방식 설정"류 문서다(0.58·0.56·0.556).
  대화 앞부분이 결제 방식 주제라 문맥 검색어까지 그쪽으로 기울어, 최종 6건에서 빠졌다. 답변 인용: 「결제 방식 설정」「미수금 추적」.
- 설령 찾았더라도 계좌번호는 I-1의 규칙 #20 때문에 "▇▇▇"가 됐을 것이다.

### I-4. C1·B3 등 긴 FAQ의 후반부 누락 ✅ 원인 확정 (문서 앞 800자만 사용)
- RAG 컨텍스트는 문서마다 **앞 800자**(`RagService.SNIPPET_CHARS = 800`)만 모델에 준다.
- C1 문서 **#3355**(1,588자)는 "Chưa thanh toán"이 **830자** 지점에서 시작한다 → 모델은 "Đã thanh toán"까지만 봤다. 전화번호 확인법(1,092자)도 잘렸다.
- go2joy 활성 문서 227건 중 **131건(58%)이 800자를 넘는다**(평균 1,533자, 최대 25,224자). 길이가 긴 FAQ는 전부 같은 위험이 있다.

### I-5. 긴 답변이 중간에 끊김 ✅ 원인 확정 (출력 토큰 한도)
- 대화 786에서 가장 긴 답변 2건(약 1,750자)이 "📧", "Thứ 2"에서 끊겼다. 베트남어는 글자당 토큰이 많아 **출력 한도 1,024토큰**에 닿았다.
- 모든 답변에 붙는 **연락처 꼬리말**(약 200~300자)이 한도를 더 줄인다.

### I-6. 답변 간 불일치·오기술 (C4 vs I13, E2, D4) — 일부 데이터 원인
- **C4 vs I13**("15분 후" vs "15분 이내"): FAQ 원문 자체가 모호하다(리포트 지적과 일치) → Go2Joy에 전달할 사항
- **D4** 정산 일정: 문서 #3363(785자)에 "ngày 17"이 222자 지점에 **있다**. 잘림이 아니고, FAQ에 일정 서술이 2가지(T+2 영업일 / 매월 2·17일)라 모델이 한쪽만 골랐다 → 데이터 정비
- **E2** "선결제 취소 불가"를 '체크인 이후' 조건 없이 서술: 원인 미확정(문서 잘림 또는 모델 요약). I-4 수정 후 재측정 필요

### I-7. G3 사용 가이드 링크 없음 — 데이터
- 가이드 문서 #2501(25,224자)에 URL이 없다. go2joy FAQ 문서는 Notion 동기화가 아니라 수동 등록(`knowledge_store`)이고, 원문 링크가 텍스트만 옮겨졌다.

### I-8. 백그라운드 탭에서 답변 표시가 늦음 ✅ 원인 확정 (위젯)
- 위젯 메시지 폴링 5초(`useChat` `refetchInterval`). React Query 기본값이 **백그라운드 탭에서는 폴링을 멈추고**(`refetchIntervalInBackground: false`),
  전역 설정 `refetchOnWindowFocus: false`라 **탭으로 돌아와도 즉시 재조회하지 않는다** → 최대 한 주기 더 지연된다.

### I-9. 회귀 테스트 — 기존 기능 확장 가능
- 골든 질문 회귀(FR-073, `GoldenService`)가 있다. 다만 **최대 20문항**이고, 의도적으로 판정 없이 차이만 보고한다.
  44문항 세트 + 자동 채점(기대 사실 포함 여부)을 하려면 확장이 필요하다.

## 3. 제약
- R1·R2는 PII 최소화(PRV Stage 5) 원칙을 지킨다. **고객이 입력한 PII는 계속 마스킹**하고, 예외는 KB·테넌트 설정에서 온 **출처가 확인된 값**뿐이다.
- R3은 프롬프트 길이(비용)를 늘린다 — 문서당 상한과 총 컨텍스트 상한을 함께 둔다.
- R4 꼬리말 템플릿은 테넌트별 설정(6개 언어)이므로 콘솔 화면 변경이 따른다(PLN에서 와이어프레임).
- 수정 후 같은 44문항으로 재측정해 리포트와 비교한다(R7 전에는 수동).
