# REQ-260920 — 채팅 위젯 노출·접속 통계 추가

| 항목 | 내용 |
|---|---|
| 작성일 | 2026-09-20 |
| 요청 | `/statistics`에 채팅 위젯 접속 기록 통계 추가 — **전체 · 에이전트별 · 노출된 URL별** |
| 유형 | 요구사항 (REQ→PLN→승인→구현) |
| 조사 기준 | main `044dae2`, 스테이징 실데이터(2026-09-20) |

## 1. AS-IS — 무엇이 이미 있고 무엇이 없나

### 1.1 노출 데이터는 **이미 쌓이고 있습니다** (핵심)

위젯 루트(`Widget.tsx`)가 `useEnsureSession()`을 호출하므로, 고객이 패널을 **열기 전**
iframe이 로드되는 시점에 `POST /session/ensure`가 호출됩니다. 임베드 상태에서는 세션
토큰을 재사용하지 않으므로(`embedded ? null : getStoredSessionToken()`), **상점 페이지
로드마다 `sessions` 행이 하나씩 생깁니다.**

즉 `sessions` 테이블이 사실상 **위젯 노출 로그**입니다. 스테이징 실측(최근 7일):

| 테넌트 | 세션(=노출) | 대화까지 간 세션 | 대화 전환율 |
|---|---|---|---|
| 2 (go2joy) | 3,929 | 11 | 0.3% |
| 6 | 935 | 0 | 0% |
| 5 | 115 | 0 | 0% |
| 1 (ivyusa) | 41 | 5 | 12% |
| **합계** | **5,062** | **19** | **0.4%** |

**이 숫자가 이번 요구사항의 값어치를 그대로 보여줍니다.** 현재 `/statistics`의 모든
지표는 *대화가 생긴 뒤*를 다루므로, 위 표의 왼쪽 열(노출 5,062)은 콘솔 어디에도
드러나지 않습니다. 운영자는 "위젯이 얼마나 보여지고 있는지", "어느 페이지에서 보이는데
아무도 안 여는지"를 볼 방법이 없습니다.

### 1.2 축별 가용성

| 축·지표 | 현재 상태 |
|---|---|
| **노출**(전체) | ✅ 즉시 가능 — `sessions`를 기간·테넌트로 집계(미리보기 `channel='preview'` 제외) |
| **접속**(패널 열람) | ❌ **서버 미기록** — §4 참조. GA4가 켜진 테넌트만 GA4에서 볼 수 있음 |
| **에이전트별** | ⚠️ 컬럼은 있음(`sessions.ai_agent_id`, 인덱스 `idx_sessions_tenant_agent`)이나 **스테이징 전 세션이 NULL**. 배관(로더 `cfg.agent` → `&agent=` → `agent_code` → `resolveAiAgentId`)은 정상이고, 테넌트가 스니펫에 `agent`를 쓰지 않을 뿐. NULL = "기본 에이전트"로 **명시 표기 필요**(빈 표가 아니라) |
| **노출된 URL별** | ❌ **데이터 없음** — 서버는 페이지 URL을 저장하지 않음(§1.3) |

### 1.3 URL — 유일한 진짜 공백

로더는 이미 페이지 URL을 **알고 있고 보내고도 있습니다**:

```js
out.push('ivy_land=' + encodeURIComponent(String(window.location.href).slice(0, 300)));
```

그러나 이 값은 위젯 안에서 **GA4로만** 흘러갑니다(`utm.ts` → `add('landing_page', …)`).
`EnsureSessionRequest`에는 해당 필드가 없고(`session_token`·`locale`·`shop_domain`·
`parent_origin`·`agent_code`가 전부), `sessions` 테이블에도 URL 컬럼이 없습니다.

즉 **GA4를 쓰는 테넌트만** 페이지별 노출을 볼 수 있고, 콘솔에서는 볼 수 없습니다.
GA4 연동은 선택 기능(동의 게이트 + `ga4Id` 설정)이라 이것을 공식 답으로 삼을 수 없습니다.

## 2. TO-BE

`/statistics`에 **접속** 섹션을 추가해 세 가지 축을 제공:

1. **전체** — 기간별 **노출 · 접속 · 대화**와 각 전환율, 일별 추이
2. **에이전트별** — 에이전트(미지정은 "기본 에이전트")별 동일 3지표
3. **노출 URL별** — 페이지 경로별 동일 3지표

핵심 가치는 단순 카운트가 아니라 **깔때기의 어느 칸에서 끊기는가**입니다 —
"이 페이지엔 위젯이 3,000번 떴는데 아무도 안 열었다"(노출→접속 단절)와 "열긴 열었는데
아무도 말을 안 건다"(접속→대화 단절)는 **처방이 완전히 다릅니다.**

## 3. 제약·리스크

### 3.1 개인정보 — URL 원문 저장은 위험

상점 URL의 쿼리스트링에는 이메일·주문번호·토큰이 실려 올 수 있습니다
(예: `/orders?email=...&token=...`). CLAUDE.md의 PII 마스킹·CCPA/GDPR 기조상
**원문 URL을 그대로 저장하면 안 됩니다.**
→ **경로만 정규화 저장**(scheme+host+pathname), 쿼리·해시 폐기. 집계 목적에도 경로가
맞습니다(같은 상품 페이지가 쿼리 때문에 수백 개로 쪼개지지 않음).

### 3.2 카디널리티

`/products/{handle}` 류가 수천 개로 늘 수 있습니다. 저장은 행당 1개 컬럼이라 부담이
없지만, **화면은 상위 N개 + 나머지 묶음**으로 제한해야 합니다.

### 3.3 기존 지표와의 혼동

`/statistics`의 기존 "대화 수"와 신규 "노출 수"는 **자릿수가 다릅니다**(5,062 vs 19).
같은 화면에 나란히 두면 오독 위험이 큽니다 → 깔때기 3칸(노출·접속·대화)을 **항상 같이**
보여주고 전환율을 함께 표기.

### 3.3b 접속은 "횟수"라 부풀 수 있음

패널을 열고 닫기를 반복하면 접속 횟수가 늘어납니다. 그래서 **접속 횟수**와
**접속한 세션 수(고유)** 를 함께 보여줘야 "한 사람이 여러 번"과 "여러 사람이 한 번"을
구분할 수 있습니다. 노출→접속 전환율은 **고유 세션 기준**으로 계산합니다(횟수 기준이면
100%를 넘을 수 있음).

### 3.4 보존

`sessions`는 대화 로그 보존 정책(기본 365일)의 적용을 받습니다. 접속 통계도 같은 창을
따르며, 이는 기존 로그 기반 섹션(채널·상담원·처리·시간대)과 동일한 성격입니다.

### 3.5 소급 불가

URL과 접속 모두 지금부터 수집하므로 **배포 이전 노출에는 값이 없습니다**. 화면에 "수집 시작일"
명시 필요(기존 *AI 사용량* 카드가 쓰는 방식과 동일).

## 4. 용어 확정 (2026-09-20 사용자 결정)

**노출과 접속은 서로 다른 지표이며 둘 다 산출합니다.**

| 용어 | 정의 | 현재 수집 |
|---|---|---|
| **노출(impression)** | 위젯이 페이지에 로드됨(iframe 로드) | ✅ `sessions` 행 |
| **접속(access)** | 고객이 **패널을 연 횟수** | ❌ **서버 미기록** — 신규 수집 필요 |

이로써 화면은 **노출 → 접속 → 대화**의 깔때기가 됩니다. 기존 `/statistics`가 마지막
칸(대화)만 보여주던 것에서, 앞의 두 칸이 처음으로 드러납니다.

### 4.1 접속 수집 지점은 이미 존재합니다

`Widget.tsx`에 패널 열림 **전환을 감지하는 단일 지점**이 있습니다(중복 발화 방지 포함):

```ts
if (panelOpen !== prevOpen.current) {
  if (panelOpen) analytics.widgetOpen();   // ← 현재 GA4로만
  else analytics.widgetClose();
  prevOpen.current = panelOpen;
}
```

현재 이 이벤트는 **GA4가 켜진 테넌트에서만** 나갑니다(`ga4Id` + 동의). 접속 통계는
GA4 여부와 무관해야 하므로 **같은 지점에서 자사 API로도 보고**합니다.

⚠️ **앱 모드 주의**: `panelOpen: isAppMode()` — WebView 앱 모드는 패널이 열린 채
시작하므로 노출=접속이 됩니다. 집계에서 이를 구분해 표기해야 오독이 없습니다.
