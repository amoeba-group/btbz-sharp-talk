# REQ-261023 라이브챗 — 대화 안 고객 메시지·상담원 메시지 각각 번역

- 작성일: 2026-10-23
- 요청 유형: [요구사항] — https://shoptalk.amoeba.site/live-chat 대화(Conversation) 패널
- 선행: REQ/PLN-260826-LiveChat-Message-Actions (R2 메시지 번역, PR #392), FIX-261006 번역 팝오버 클리핑

## 0. 요구사항 원문

> https://shoptalk.amoeba.site/live-chat
> Conversation 안에서 고객대화와 에이전트 대화 각각 번역기능 추가

## 1. 요구 해석

"각각"을 **방향별 두 가지 번역**으로 해석한다.

| # | 대상 | 목적 | 비고 |
|---|---|---|---|
| T1 | **고객 메시지**(`sender=user`) | 상담원이 고객 말을 자기 언어로 읽는다 | 기구현 — 노출 조건이 좁아 확대 |
| T2 | **상담원·AI 메시지**(`sender=agent/ai`) | 상담원(또는 관리자)이 이미 나간 답변을 자기 언어로 읽는다 | **신규** — 현재 버튼 자체가 없음 |
| ~~T3~~ | ~~작성 중 답장 번역 후 발송~~ | — | **범위 제외(2026-10-23 사용자 확정)**: 답장 번역은 운영자 열람 전용, 발송 기능 불필요 |

## 2. AS-IS (origin/main `0c62791d` 기준 코드 확인)

- **번역 API**: `POST /agent/messages/:id/translate {lang}` (`agent.service.ts` `translateMessage`).
  테넌트 스코프 조회, 6개 시스템 언어 검증, Redis `msgtr:{id}:{lang}` 24h 캐시, `feature='agent_translate'`.
  ⚠️ 시스템 프롬프트가 `"Translate the customer message into …"` 로 **고객 메시지 전제** — 서버는 sender를 막지 않지만
  상담원/AI 메시지에 그대로 쓰면 프롬프트 의미가 어긋나고, AI 답변의 마크다운(목록·링크) 보존 지시가 없다.
- **콘솔 UI** (`LiveChatPage.tsx`):
  - 번역 버튼은 `m.senderType === 'user' && msgActionsVisible` 일 때만, 지식조회·답글·이슈와 **한 묶음**의 호버 액션열에 있다.
  - `msgActionsVisible = !(status==='ai_active' && autoReplyEffective && mode!=='approve')` — **AI 자동응답 중인 대화에서는 번역도 숨겨짐**
    (PLN-260826 D2는 "끼어들 일 없음"이 근거였으나, 번역은 읽기 전용이라 그 근거가 해당하지 않는다. 모니터링 중 외국어 대화를 못 읽음).
  - 인라인 번역 서브버블도 `senderType==='user'` 조건이라 좌측 정렬·밝은 배경 고정.
  - 상담원/AI 버블(우측 정렬, 상담원은 `bg-primary-500 text-white`)에는 액션열이 없다.
- **컴포저**: 한 줄 `<input>` + 발송. 번역 기능 없음. 발송은 `sendMessage` → `ModerationService.moderate()`(FR-069) 경유.
- **고객 언어**: `chat_sessions.language`(대문자 `EN`/`VI`…)가 서버에 있으나 대화 상세 응답(DTO)에 **노출되지 않음** — 콘솔은 고객 언어를 모른다.
- 저장: 번역은 행에 저장하지 않음(흐르는 데이터, 캐시만). 스키마 변경 필요 없음.

## 3. TO-BE

### T1. 고객 메시지 번역 — 항상 사용 가능
- 번역 버튼을 액션 묶음에서 분리: **번역은 대화 상태와 무관하게 노출**, 지식조회·답글·이슈 3종은 기존 게이트 유지.
- 동작(팝오버 6개 언어·인라인 서브버블·닫기·캐시)은 기존과 동일.

### T2. 상담원·AI 메시지 번역 — 신규
- `sender=agent|ai` 버블에도 호버 시 번역 버튼(버블 **왼쪽**, 시각 표시 옆). `system` 메시지는 제외.
- 서브버블은 **원 버블 쪽(우측) 정렬**, 원문 유지. 언어 선택 팝오버는 T1과 동일 컴포넌트.
- 서버: 같은 엔드포인트·캐시, **발화자별 프롬프트**(고객 메시지 / 지원 답변 — 마크다운·링크 보존). 응답 계약 불변.

## 4. 제약·원칙

- 테넌트 격리: 번역 대상 메시지는 `tenant_id`로 조회(기존 유지).
- 모더레이션: 번역(T1·T2)은 운영자 콘솔 전용으로 고객에게 나가지 않으므로 대상 아님. 발송 경로 무변경.
- PII: 번역 입력은 상담원 화면에 이미 보이는 본문 그대로(마스킹 대상 아님 — 기존 T1과 동일 취급). 로그에 본문을 남기지 않는다.
- 비용: 메시지·언어별 캐시로 1회.
- i18n: 신규 문구 6개 언어, `npm run i18n:check`. 성공/실패 토스트(실패=수동 닫기) 준수.
- 스키마 변경 없음 → 마이그레이션 없음. 신규 에러코드 없음(기존 `VALIDATION_FAILED`·`BRIEFING_FAILED` 재사용).

## 5. 사용자 흐름

1. 상담원이 베트남어 고객 메시지에 마우스를 올림 → 번역 → 한국어 → 아래에 한국어 서브버블 (AI 자동응답 중 대화에서도 가능)
2. 지난 AI 답변(베트남어)에 마우스 → 번역 → 한국어 → 우측에 한국어 서브버블

## 6. 갭 요약

| 갭 | 조치 |
|---|---|
| 상담원/AI 버블에 번역 없음 | T2 UI + 발화자별 프롬프트 |
| 자동응답 중 대화는 번역 불가 | T1 게이트 분리 |
| 프롬프트가 고객 메시지 전제·마크다운 보존 없음 | 서버 프롬프트 분기 |
