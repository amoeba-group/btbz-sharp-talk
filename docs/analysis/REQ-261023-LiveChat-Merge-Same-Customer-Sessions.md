# REQ-261023 라이브챗 — 같은 고객의 세션을 한 대화방으로 통합 · 이후 세션 자동 추가

- 작성일: 2026-10-23
- 요청 유형: [요구사항] — https://shoptalk.amoeba.site/live-chat
- 선행: REQ/PLN-260824-LiveChat-Session-Grouping(타임라인/프로젝트, PR #352), PLN-261006 P1 동일인 제안(PR #588), PLN-261022 2단계 대화 연속성(PR #689), PLN-261023 S3·S4(번호 통일·claimed 대화 귀속, PR #708)

## 0. 요구사항 원문

> 실시간상담 대화방세션 선택후 타임라인/프로젝트 외에 동일한 사용자/고객인 경우 대화방세션을 통합하여 한 대화방에서 볼수 있게 합치는 기능필요. 이후 세션이 달라도 동일 사용자인 경우 합쳐진 대화방에 자동으로 추가될수 있도록 선택기능 필요

## 1. 요구 해석

| # | 요구 | 해석 |
|---|---|---|
| R1 | 세션 선택 후 같은 고객의 대화방 세션을 **통합** | 열려 있는 대화에서 [같은 고객 대화 통합]을 누르면, 같은 고객으로 판정된 다른 세션들이 후보로 나온다. 운영자가 고른 세션들이 **하나의 통합 대화방**이 된다 |
| R2 | 타임라인/프로젝트 **외에** | 별도 탭의 '그룹 방'(읽기 전용 병합 피드 + 수신자 선택 1:1 발신)이 아니다. **평소 쓰는 대화방 화면 자체**가 합쳐진다. 목록에도 한 줄로 보이고, 고객 패널·AI 토글·종료·인계를 그대로 쓴다 |
| R3 | 한 대화방에서 보기 | 통합된 모든 세션의 모든 대화 메시지를 시간순으로 한 화면에 보여 준다. 세션·대화가 바뀌는 지점에는 구분선을 둔다 |
| R4 | 이후 세션도 자동 추가 — **선택 기능** | 통합방마다 "같은 고객의 새 세션 자동 추가" 스위치를 둔다. 켜져 있으면 그 고객의 새 세션이 생기거나 기존 세션이 그 고객으로 확인될 때 통합방에 들어온다 |

## 2. AS-IS

### 2-1. 이미 있는 것

| 기능 | 동작 | 이번 요구와의 차이 |
|---|---|---|
| 타임라인/프로젝트 그룹 (`chat_groups`, `chat_group_members`, #352) | 운영자가 세션을 골라 묶는다. [그룹] 탭의 별도 '그룹 방'에서 병합 피드를 본다. 답장은 수신 세션을 직접 골라 1:1로 보낸다. 멤버 세션의 **이후 대화**는 자동으로 들어온다 | ① 일반 목록에서는 세션이 따로따로 보인다 ② 그룹 방에는 고객 패널·AI 토글·종료·인계가 없다 ③ 같은 고객의 **새 세션**은 자동으로 들어오지 않는다 ④ kind(timeline/project)는 동작 차이가 없는 구분자다(설계 원칙) |
| 동일인 제안 배너 (`relatedSessions`, #588) | 열린 대화와 같은 고객인 다른 세션을 배너로 보여 준다. 판정 기준은 `sessions.customer_id`가 같거나 고객 행의 `email_hash`가 같은 경우다. 그룹 생성·추가로 연결된다 | 판정 기준을 재사용할 수 있다. 다만 claimed 세션은 `sessions.customer_id`가 NULL이라 **후보에서 빠진다**(PLN-261023 S4부터 `conversations.customer_id`에만 고객이 있음) |
| 대화 연속성 (`conversations.prev_conversation_id`, `thread_continuity`, #689) | 같은 계정의 새 대화를 직전 대화와 연결하고, 상담원 sticky 배정과 AI 이전 대화 발췌에 쓴다 | 연결 정보만 있을 뿐 콘솔에서 합쳐 보이지 않는다. 테넌트 옵션이다(go2joy 스테이징=1) |

## 3. TO-BE

```
목록                                  대화방 (통합)
┌─────────────────────────┐   ┌──────────────────────────────────────────┐
│ ● 김하나 · 세션 912 [통합 3]│ → │ 김하나 · 세션 912  [통합 3 ▾] [찾기] [⋯] │
│   "환불 문의드려요"   2분 │   │ ─── 세션 120 · 웹 · 10/02 ───             │
│ ○ 이둘 · 세션 905        │   │  고객: 사이즈 문의…                        │
└─────────────────────────┘   │ ─── 세션 388 · 앱 · 10/15 ───             │
                              │  고객: 배송 언제…                          │
                              │ ─── 세션 912 · 웹 · 오늘 (진행 중) ───      │
                              │  고객: 환불 문의드려요                      │
                              │ [답장 대상: 세션 912 ▾] [입력……] [보내기]  │
                              └──────────────────────────────────────────┘
```

- 목록에는 통합방 하나가 **한 줄**로 보인다. 그 줄은 가장 최근 대화를 대표로 삼고, `[통합 N]` 배지를 붙인다.
- 대화방은 기존 대화방 화면 그대로다. 메시지는 통합된 세션 전체를 시간순으로 보여 주고, 고객 패널·AI·종료·인계는 **답장 대상 대화**에 적용된다.
- 답장 대상의 기본값은 진행 중인 대화다(여럿이면 가장 최근). 진행 중인 대화가 없으면 가장 최근 대화다. 바꿀 수도 있다.

## 4. GAP

| # | 갭 | 필요 작업 |
|---|---|---|
| G1 | 통합방이라는 개념이 없다 | 통합방 저장 구조, 생성·해제·세션 빼기 API |
| G2 | 일반 목록은 대화 단위 행이다 | 통합방에 속한 대화들을 대표 1행으로 접는다(페이지네이션·검색·필터와 함께) |
| G3 | 대화방 메시지 API는 대화 1개 단위다 | 통합방 범위로 넓힌 메시지 피드(기존 그룹 피드의 전역 id 커서 재사용), 세션 구분선, 답장 대상 선택 |
| G4 | 동일인 판정이 claimed 대화를 놓친다 | 판정 출처에 `conversations.customer_id` 추가 |

| G6 | 운영자가 뺀 세션이 자동 추가로 다시 들어올 수 있다 | 제외 기록 |

## 5. 사용자 흐름

1. 상담원이 목록에서 대화를 연다. 같은 고객의 다른 세션이 있으면 헤더에 [같은 고객 대화 통합 (N)]이 보인다(기존 동일인 배너 자리).
2. 누르면 후보 세션 목록이 체크된 상태로 나온다(채널·마지막 대화 시각 포함). 아래에 □ "이후 같은 고객의 새 세션 자동 추가" 체크박스가 있다.
3. [통합]을 누르면 목록이 1행으로 바뀌고, 대화방이 합쳐진 메시지로 다시 그려진다. 성공 토스트가 뜬다.
4. 이후 그 고객이 새 세션으로 문의하면, 자동 추가가 켜져 있을 때 같은 행이 맨 위로 올라오고 대표 대화가 새 대화로 바뀐다.
5. [통합 N ▾] 메뉴에서 세션별로 [이 세션 빼기]를 할 수 있다. 뺀 세션은 다시 자동 추가되지 않는다. 메뉴에는 [자동 추가 켜기/끄기]와 [통합 해제]도 있다.

## 6. 제약

- 통합은 **보기와 답장 대상의 묶음**이다. 대화·메시지·배정·상태·통계·CSAT는 대화 단위 그대로 두고, 아무것도 옮기거나 지우지 않는다. 해제하면 원래대로 돌아간다(그룹과 같은 원칙).
- 발신은 언제나 대화 1개를 대상으로, 기존 `AgentService.sendMessage` 경로를 탄다(모더레이션·동의·감사 상속, 수신 전용 채널 거부).
- 동일인은 **확인된 신원**으로만 판정한다. 게스트(신원 없음) 세션은 후보에 나오지 않는다. claimed(서명 없는 신원)는 PLN-261023 D4대로 대화 귀속까지만 인정하므로, 후보에는 나오되 '미검증' 표시를 붙인다.
- 다른 테넌트의 세션은 섞이지 않는다(모든 조회에 `tenant_id`).
- 목록 쿼리는 5초 주기로 폴링된다. 접기 조건을 추가해도 기존 인덱스로 감당해야 한다.
- 다른 세션에서 진행 중인 REQ-261023-LiveChat-Bidirectional-Translation이 `LiveChatPage.tsx`의 메시지 영역을 수정한다. 충돌 가능성이 있으므로 머지 순서를 맞춘다.
