SharpTalk · Cài đặt → Nền tảng

Kết nối nền tảng thương mại: nhập giá trị nào, tìm ở đâu

Hướng dẫn thực tế về các giá trị bạn nhập ở /settings/platforms để kết nối từng cửa hàng — tên đăng nhập, tên cơ sở dữ liệu, API key… — và phát hành hoặc tìm mỗi giá trị ở đâu trong trang quản trị của nền tảng. Chuẩn bị giá trị, chọn nền tảng ở Thêm nền tảng, dán vào hộp thoại cài đặt, lưu, rồi kiểm tra bằng Kiểm tra kết nối.

Bố cục màn hình (sửa ngày 19/10/2026) — /settings/platforms có hai phần. Nền tảng đã kết nối chỉ hiển thị thẻ cho nền tảng đã lưu thông tin xác thực; nhãn là Đã kết nối (kiểm tra hoặc đồng bộ thành công), Lỗi, hoặc Chưa kiểm tra (mới lưu). Thêm nền tảng liệt kê mọi nền tảng được hỗ trợ dưới dạng nút; nền tảng đã kết nối được đánh dấu ✓. Nếu bạn vận hành nền tảng tự phát triển, không thuộc Shopify, Cafe24, WooCommerce, Odoo hay Haravan, hãy dùng nút Nền tảng riêng và chỉ đăng ký tên cùng mô tả (không cần phát hành giá trị nào; hiển thị "Đã đăng ký" ngay).

Chung cho mọi nền tảng

  • Giá trị bí mật (token, secret, API key) không hiển thị lại sau khi lưu — chỉ nhập lại khi xoay vòng.
  • URL phải là https:// miền công khai. Địa chỉ nội bộ/riêng tư (localhost, IP nội bộ) bị chặn vì lý do bảo mật.
  • Quyền tối thiểu cần có là đọc đơn hàng, khách hàng và sản phẩm. Không cần quyền ghi.
  • Khi kiểm tra kết nối thất bại, thẻ hiển thị lý do — 401 = token sai/hết hạn, 404 = sai địa chỉ.
  • Các hình minh họa màn hình bên dưới là hình minh họa vị trí phát hành mỗi giá trị; màn hình thật của nhà cung cấp có thể khác về từ ngữ và bố cục.

Phát hành trong trang quản trị Shopify

  1. Vào Settings → Apps and sales channels.
  2. Develop apps → Create an app, rồi đặt tên app.
  3. Ở Configuration → Admin API integration, cấp các scope đọc.read_orders · read_customers · read_fulfillments · read_products
  4. Nhấn API credentials → Install app.
  5. Sao chép Admin API access token (shpat_…) hiển thị ngay sau khi cài.Token chỉ hiển thị một lần — lưu vào SharpTalk ngay.
  6. Địa chỉ cửa hàng là phần xxxx.myshopify.com trong URL quản trị (không phải tên miền thương hiệu).
↔Nếu đã cài qua nút "Connect" của app công khai SharpTalk, token được lưu tự động. Nhập thủ công ở trên là dành cho app tùy chỉnh do bạn tự vận hành.

02Cafe24

Kết nối cửa hàng Cafe24 bằng access token Admin API v2 OAuth.

Cửa hàng kết nối qua OAuth được kiểm tra, đồng bộ (đơn hàng · danh mục) và mở từ thẻ Cafe24 trong Nền tảng đã kết nối; Cấu hình chạy lại bước cấp quyền (2026-10-19). Kiểm tra kết nối trên thẻ sẽ cấp access token thật và đọc 1 sản phẩm (hoặc đơn hàng).

Admin API v2 · Bearer (OAuth)

SharpTalk yêu cầu gì

Mall IDmall_idID cửa hàng (vd: yourmall)bắt buộc

Tìm trong Cafe24 Developer Center

  1. Mall ID — phần yourmall của URL quản trị yourmall.cafe24.com, hoặc ID cửa hàng hiển thị ở đầu trang quản trị.
  2. Client ID / Secret — đăng nhập developers.cafe24.com → Tạo app → tìm ở mục App info của app.Thêm scope đọc cho app — mall.read_order · mall.read_customer · mall.read_product.
  3. Access token — dán token Admin API phát hành qua luồng OAuth (Authorization Code → Access Token).Hiệu lực 2 giờ; refresh token 14 ngày — phát hành lại khi hết hạn.
↔Nút "Connect" OAuth của Cafe24 ở đầu phần Cài đặt kết nối chỉ với một cú nhấp bằng tài khoản chủ cửa hàng và tự quản lý token. Nên dùng nếu nhập token thủ công phiền phức.

03WooCommerce

Kết nối bằng consumer key/secret REST API v3 (Basic auth).

REST v3 · Basic auth

Phát hành trong trang quản trị WordPress · WooCommerce

  1. Vào WooCommerce → Settings → Advanced → REST API.
  2. Nhấn Add key.
  3. Nhập mô tả, chọn User, đặt Permissions thành Read.
  4. Generate API key → Consumer key (ck_…) và Consumer secret (cs_…) xuất hiện.Không xem lại được sau khi rời màn hình — sao chép ngay.
  5. Store URL là địa chỉ gốc của trang. Đừng thêm /wp-admin hay /wp-json.
!Kiểm tra kết nối gọi …/wp-json/wc/v3/system_status. 404 = REST API tắt hoặc sai URL (kiểm tra permalink), 401 = sai key/secret.

04Odoo

Xác thực với API ngoài (JSON-RPC) bằng URL · DB · người dùng · API key.

★ trọng tâm

SharpTalk xác minh bốn giá trị này bằng cách gọi common.authenticate(db, username, api_key) tại {url}/jsonrpc.

① Server URL

  1. Phần host của địa chỉ bạn mở Odoo.Odoo Online (SaaS): https://mycompany.odoo.com · Tự lưu trữ / Odoo.sh: tên miền thật của bạn. Đừng thêm đường dẫn như /web.

② Tên cơ sở dữ liệu  — tìm ở đâu

  1. Odoo Online (SaaS) — tên DB = subdomain. Với mycompany.odoo.com thì DB là mycompany.
  2. Tự lưu trữ — tên hiển thị trong dropdown cơ sở dữ liệu ở màn hình đăng nhập.Nếu không có dropdown (một DB): tên liệt kê ở …/web/database/manager, hoặc thiết lập -d <db> / db_name của server.
  3. Nhập đúng định danh DB (kể cả chữ hoa/thường và dấu gạch nối), không phải tên công ty hay tên hiển thị.

③ Username

  1. ID đăng nhập Odoo (thường là email). API hoạt động với quyền của người dùng này, nên dùng tài khoản tích hợp riêng có quyền đọc đơn hàng, liên hệ và sản phẩm.

④ API key  — phát hành ở đâu trong Odoo

  1. Mở avatar → My Profile / Preferences ở góc trên bên phải.
  2. Vào tab Account Security.Nếu không có, trước tiên bật Settings → Activate the developer mode.
  3. Developer API Keys → New API Key → đặt tên mục đích → xác nhận mật khẩu → sao chép key ngay.Key chỉ hiển thị một lần. Nó thay cho mật khẩu khi gọi API ngoài, nên hãy dùng API key — không dùng mật khẩu tài khoản.
!Thành công thì thẻ hiển thị Connected (uid N). Lỗi authentication failed — check db / user / API key thường do gõ sai tên DB.

Phát hành trong trang quản trị Haravan

  1. Địa chỉ cửa hàng — địa chỉ quản trị Haravan your-store.myharavan.com.
  2. Access token — tạo Private App hoặc tích hợp Admin API trong mục Apps của trang quản trị và dùng token nó phát hành.Cấp quyền đọc đơn hàng, khách hàng và sản phẩm. Admin API của Haravan tương thích Shopify, nên SharpTalk xác minh với …/admin/shop.json bằng Bearer token.
  3. Dán token vào ô Access token, lưu và kiểm tra. 401 = token sai/hết hạn.
