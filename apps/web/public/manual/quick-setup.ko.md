## 0. 시작 전에

**용어**

| 용어 | 뜻 |
|---|---|
| 테넌트(tenant) | 샵톡에 입주한 하나의 상점. 데이터·설정·지식이 상점 단위로 완전히 분리됩니다 |
| 슬러그(slug) | 테넌트 전용 로그인 주소 조각. `https://shoptalk.amoeba.site/user/ivyusa`처럼 주소 끝에 붙습니다 |
| 플랫폼 관리자 | `/admin`으로 로그인하는 샵톡 운영사 관리자 (테넌트 개설 권한) |
| 테넌트 관리자(master) | 상점 콘솔의 최고 권한 직급. 팀원·권한·설정 전체를 관리합니다 |
| 임시 비밀번호 | 초대 시 시스템이 발급하는 1회용 비밀번호. **화면에 한 번만 표시**됩니다 |

**준비물**
- 플랫폼 관리자 계정 (`/admin/login`)
- 개설할 상점의 **쇼핑몰 도메인** (예: `example.myshopify.com`, `mallid.cafe24.com`)
- 테넌트 관리자로 초대할 사람의 **이메일 주소**
- 연동할 플랫폼의 자격증명 (3장 참조 — 테넌트 관리자가 준비)

**소요 시간**: 어드민 작업 ~5분 + 테넌트 첫 세팅 ~30분 (플랫폼 연동 승인 대기 제외)

## 1. 테넌트 개설
*(플랫폼 관리자 · `/admin/tenants`)*

### 1.1 새 테넌트 생성

`/admin/tenants` → **[새 테넌트]** 버튼 → 모달에서 4개 필드 입력:

| 필드 | 필수 | 설명 |
|---|---|---|
| 이름 | ✅ | 상점 표시 이름 |
| 로그인 경로(slug) | — | 비우면 이름에서 자동 파생. 입력 시 자동 소문자화 |
| 쇼핑몰 도메인 | ✅ | 상점의 대표 도메인. Shopify면 `*.myshopify.com`, Cafe24면 몰 도메인 등 **모든 플랫폼 공용** |
| 요금제 | ✅ | `starter` / `growth` / `enterprise` / `custom` — 플랜에 따라 기본 제공 메뉴가 다릅니다. 개설 후에는 행의 **[요금제/애드온]**에서 변경(이슈 워크플로우 애드온 base/bridge/native도 여기서) |

💡 **팁 — 슬러그 규칙**: 소문자·숫자·하이픈만, 콘솔 화면 이름(`admin`, `login`,
`dashboard`, `settings` 등 예약어)과 겹칠 수 없습니다. 예약어를 입력하면 서버가
자동으로 `-shop` 접미를 붙입니다. 슬러그는 곧 로그인 URL이므로 상점이 기억하기 쉬운
값을 권장합니다.

### 1.2 (선택) 제공 메뉴 조정

테넌트 행의 **[제공 메뉴]** → 메뉴별로 3단 선택:

| 모드 | 의미 |
|---|---|
| 플랜 따름 | 요금제 기본값 그대로 (기본) |
| 강제 제공 | 플랜과 무관하게 이 테넌트에 제공 |
| 차단 | 플랜과 무관하게 미제공 |

결과 열이 즉시 바뀌고, 예외 설정된 행에는 `*`가 표시됩니다.

💡 **팁**: 여기서 차단한 메뉴는 테넌트 master가 직급 권한을 줘도 보이지 않습니다
(2계층 구조: 어드민 제공 → 테넌트 내부 권한). 이슈 보드는 워크플로우 모드 설정도
함께 필요합니다.

### 1.3 테넌트 관리자 초대 + 임시 비밀번호 발급

테넌트 행의 **[사용자 관리]** → `/admin/tenants/…/users` → **[사용자 초대]**:

1. `이메일` 입력, `직급`은 기본값 **master** 유지 (첫 관리자이므로)
2. **[초대]** 클릭 → 즉시 **임시 비밀번호 모달**이 뜹니다

```
┌─ 임시 비밀번호 발급됨 ───────────────────────┐
│ user@shop.com 님의 임시 비밀번호              │
│ ┌──────────────────────────┐                 │
│ │  TmpXXXXXXXXX!           │   [복사]        │
│ └──────────────────────────┘                 │
│ ⚠️ 이 값은 지금 한 번만 표시됩니다.           │
│    안전한 경로로 전달하고, 최초 로그인 시     │
│    반드시 변경됩니다.                         │
└──────────────────────────────────────────────┘
```

> ⚠️ **임시 비밀번호는 이메일로 발송되지 않습니다.** 이 모달에 1회 표시되는 값을
> 관리자가 복사해 **직접 전달**해야 합니다. 창을 닫아 값을 잃었다면 그 사용자 행의
> **[임시 비밀번호]** 버튼으로 재발급하면 됩니다 (이전 값은 무효화).

💡 **팁 — 전달 보안**: 비밀번호를 이메일 본문·단체 채팅에 남기지 마세요. 1:1 보안
메신저나 전화로 전달하고, 첫 로그인(=강제 변경)이 끝났는지 확인하는 것까지가
개설 절차입니다. 발급 이력은 감사 로그(`/admin/audit`)에 남습니다.

### 1.4 로그인 URL 전달

같은 화면 상단 카드에 이 테넌트의 **로그인 페이지 URL**(`https://…/슬러그`)이 표시됩니다.
**[복사]** 해서 임시 비밀번호와 함께 전달하세요.

전달할 것 3가지: ① 로그인 URL ② 이메일(계정 ID) ③ 임시 비밀번호

## 2. 첫 로그인
*(테넌트 관리자 · `https://shoptalk.amoeba.site/user/<슬러그>`)*

### 2.1 로그인

전달받은 URL로 접속하면 상점 이름이 표시된 로그인 화면이 나옵니다. 이메일 + 임시
비밀번호로 로그인합니다.

💡 **팁**: "해당 매장을 찾을 수 없음"이 나오면 URL의 슬러그 철자를 확인하세요.
**이메일 기억하기**를 켜면 이 브라우저에서 다음부터 이메일이 채워집니다.

### 2.2 강제 비밀번호 변경

로그인 직후 **닫을 수 없는 비밀번호 변경 창**이 뜹니다 (취소 불가 — 임시 비밀번호로는
콘솔을 쓸 수 없습니다).

- `현재(임시) 비밀번호` + `새 비밀번호` + `확인` 입력
- 새 비밀번호 규칙 3가지가 입력 중 실시간으로 ✓/✕ 표시됩니다:
  **① 최소 10자 ② 대문자·소문자·숫자·특수문자 중 3종 이상 ③ 흔한 비밀번호 아님**
- 본인 이메일이 포함된 비밀번호, 직전과 같은 비밀번호는 서버에서 거부됩니다

### 2.3 MFA(2단계 인증) 등록

master·director 직급은 보안 정책상 **MFA(TOTP) 등록이 강제**됩니다.

| 용어 | 뜻 |
|---|---|
| TOTP | Google Authenticator 등 인증 앱이 30초마다 생성하는 6자리 코드 |
| 복구 코드 | 인증 앱을 잃었을 때 대신 쓰는 1회용 코드 10개 — **등록 직후 한 번만 표시** |

- 시행일 전: 상단에 노란 유예 배너(마감일 표시) → 마이페이지에서 미리 등록 가능
- 시행일 후: 등록 전까지 콘솔 사용이 차단되는 등록 창이 뜹니다
- 등록: QR 스캔(또는 수동 키 입력) → 앱의 6자리 코드 입력 → **복구 코드 10개를
  다운로드/보관** → 완료. 이후 로그인마다 6자리 코드를 추가 입력합니다

💡 **팁**: 복구 코드는 이때 한 번만 보여줍니다. 반드시 저장하세요. 인증 앱과 복구
코드를 모두 잃으면 관리자(어드민 또는 상점 master)의 **[MFA 리셋]**으로만 풀 수
있습니다.

## 3. 커머스 플랫폼 연동
*(콘솔 좌측 메뉴 **[테넌트 설정]** → **플랫폼 연동** 탭)*

> 설정은 **8개 탭**입니다: 기본 설정(AI 엔진·사용량·스토어프론트·지식 옵션) / 상담원 연결 /
> 위젯 설정 / 플랫폼 연동 / 마케팅·헬프데스크 / 메신저 채널 / 기타 설정 / 개인정보
> 안내. 이 장은 *플랫폼 연동* 탭, 4장은 *위젯 설정* 탭입니다.

플랫폼 연동 탭의 타일에서 사용할 플랫폼의 **[설정]**을 누르면 연동 창이 열립니다.
탭 우상단 **[연동 가이드]**가 플랫폼별로 자격증명을 어디서 찾는지 알려줍니다.
⚠️ **저장 ≠ 연결**: 자격증명을 저장하면 상태가 "미테스트"입니다 — **[연결 테스트]**를
통과해야 "연결됨"이 됩니다(실패 시 "오류").

| 용어 | 뜻 |
|---|---|
| 자격증명(credential) | 플랫폼 API에 접근하기 위한 키·토큰. 암호화 저장되며, 저장 후에는 값 대신 "설정됨"으로만 표시됩니다 |
| 연결 테스트 | 저장한 자격증명으로 실제 API를 1회 호출해 유효성을 확인하는 버튼 |
| 동기화(sync) | 플랫폼의 주문·상품 데이터를 샵톡 캐시로 가져오는 작업 |

### 3.1 Cafe24 ✅

**권장 경로 — OAuth 연결 카드**: 플랫폼 연동 탭의 *Cafe24 (OAuth)* 카드에서
1. `몰 ID` 입력 (`몰ID.cafe24.com`의 몰ID 부분)
2. **[연결]** → Cafe24 인가 페이지로 이동 → 로그인·권한 승인 → 콘솔로 자동 복귀
3. 연결됨 배지 확인 후 **[지금 동기화]**(주문) / **[상품 동기화]** 실행

💡 **팁**: 상품 동기화는 상품 **캐시**까지만 채웁니다. 이 상품들을 AI가 답변에 쓰게
하려면 [지식] 화면의 **카탈로그 동기화**(미리보기→실행)를 별도로 실행해야 합니다 —
[지식·AI 매뉴얼 2.2장](knowledge-ai.ko.md) 참조.

수동 경로(토큰을 이미 보유한 경우): Cafe24 타일의 모달에 `mall_id` +
`access_token`(+ client_id/secret)을 직접 입력할 수도 있습니다. OAuth 연결이 표준입니다.

### 3.2 Shopify ✅

Shopify 타일의 모달:

| 필드 | 필수 |
|---|---|
| 쇼핑몰 도메인 (`*.myshopify.com`) | ✅ |
| Admin API Access Token | ✅ |
| API Key / API Secret | 선택 |

저장 후 **[연결 테스트] → [지금 동기화] → [웹훅 등록]** 순서로 실행합니다. 웹훅을
등록해야 주문·배송 상태 변화가 실시간으로 위젯 알림에 반영됩니다.
토큰 발급 절차는 쇼피파이 연동 가이드 참조.

### 3.3 Odoo · WooCommerce · Haravan ✅

각 타일 모달에 자격증명(Odoo: `서버 URL`/`DB 이름`/`사용자명`/`API Key`)을 입력하고
**[연결 테스트]**를 통과시킨 뒤, 같은 모달의 **[상품 가져오기] / [주문 동기화]**로
데이터를 가져옵니다. 가져온 상품을 AI가 답변에 쓰려면 [지식]의 카탈로그 동기화가
별도로 필요합니다(3.1 팁과 동일).

### 3.4 스토어프론트 URL

**기본 설정 탭**의 *스토어프론트* 카드에 상점의 **고객용 사이트 주소**를 입력하세요.
미설정 시 위젯의 상품 링크가 비활성화됩니다(카드에 경고 표시).

> 그 외 Klaviyo·Yotpo(마케팅)·Gorgias(헬프데스크)는 *마케팅·헬프데스크* 탭,
> 메신저 채널(텔레그램·바이버·지메일 등)은 *메신저 채널* 탭에서 같은 방식의
> 타일/카드로 연동합니다. 이 문서에서는 생략합니다.

## 4. 채팅위젯 설정·설치
*(**[테넌트 설정] → 위젯 설정** 탭)*

### 4.1 위젯 설치

**설치 가이드 카드**에서 플랫폼 탭(Shopify / Cafe24 / WooCommerce / Odoo)을 선택하면
해당 플랫폼용 설치 스니펫과 단계 안내가 나옵니다. 모든 코드 블록에 복사 버튼이 있습니다.

- **Shopify**: 앱 임베드(권장) / ScriptTag / 수동 설치 3방식 탭
- **Cafe24**: 몰 디자인에 붙여넣는 전용 스니펫 (회원 로그인 경로가 포함되어 있음)
- **WooCommerce**: `functions.php`용 PHP 스니펫 / **Odoo**: 범용 HTML 스니펫

**임베드 & SDK 카드**에서는:
- 범용 설치 스니펫(`embed.js`) 복사
- **허용 도메인**: 위젯을 띄울 도메인 목록. 비워두면 스토어프론트 URL이 적용됩니다
- **서명 시크릿**: 회원 신원 연동(로그인 연동) 시 사용. **[생성]하면 값이 한 번만
  표시**되니 즉시 복사해 서버 담당자에게 전달하세요

💡 **팁**: 설치 후 실제 쇼핑몰 페이지를 열어 우하단 런처(말풍선 버튼)가 뜨는지
확인하는 것이 가장 확실한 검증입니다. 안 뜨면 [9장 문제 해결](#9-문제-해결) 참조.

### 4.2 문구·동작 (위젯 동작 카드)

| 항목 | 설명 |
|---|---|
| 로그인 방식 | `redirect`(쇼핑몰 로그인 페이지로 이동 후 복귀, 기본) / `popup`(팝업 로그인) |
| 타임존 | 상점 기준 시간대 — 영업시간 표시 등에 사용 |
| 표시 이름 | 위젯 헤더에 보이는 상점 이름 (최대 80자) |
| 첫 방문 인사 / 로그인 후 인사 | **6개 언어 탭**(EN/ES/KO/VI/JA/ZH)별로 각각 작성 (최대 500자) — 필드 아래 "기본 문구:"로 기본값이 표시됩니다 |

💡 **팁**: 인사말을 언어별로 비워두면 기본 문구가 나갑니다. 주력 언어 하나만 먼저
정성껏 쓰고 나머지는 나중에 채워도 됩니다.

### 4.3 탭·테마

**위젯 탭 카드**: 알림 / 주문 / 채팅 3탭 중 노출할 탭 선택(최소 1개는 유지 — 마지막
1개는 해제 불가), 탭 위치는 상단/하단.

**위젯 테마 카드**: `브랜드 색상`(피커/HEX) · `헤더 스타일`(흰색/브랜드색) ·
`로고` 업로드 · `런처` 위치(좌/우)·크기(sm/md/lg)·아이콘(채팅/물음표/헤드셋/로고).
오른쪽 미리보기에서 즉시 확인할 수 있습니다.

**커스텀 위젯 카드**(테마 카드 아래): 폰트·글자 크기·모서리·패널 크기·런처 아이콘까지
바꾸고 싶다면 **[커스텀 위젯 만들기]**로 이름 있는 디자인을 만들고 **[사용함]**을 누릅니다.
배포 없이 즉시 반영되고, 언제든 **[기본 위젯으로 복귀]**할 수 있습니다. 폰트·아이콘
파일은 **디자인 파일** 카드에 먼저 올립니다. 상세: 사용자 설명서 14장.

💡 **팁**: 색은 **브랜드 색 하나만** 고르면 됩니다. 밝기 단계와 글자색은 대비
기준(4.5:1)에 맞춰 자동 계산되므로 "밝은 색을 골랐더니 글씨가 안 보이는" 일은 없습니다.
저장한 테마는 **고객의 다음 위젯 세션부터** 반영됩니다. 상세:
위젯설정가이드.

## 5. AI 최소 설정
*(좌측 메뉴 **[AI 설정]**)*

AI 설정 화면은 왼쪽에 설정 카드들, 오른쪽에 **미리보기/코칭 스튜디오**가 있는 구조입니다.
개설 단계에서는 세 가지만 확인하면 됩니다.

| 용어 | 뜻 |
|---|---|
| 페르소나 | AI 상담봇의 말투·태도·원칙을 서술한 텍스트. 모든 AI 답변의 톤을 결정 |
| 응답 규칙 | AI가 반드시 지킬 규칙 목록 (한 줄 = 규칙 1개) |
| 엔진 | 답변을 생성하는 AI 모델. 플랫폼 관리자가 등록한 것 중 선택 |
| stub(스텁) | 실제 AI 키 없이 동작하는 데모 응답기. **실서비스 품질이 아님** |

1. **봇 페르소나** 카드에 상점 소개·말투·금지사항을 서술하고 저장
   (예: *"OO몰의 친절하고 간결한 상담사입니다. 제공된 지식에서만 답하세요."*)
2. **응답 규칙**에 최소 2~3개 등록
   (예: "환불 완료를 단정하지 말 것", "특정 날짜 도착을 보장하지 말 것")
3. **AI 기능** 카드에서 각 기능의 적용 엔진을 확인 — **`stub` 배지가 보이면 실제
   엔진이 연결되지 않은 것**입니다. 해결 방법 2가지: ① [테넌트 설정 → 기본 설정]의
   *AI 엔진* 카드에 **내 API 키로 자체 엔진을 등록**(플랫폼 엔진보다 우선, 비용은
   우리 계정으로 청구) ② 플랫폼 관리자에게 공용 엔진 등록(`/admin/ai-engines`)을
   요청.

💡 **팁**: 시나리오 버튼(위젯 하단 빠른 메뉴)은 기본 6종(배송 조회·취소/환불·제품
도움말·고객 지원 문의·제휴·내 주문)이 **6개 언어 라벨과 함께** 자동 적용되므로 개설
단계에서 손대지 않아도 됩니다. 페르소나·규칙 작성 요령과 전체 AI 설정은
[지식·AI 매뉴얼 4장](knowledge-ai.ko.md) 참조.

## 6. 지식 최초 입력
*(좌측 메뉴 **[지식]**)*

AI는 **등록된 지식에서만** 답합니다. 지식이 없으면 대부분의 질문이 상담원에게
넘어가므로, 개설 단계에서 핵심 정책 지식부터 채우세요. 가장 빠른 경로는 **범용
상담가이드**입니다:

1. 문서 카드 위 그룹 탭에서 **CounselInfo** 선택 → **[일괄등록]** → 안내 블록의
   **범용 상담가이드**(바로 쓰는 기본 상담 KB, 90행 규모)를 CSV/XLSX로 다운로드
2. 기한·비용·정책을 상점에 맞게 수정 → 같은 창에 업로드 → 생성·갱신 건수 확인
   - 배송·취소/환불·교환/반품·FAQ가 한 번에 채워집니다. 같은 파일을 나중에 고쳐
     다시 올리면 **중복 없이 갱신**됩니다(라운드트립)
3. 개별 문서는 **[보드에 작성]**(권장 — 게시 후 [KB 채택]) 또는
   **[지식베이스문서 추가]**(긴급용)로 등록합니다
4. 오른쪽 **지식으로 답변하기(QA) 패널**에 고객이 물을 법한 질문을 입력해
   답변·출처·신뢰도를 확인 — 방금 등록한 문서가 출처 목록에 뜨면 성공입니다

💡 **팁**: 문서 제목·본문에 **고객이 실제 쓰는 표현**(예: "배송 얼마나 걸려요")을
포함하면 검색 적중률이 올라갑니다. 지식 보드 워크플로우, 상품 지식 대량 등록
(카탈로그 동기화·CSV), AI 임포트(pdf·docx·md·YouTube), 외부 소스(Google Drive·
Notion) 연동, 검증·품질 관리는
[지식·AI 매뉴얼](knowledge-ai.ko.md)에서 다룹니다.

  직무 라벨 선택 → 1장과 동일한 **임시 비밀번호 모달**이 뜹니다(1회 표시·직접 전달).

  위젯에서 상담 주제를 고르게 하려면 *상담카테고리 관리*에서 노출함으로 두세요. 규칙을 만든
  뒤에는 **배정 확인**으로 누구에게 연결되는지 확인하세요. 상세는
  [지식·AI 매뉴얼 5장](knowledge-ai.ko.md) 참조.

## 9. 문제 해결

**Q. 로그인이 안 됩니다 (임시 비밀번호).**
임시 비밀번호는 재발급하면 이전 값이 무효화됩니다. 최신 발급본인지 확인하고, 안 되면
관리자에게 재발급을 요청하세요. 로그인 URL의 슬러그가 다른 상점 것은 아닌지도 확인하세요
(2회 이상 실패 시 화면에 안내가 뜹니다).

**Q. 임시 비밀번호 창을 닫아버렸습니다.**
값은 다시 볼 수 없습니다. 사용자 행의 **[임시 비밀번호]** 버튼으로 재발급하세요.

**Q. 위젯이 쇼핑몰에 안 뜹니다.**
① 스니펫이 실제 배포된 페이지에 있는지 ② 임베드 카드의 허용 도메인에 해당 도메인이
포함되는지(비어 있으면 스토어프론트 URL 기준) ③ 브라우저 캐시 새로고침 순으로 확인하세요.

**Q. AI 답변이 이상하게 기계적입니다.**
AI 기능 카드에 `stub` 배지가 있는지 보세요. 스텁은 데모용 응답기입니다.
[테넌트 설정 → 기본 설정]의 *AI 엔진* 카드에 자체 엔진을 등록하거나 플랫폼
관리자에게 공용 엔진 등록을 요청하세요. *AI 사용량* 카드의 "폴백 n회" 경고도 같은
신호입니다.

**Q. AI가 자꾸 "상담원 연결"로 넘깁니다.**
해당 주제의 지식 문서가 없거나 비활성 상태일 가능성이 큽니다. 6장대로 문서를 등록하고
QA 패널로 확인하세요.

**Q. 설정을 바꿨는데 위젯이 그대로입니다.**
위젯 설정(문구·테마·탭)은 고객의 **다음 세션**부터 반영됩니다. 위젯을 닫았다 열거나
페이지를 새로고침하세요.
