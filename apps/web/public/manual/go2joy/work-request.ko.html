1. 연동 규격 변경 이력 v1.1

Go2Joy가 v1.0 PDF로 구현한 부분이 있어, 버전별 차이를 한 표로 정리합니다. v1.4 열이 최종 규격이며, SharpTalk은 10/24 가이드 v1.4와 새 테스트 벡터를 배포했습니다(S-01 완료).

항목 v1.0 (10/20 PDF) v1.3 v1.4 (본 요청서)
userId 로그인 ID(go2joysupport) "ha:" + userSn v1.3과 같음
서명 속성 키 5개: hotel_id · hotel_name · province · region · role 5개(같음) 4개: hotel_id · hotel_name · province_sn · role
성·시 province = 성 이름(Hồ Chí Minh) 같음 province_sn = Go2Joy provinceSn(Province Feed sn, 예: Hồ Chí Minh = "1")
지역 HA 산출 3값(north · central · south) HA 산출 5코드 보내지 않음. SharpTalk이 Province Feed region(1 ~ 5)으로 산출
역할 표시명(Lễ tân) 같음 HA 역할 코드(화면 언어와 무관한 값). 코드표는 WR-01에서 회신
값 정규화 공백 정리 · trim · 120자 + NFC 순서 고정: NFC → 공백 정리 → trim → 120자(mb_substr)
"전체 호텔" 선택 규정 없음 재호출만 규정 호텔 키 3개(hotel_id · hotel_name · province_sn)를 빼고 role만 서명 → 폴백 담당자(WR-13)
빈 값 빈 attributes·email 제외 같음 빈 name · email · phone도 필드째 제외(email 빈 값·형식 오류는 400)
테스트 벡터 T1 · T2(옛 userId) T1 ~ T5 T1 ~ T6(T6 = 분해형 유니코드 입력). 이전 벡터는 사용하지 않음
전환 기간 SharpTalk은 v1.3 형식(province · region 키)도 당분간 서명 검증을 통과시킵니다. 배정에는 v1.4 값을 우선 사용합니다. HA가 v1.4로 전환하면 종료합니다(S-02).

3.1 HA 개발팀 — 백엔드

WR 작업 상세 완료 기준 우선 기한(제안) 관련
WR-01 서명 엔드포인트 구현 v1.1 로그인 세션으로 호출하는 API(예: GET /api/v1/staff/sharptalkIdentity)가 서버에서 패키지를 만들어 서명합니다.
① userId = "ha:" + userSn
② 속성 4개: hotel_id · hotel_name · province_sn · role(역할 코드). region은 보내지 않음
③ "전체 호텔"이면 호텔 키 3개를 빼고 role만
④ 정규화 순서: Normalizer::normalize($v, Normalizer::FORM_C) → 공백 정리 → trim → mb_substr(…, 0, 120). PHP intl 확장 필요
