전체 그림

카페24 연동은 세 가지 연결로 이루어집니다. 셋은 독립적이라, 필요한 것만 켜도 됩니다.

① 관리자 연결 (OAuth, 3장)        몰 → 샵톡   주문·상품을 읽어 옴 (읽기 전용)

      └─ 상품 가져오기 (5장)        → 지식 변환 → AI가 상품을 인용·링크
② 위젯 설치 (스마트디자인, 6장)    샵톡 → 몰   모든 페이지에 채팅 위젯
③ 회원 로그인 (7장)               몰 회원 ↔ 위젯 세션   위젯 안에서 '내 주문' 표시

01

플랫폼 관리자 — 개발자센터 앱과 서버 설정

이 장은 배포당 한 번만 합니다. 이미 다른 테넌트가 카페24 연결을 쓰고 있다면 건너뛰고 2장으로 가세요.

1.1 개발자센터 앱 등록

  1. developers.cafe24.com에 로그인 → 앱 만들기로 샵톡용 앱을 만듭니다.
  2. 앱 정보에서 Client ID와 Client Secret을 확인합니다(1.3절 환경변수에 넣습니다).
  3. Redirect URI에 콘솔 도메인의 콜백 주소를 정확히 하나 등록합니다. 스테이징 https://shoptalk.amoeba.site/api/v1/auth/cafe24/callback · 프로덕션 https://sharptalk.amoeba.site/api/v1/auth/cafe24/callback
  4. 권한(Scope)에 아래 4개를 추가합니다. 모두 읽기 권한입니다.
권한쓰는 곳
mall.read_order주문 동기화(4장)
mall.read_product상품 가져오기(5장)
mall.read_category상품의 카테고리 이름(5장) — 없으면 지식 문서의 카테고리가 비어 버립니다
mall.read_customer_identifier회원 로그인(7장)
⚠️ 카페24는 앱 하나에 Redirect URI를 하나만 받습니다.

그래서 관리자 연결과 회원 로그인이 같은 콜백(/auth/cafe24/callback)을 함께 쓰고, 샵톡이 요청 종류를 내부에서 구분합니다. 스테이징과 프로덕션은 콜백 주소가 다르므로 앱을 따로 만드세요.

💡 팁

회원 개인정보 권한(mall.read_personal)은 필요 없습니다. 회원 아이디는 회원 로그인 토큰 응답에 들어 있어 개인정보 리소스를 읽지 않습니다. 권한이 적을수록 카페24 심사·몰 운영자 동의가 쉬워집니다.

1.2 권한을 나중에 추가했다면

권한을 추가해도 이미 연결된 몰에는 반영되지 않습니다. 토큰은 동의한 시점의 권한으로 발급되기 때문입니다. 권한을 추가한 뒤에는 각 테넌트가 3장의 [Cafe24 연결]을 다시 눌러 재동의해야 합니다. 재동의 없이 새 권한을 쓰는 기능을 실행하면 카페24가 insufficient_scope로 거부합니다.

1.3 서버 환경변수

API 컨테이너의 env 파일(env/backend/.env.{환경})에 설정합니다.

변수값비고
CAFE24_CLIENT_ID앱의 Client ID필수 — 비어 있으면 연결 시 E5010
CAFE24_CLIENT_SECRET앱의 Client Secret필수
CAFE24_REDIRECT_URI1.1의 콜백 주소와 글자 하나까지 동일다르면 토큰 교환이 실패합니다
CAFE24_CONSOLE_RETURN_URL콘솔 주소 (예: https://sharptalk.amoeba.site)연결 후 운영자가 돌아올 곳
CAFE24_SCOPESmall.read_order,mall.read_product,mall.read_category관리자 연결 권한
CAFE24_CUSTOMER_SCOPESmall.read_customer_identifier회원 로그인 권한
CAFE24_SYNC_INTERVAL_MIN예: 30주문 자동 동기화 주기(분). 0이면 끔
CAFE24_LOGIN_SYNC_LOOKBACK_DAYS기본 30 (최대 90)회원 로그인 직후 보충 동기화 범위
⚠️ 값을 비운 줄(`CAFE24_SCOPES=`)을 남기지 마세요.

빈 줄은 "기본값 사용"이 아니라 "빈 값"으로 읽힙니다 — 권한이 빈 채로 동의 화면이 열리거나, 연결 후 콘솔로 돌아오지 못합니다. 쓰지 않는 변수는 줄째 지우고, 쓰는 변수는 위 표처럼 값을 명시하세요. CAFE24_CUSTOMER_REDIRECT_URI·CAFE24_API_HOST_TEMPLATE·CAFE24_AUTH_HOST_TEMPLATE·CAFE24_API_VERSION은 특별한 이유가 없으면 줄째 지웁니다.

⚠️

env를 바꾼 뒤에는 API 컨테이너를 재시작하고, 부팅 로그에 Cafe24 auto-sync enabled — every N min(또는 disabled)이 의도대로 찍혔는지 확인하세요.

02

테넌트 기본 설정 — 스토어 도메인·상점 주소

설정 > 기본 설정 > 스토어프론트 카드에서 두 값을 먼저 저장합니다. 연결 전에 해야 하는 이유는, 샵톡이 이 값으로 "이 몰이 정말 이 테넌트의 몰인가"를 검사하기 때문입니다.

필드넣는 값쓰이는 곳
스토어 도메인yourmall.cafe24.com위젯이 이 테넌트를 찾는 기준 · 연결/동기화 시 몰 일치 검사
상점 주소https://yourmall.cafe24.com채팅에서 상품 링크를 클릭 가능하게 만드는 기준

몰 일치 검사: 스토어 도메인(또는 상점 주소)이 *.cafe24.com이면, 3장에서 다른 몰 ID를 입력해 연결하려 할 때 거부되고(E5045), 이미 저장된 연결도 몰이 다르면 주문 동기화를 거부합니다. 한 글자 오타로 다른 상점의 주문이 섞여 들어오는 사고를 막는 장치입니다.

⚠️

두 값이 서로 다른 카페24 몰을 가리키면 어느 쪽도 믿을 수 없으므로 연결과 동기화가 모두 거부됩니다. 둘 다 같은 몰로 맞추세요.

💡 팁

브랜드 독자 도메인(예: www.brand.co.kr)을 쓰는 몰도 연결은 됩니다 — 다만 비교할 근거가 없어 몰 일치 검사를 건너뛰고 서버 로그에 경고만 남깁니다. 이 경우 몰 ID를 특히 꼼꼼히 확인하세요. 회원 로그인(7장)은 *.cafe24.com 주소에서만 동작합니다.

03

몰 연결 — OAuth 동의

설정 > 플랫폼 연동의 Cafe24 (OAuth) 카드에서 진행합니다. master 직급만 할 수 있습니다.

  1. 몰 ID 칸에 상점 아이디를 입력합니다(yourmall). yourmall.cafe24.com이나 https://yourmall.cafe24.com/을 붙여 넣어도 알아서 몰 ID만 씁니다.
  2. [Cafe24 연결]을 누르면 카페24 동의 화면으로 이동합니다.
  3. 몰 대표 운영자 계정으로 로그인해 권한에 동의합니다.
  4. 콘솔로 돌아오면 「Cafe24 연결됨: yourmall」 토스트가 뜨고 상태가 연결됨으로 바뀝니다. 이때부터 [지금 동기화]·[상품 가져오기] 버튼이 나타납니다.
돌아왔을 때 표시뜻 · 조치
Cafe24 연결됨: {몰}성공
요청 권한을 거부했습니다 (invalid_scope)개발자센터 앱에 해당 권한이 없음 → 1.1의 권한 4개 추가 후 다시 연결
동의가 거부되었습니다 (access_denied)동의 화면에서 취소했거나 권한 없는 계정 → 대표 운영자 계정으로 재시도
Cafe24 연결 실패아래 원인 중 하나 — 9장 FAQ 참고

「Cafe24 연결 실패」의 흔한 원인:

  • 몰 ID가 스토어 도메인의 몰과 다름(E5045) → 2장의 스토어 도메인 확인
  • 그 몰이 이미 다른 테넌트에 연결됨(E5046) → 몰 하나는 테넌트 하나에만 연결됩니다
  • 동의 화면에서 10분 넘게 머묾(E5011) → 처음부터 다시
  • 서버에 앱 값이 없음(E5010) → 플랫폼 관리자에게 1.3절 요청
💡 팁

같은 테넌트가 같은 몰을 다시 연결하는 것은 언제든 안전합니다. 권한을 추가했거나(1.2절) 토큰이 만료됐을 때(4.3절) 그냥 [Cafe24 연결]을 다시 누르면 새 토큰으로 교체됩니다.

⚠️

콘솔에는 연결 해제 버튼이 없습니다. 잘못된 몰을 연결했다면 올바른 몰로 다시 연결하거나(같은 테넌트면 교체됨), 플랫폼 관리자에게 자격증명 삭제를 요청하세요.

04

주문 동기화

카페24에는 Shopify 같은 실시간 웹훅이 없어, 샵톡이 주기적으로 주문을 가져옵니다. 가져온 주문은 AI 상담(배송 문의 등)과 위젯의 '내 주문'(7장)에 쓰입니다.

4.1 동기화가 일어나는 세 경로

경로범위언제
[지금 동기화] 버튼최근 7일 · 최대 2,000건운영자가 누를 때
자동 동기화최근 7일CAFE24_SYNC_INTERVAL_MIN분마다, 연결된 모든 테넌트
회원 로그인 보충최근 30일(설정 시 최대 90일)회원이 위젯에서 로그인한 직후

4.2 절차

  1. [지금 동기화]를 누릅니다.
  2. 토스트에 결과가 표시됩니다(예: Synced 12 order(s)).
  3. 콘솔 주문 메뉴에서 카페24 주문이 보이는지 확인합니다.
💡 팁

카페24 주문 조회는 한 번에 최대 3개월 범위만 허용합니다. 그래서 어느 경로도 90일을 넘겨 가져오지 않습니다. 오래된 주문 문의는 상담원이 카페24 관리자에서 직접 확인하세요.

4.3 토큰 유지

연결 토큰은 2시간짜리 접근 토큰 + 14일짜리 갱신 토큰으로 이루어지며, 샵톡이 쓸 때마다 자동으로 갱신합니다. 자동 동기화가 켜져 있으면 갱신이 계속 일어나 만료될 일이 없습니다.

⚠️

자동 동기화가 꺼진 배포에서 14일 넘게 아무 동기화도 하지 않으면 갱신 토큰이 만료됩니다. 이때 동기화 결과에 Cafe24 store is not connected — reconnect the mall이 표시되며, 3장의 [Cafe24 연결]을 다시 하면 복구됩니다.

05

상품 → 지식 변환

상품 정보는 두 단계로 지식이 됩니다. 중간에 미리보기를 두는 것은 상품 목록 갱신이 지식베이스를 몰래 바꾸지 않게 하기 위해서입니다.

[상품 가져오기] (설정 > 플랫폼 연동)      카페24 상품 → 샵톡 상품 목록
        │
        ▼
[카탈로그에서 동기화] (지식)               미리보기 확인 → [동기화 실행] → 상품당 지식 문서 1건 + 색인

5.1 상품 가져오기

  1. 설정 > 플랫폼 연동 > Cafe24 (OAuth)에서 [상품 가져오기]를 누릅니다.
  2. 「상품 N건 동기화, M건 보관됨 — 지식 메뉴에서 변환을 실행하세요」가 뜨면 성공입니다.
  • 보관됨: 이번에 몰에서 찾을 수 없었던(삭제·미진열) 상품입니다. 가져오기가 끝까지 완료된 경우에만 보관 처리하며, 중간에 끊긴 실행은 아무것도 보관하지 않습니다.
  • 상품명·가격·카테고리·옵션 값·상품 태그를 가져옵니다. 설명이 짧은(80자 미만) 상품은 상세 설명을 추가로 조회합니다.

5.2 지식으로 변환

  1. 지식 메뉴에서 [카탈로그에서 동기화]를 누릅니다.
  2. 미리보기에서 신규·갱신·흡수·보류 건수를 확인합니다.
  3. [동기화 실행] → 문서 작성 → 색인(임베딩)이 끝나면 완료입니다. 몇 분 걸리며, 창을 닫아도 계속됩니다.

보류설명과 태그가 모두 비어 답변 근거가 될 수 없는 상품
💡 팁

한국 쇼핑몰은 상세 설명을 이미지로만 올리는 경우가 많아 텍스트 설명이 거의 없습니다. 그래서 샵톡은 카테고리·옵션 값·상품 태그를 항상 태그로 채워, 설명이 없어도 상품이 보류되지 않게 합니다. 답변 품질을 높이려면 카페24 상품에 검색어(태그)와 간단설명을 텍스트로 채워 두세요.

⚠️

지식이 만들어져도 상점 주소(2장)가 비어 있으면 채팅의 상품 인용이 링크 없는 글자로만 나옵니다. 카페24 상품 링크는 https://yourmall.cafe24.com/product/detail.html?product_no={번호} 형식으로 만들어집니다.

06

위젯 설치 — 스마트디자인

6.1 스니펫 복사

  1. 설정 > 위젯 설정 > 설치 가이드 카드에서 플랫폼 Cafe24를 고릅니다.
  2. 표시된 스니펫을 복사합니다. 스토어 도메인(2장)이 이미 들어가 있습니다.
<!-- SharpTalk widget (Cafe24) -->
<script>
  window.SHARPTALK_WIDGET_CONFIG = {
    shop: "yourmall.cafe24.com",
    locale: "ko",
    widgetUrl: "https://shoptalk.amoeba.site/widget",
    loginPath: "/member/login.html",
    loginReturnParam: "returnUrl"
  };
</script>
<script src="https://shoptalk.amoeba.site/widget/embed.js" defer></script>

6.2 카페24 관리자에 붙여 넣기

  1. 카페24 관리자 → 디자인(PC/모바일) → 스마트디자인 편집을 엽니다.
  2. 대표 디자인의 레이아웃 HTML(공통 레이아웃)을 엽니다.
  3. </body> 바로 앞에 스니펫을 붙여 넣고 저장/반영합니다.
  4. PC 디자인과 모바일 디자인이 따로 있으면 양쪽 모두에 붙여 넣습니다.
💡 팁

스니펫은 콘솔에서 그대로 복사하세요. 손으로 고치다 /widget 경로가 빠지면 위젯 대신 콘솔 화면이 응답해(상태 코드는 200) 아무 오류 없이 위젯만 안 뜹니다.

⚠️

디자인을 새로 만들거나 대표 디자인을 바꾸면 새 디자인에는 스니펫이 없습니다. 디자인 교체 후에는 반드시 다시 붙여 넣으세요.

07

회원 로그인 · 내 주문

카페24에는 "지금 로그인한 회원이 누구인지" 위젯에 알려 주는 통로가 없습니다. 그래서 샵톡은 카페24의 고객 인증(회원 OAuth)을 이용해, 카페24가 직접 확인해 준 회원 아이디로 위젯 대화를 그 회원에게 묶습니다.

7.1 고객에게 보이는 흐름

  1. 위젯의 주문 탭에서 [로그인]을 누릅니다.
  2. 카페24 로그인(이미 로그인했다면 생략) → 몰의 동의 화면을 거칩니다.
  3. 위젯이 주문 탭으로 다시 열리고, 최근 30일 주문 최대 10건이 표시됩니다.
  4. 더 오래된 주문은 [더보기] → 몰의 마이페이지 주문 조회(/myshop/order/list.html)로 안내합니다.

7.2 운영자 설정

설정 > 위젯 설정 > 위젯 동작의 고객 로그인 열기 방식을 고릅니다.

방식동작언제
전체 페이지 이동 (권장)같은 탭에서 로그인 후 원래 페이지로 돌아와 위젯이 자동으로 다시 열림기본값 · 가장 안정적
팝업 창작은 창에서 로그인, 끝나면 창이 저절로 닫히고 페이지는 그대로장바구니 등 페이지 이동을 피하고 싶을 때
💡 팁

팝업이 브라우저에 차단되면 자동으로 전체 페이지 이동 방식으로 바뀌어 로그인은 그대로 진행됩니다.

7.3 보안 · 제약

  • 위젯에는 카페24 토큰이 전달되지 않습니다. 서버가 확인을 마친 뒤 1회용 티켓(60초)만 몰 페이지로 돌려주고, 위젯이 이를 대화 세션으로 교환합니다.
  • 로그인 후 돌아가는 주소는 **그 몰의 *.cafe24.com 주소로만** 허용됩니다.
  • ⚠️ 독자 도메인으로 접속한 고객은 회원 로그인을 쓸 수 없습니다. 위젯이 몰 ID를 알아낼 수 있는 주소가 yourmall.cafe24.com뿐이기 때문입니다. 독자 도메인 몰에서는 위젯 상담은 정상이지만 '내 주문'은 표시되지 않습니다.
  • 몰 하나가 두 테넌트에 연결된 상태라면 어느 테넌트로 로그인시킬지 정할 수 없어 로그인을 거부합니다(3장의 E5046이 이 상태를 막습니다).
08

작업 체크리스트

플랫폼 관리자 (배포당 1회)

  • 개발자센터 앱 생성, Redirect URI = 이 배포의 /api/v1/auth/cafe24/callback
  • 권한 4개: mall.read_order · mall.read_product · mall.read_category · mall.read_customer_identifier
  • env에 Client ID/Secret · Redirect URI · 콘솔 주소 · 권한 · 자동 동기화 주기 — 빈 줄 없음
  • API 재시작 후 부팅 로그에서 Cafe24 auto-sync 줄 확인

테넌트 master (몰마다)

  • 설정 > 기본 설정: 스토어 도메인 yourmall.cafe24.com, 상점 주소 https://yourmall.cafe24.com
  • 설정 > 플랫폼 연동: 몰 ID 입력 → [Cafe24 연결] → 「연결됨」 토스트
  • [지금 동기화] → 주문 메뉴에 카페24 주문 표시
  • [상품 가져오기] → 지식 > [카탈로그에서 동기화] → 미리보기 → [동기화 실행]
  • 설정 > 위젯 설정: 설치 가이드(Cafe24) 스니펫을 스마트디자인 PC·모바일 레이아웃 </body> 앞에 붙임
  • 몰에서 위젯이 뜨고, 상품 질문에 상품 링크가 붙은 답이 오는지
  • 테스트 회원으로 위젯 [로그인] → 주문 탭에 그 회원의 주문이 보이는지
09

FAQ / 문제 해결

Q. [Cafe24 연결]을 눌렀더니 바로 「Cafe24 연결 실패」가 뜹니다.
동의 화면으로 가기 전에 실패한 경우입니다. ① 몰 ID가 스토어 도메인의 몰과 다름(E5045) ② 그 몰이 다른 테넌트에 이미 연결됨(E5046) ③ 서버에 앱 값이 없음(E5010) 중 하나입니다. ①은 2장 설정을 확인하고, ②·③은 플랫폼 관리자에게 문의하세요.
Q. 동의까지 마쳤는데 콘솔로 돌아와 「Cafe24 연결 실패」가 뜹니다.
토큰 교환이 실패한 경우입니다. 가장 흔한 원인은 env의 CAFE24_REDIRECT_URI가 개발자센터에 등록한 주소와 다른 것입니다(끝의 /, http/https 포함). 동의 화면에서 10분 넘게 머물렀다면 처음부터 다시 하세요.
Q. 「요청 권한을 거부했습니다(invalid_scope)」가 뜹니다.
샵톡이 요청한 권한이 개발자센터 앱에 등록돼 있지 않습니다. 샵톡 쪽에서 고칠 것은 없고, 1.1절의 권한을 앱에 추가한 뒤 다시 연결하세요.
Q. [지금 동기화] 결과가 refusing to sync: tenant runs on A.cafe24.com but the stored credential is for "B"입니다.
저장된 연결이 이 테넌트의 몰이 아닙니다. 다른 상점 주문이 섞이지 않도록 동기화를 막은 상태입니다. 올바른 몰 ID로 [Cafe24 연결]을 다시 하세요. names two malls라고 나오면 스토어 도메인과 상점 주소가 서로 다른 몰을 가리키는 것이니 2장에서 맞추세요.
Q. 동기화 결과가 Cafe24 store is not connected — reconnect the mall입니다.
연결한 적이 없거나, 14일 넘게 쓰지 않아 갱신 토큰이 만료된 경우입니다(4.3절). [Cafe24 연결]을 다시 하세요.
Q. 상품을 가져왔는데 AI가 상품을 모릅니다.
[상품 가져오기]는 상품 목록만 채웁니다. 지식 > [카탈로그에서 동기화] → [동기화 실행]까지 해야 답변에 쓰입니다(5.2절).
Q. 지식 문서의 카테고리가 비어 있습니다.
mall.read_category 권한 없이 연결된 몰입니다. 앱에 권한을 추가하고(1.1절) [Cafe24 연결]로 재동의한 뒤, [상품 가져오기]와 카탈로그 동기화를 다시 실행하세요.
Q. 채팅의 상품 인용에 링크가 없습니다.
설정 > 기본 설정의 상점 주소가 비어 있거나 몰 주소와 다릅니다. https://yourmall.cafe24.com으로 저장하세요.
Q. 몰에 위젯이 안 뜹니다.
① 스니펫이 현재 대표 디자인의 레이아웃에 있는지(디자인 교체 시 사라짐) ② PC·모바일 디자인 양쪽에 있는지 ③ 스니펫의 shop이 설정 > 기본 설정의 스토어 도메인과 같은지 확인하세요. 브라우저 개발자도구 네트워크 탭에서 embed.js가 JavaScript로 내려오는지(HTML이면 주소 오류) 보면 빠릅니다.
Q. 회원이 로그인했는데 위젯이 계속 비로그인 상태입니다.
① 고객이 독자 도메인으로 접속 중이면 회원 로그인이 동작하지 않습니다(7.3절) ② 앱에 mall.read_customer_identifier 권한이 있는지 ③ 몰이 이 테넌트에만 연결돼 있는지 확인하세요. 실패해도 고객은 원래 페이지로 조용히 돌아가므로, 사유는 서버 로그의 Cafe24 customer-auth … failed / Cafe24 member sign-in callback failed 줄에서 확인합니다.
Q. 로그인은 되는데 '내 주문'이 비어 있습니다.
최근 30일 안에 그 회원 아이디로 주문한 내역이 없거나, 아직 동기화되지 않은 경우입니다. 로그인 직후 30일 범위 보충 동기화가 자동으로 돌지만, 주문 조회 권한(mall.read_order)이 없으면 실패합니다. 비회원 주문은 회원 아이디가 없어 표시되지 않습니다.
Q. 스테이징과 프로덕션에서 같은 개발자센터 앱을 써도 되나요?
안 됩니다. 카페24 앱은 Redirect URI를 하나만 받으므로 콜백 주소가 다른 두 배포를 동시에 지원할 수 없습니다. 배포마다 앱을 하나씩 만드세요.
