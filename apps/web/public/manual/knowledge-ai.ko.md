## 0. AI 응답 파이프라인 이해

고객 메시지 하나가 처리되는 전체 흐름입니다. 이 문서의 모든 설정은 이 흐름의 어딘가를
조정하는 일입니다.

```
고객 메시지
  │
  ▼
① 의도 분류 ──── 주문·개인정보가 필요하면 → 본인확인(로그인) 안내
  │               deny-list 매칭 시: 「답변 안 함」→ 즉시 인계 /
  │               「답변 후 인계」→ ②~④를 거쳐 답한 뒤 인계
  ▼
② 지식 검색(RAG) ── 등록된 지식 문서에서 관련 근거를 찾음
  │
  ▼
③ 답변 생성 ──── 페르소나·응답 규칙 + 검색 근거로 답변 작성, 신뢰도 산정
  │
  ▼
④ 모더레이션 ─── 금칙 규칙 검사 (통과 못 하면 고객에게 미노출)
  │
  ▼
⑤ 분기: 신뢰도 충분 → 고객에게 답변(+출처)
        신뢰도 낮음 / 차단 / 고객이 상담원 요청 → 상담원 대기열(에스컬레이션)
```

- **답변 언어**는 고객 세션 언어를 따릅니다 (en/es/ko/vi/ja/zh).
- 상담원이 보내는 메시지도 ④ 모더레이션을 똑같이 통과합니다 (우회 불가).

## 1. 지식 구조 이해

**용어**

| 용어 | 뜻 |
|---|---|
| 지식 문서(document) | AI가 답변 근거로 쓰는 글 1건. 제목·카테고리·본문으로 구성 |
| **지식 보드(board)** | 모든 지식이 **먼저 작성·검토되는 큐레이션 계층**(`/knowledge/board`). 게시된 문서를 KB로 "채택"하면 답변 근거가 됩니다 |
| KB 채택 | 보드 문서를 지식베이스(KB) 문서로 승격하는 것. 재채택하면 같은 문서가 갱신됩니다(중복 생성 없음) |
| 임베딩(embedding) | 문서를 검색 가능한 벡터로 변환하는 색인 작업. 등록·수정 시 자동 수행 |
| RAG | 질문과 관련된 문서를 검색해 그 근거로만 답변을 생성하는 방식 |
| 소스(source) | 문서를 외부에서 자동으로 가져오는 연결(게시판·Google Drive·Notion) |
| 그룹 | 문서 대분류 3종: **CounselInfo**(상담 — 정책·FAQ) / **ProductInfo**(상품 — 카탈로그 유래) / **OperationInfo**(운영 매뉴얼) |
| 카테고리 | 그룹 아래 세부 분류. **(그룹, 이름) 단위로 관리**되며, 에이전트 범위(§3.5)도 카테고리에 겁니다 |
| 활성/노출(active) | 검색 대상 포함 여부. **비활성 문서는 답변 근거로 쓰이지 않음** |
| 신뢰도(confidence) | 답변이 근거에 얼마나 뒷받침되는지의 수치. 낮으면 상담원 인계 |

지식 화면(`/knowledge`)의 배치: 상단에 지식 보드 배너와 **지식 갭 제안**, 왼쪽에
소스·사용법 가이드·카테고리·문서 관리, 오른쪽에 **지식으로 답변하기(QA 패널)**와
**지식 충돌 검토**가 고정되어 있어 등록↔검증을 한 화면에서 오갈 수 있습니다.
문서 목록 위 **그룹 탭**(전체 / CounselInfo / ProductInfo / OperationInfo)이 문서·
카테고리·일괄 도구의 작업 대상을 정합니다.

## 2. 지식 등록

### 2.0 표준 경로 — Smart Knowledge Board (권장)

모든 지식은 보드에서 먼저 작성·검토한 뒤 KB로 채택하는 것이 표준 경로입니다.
문서 카드의 **[보드에 작성]**이 기본 버튼이고, 지식베이스문서 추가는
**긴급 수정용**입니다.

**절차**: `/knowledge` 상단 배너 **[보드 열기]** 또는 문서 카드 **[보드에 작성]** →
1. 작성: `그룹`(CounselInfo/ProductInfo/OperationInfo) / `1차·2차 분류` / `작성팀` /
   `제목` / `태그` / 마크다운 본문 + 첨부(파일당 50MB, [본문에 삽입] 가능).
   본문에 `[[문서 제목]]`을 쓰면 다른 보드 문서와 연결됩니다(우측 *링크* 패널에서
   백링크 확인 — 링크는 **제목 기준**이라 제목을 바꾸면 기존 링크가 "미작성"으로 뜹니다).
2. **[임시 저장]**(작성중) → **[게시]**(게시됨) — 게시 전 문서는 채택할 수 없습니다.
3. **[시뮬레이션]**: 고객 질문을 넣어 이 문서가 인용되는지·확신도·유사도를 채택 전에
   확인합니다. **골든셋 A/B**는 등록된 검증 질문(§6.3)을 문서 미포함/포함으로 각각
   실행해 개선 폭을 보여줍니다(질문당 LLM 2회 호출 — 확인 후 실행).
4. **[KB 채택]**: 검토자가 카테고리를 정하면(미지정 시 2차→1차 분류 순) KB 문서가
   생성됩니다. **재채택은 같은 KB 문서를 갱신**하며 자동 재임베딩됩니다. 보드 원본을
   고친 뒤 재채택 전까지는 **"개정 미반영"** 배지가 붙습니다.
5. 협업: 우측 **코멘트**(입력 중 `@`로 팀원 멘션 — 보드 목록의 `@나` 수신함에 쌓임),
   **[보류]/[재채택]/[게시로 복귀]**로 상태를 되돌릴 수 있습니다.

**FAQ 일괄 이관**: 보드 목록의 **[FAQ 임포트]** — 기존 FAQ/Q&A 게시판을 CSV/XLSX로
내보내 업로드하면 행마다 게시 상태의 보드 문서가 됩니다(필수 컬럼 title·content,
선택 category1·category2·tags, 중복 제목은 건너뜀).

💡 **팁**
- 채택된 KB 문서를 KB 쪽에서 직접 고치면 보드 원본과 **분기**됩니다 — 문서 상세에
  경고와 [보드 원본 열기]가 표시됩니다. 개정은 보드에서 하고 재채택하세요.
- 시뮬레이션에서 "인용되지 않음"이면 제목·본문을 고객 어휘로 보강한 뒤 다시
  시뮬레이션 — 채택 후 QA 패널로 확인하는 것보다 한 단계 빠릅니다.

### 2.1 수동 문서 등록·편집 (긴급 수정용)

**절차**: 문서 카드 → **[지식베이스문서 추가]** → `그룹` 선택 / `제목` / `카테고리`
(선택한 그룹의 것만 자동완성) / `내용` 입력 → 저장.
제목을 클릭하면 상세 창이 열리고 **[편집]**에서 다음을 관리합니다:

| 필드 | 용도 |
|---|---|
| 원문 URL | 근거가 된 외부 문서 링크 (목록에서 바로 열기) |
| 적용 시작일 | 정책 발효일 |
| 검토 주기(일) | 지나면 목록에 `stale`(검토 필요) 배지 표시 → §3.3 |
| 내용 | 저장 시 **자동 재임베딩** (검색 색인 갱신) |

💡 **팁**
- 문서 1건 = 주제 1개. "배송+환불+교환"을 한 문서에 몰아넣기보다 나눠 등록해야
  검색이 정확해집니다.
- 제목·본문에 **고객의 실제 표현**("배송 얼마나 걸려요", "환불 언제 돼요")을
  포함하세요. 검색은 유사도 기반이라 고객 어휘와 가까울수록 적중합니다.
- 구버전 정책은 삭제 대신 **노출을 꺼서(비활성)** 근거에서 제외하세요.
  이력이 남고, 되돌리기 쉽습니다.
- 목록은 **제목 우선** 배치로 바뀌었습니다: 그룹(전체 탭에서만)·**출처 배지**(직접/
  보드/파일/YouTube/Drive/Notion/카탈로그)·카테고리·제목·수정일이 열이고, 노출 토글·
  상태·삭제 등 나머지는 행 끝 **⋯(더보기)** 메뉴에 있습니다. 노출/출처/상태 필터와
  정렬은 전부 서버 기준입니다. 상태가 "대기"인 문서도 **키워드 검색에는 이미 사용**
  됩니다 — 색인을 기다리는 것은 의미 검색뿐입니다.

### 2.2 상품 지식 — 카탈로그 동기화 · CSV · 사용 가이드

**용어**

| 용어 | 뜻 |
|---|---|
| 상품 캐시 | 플랫폼(Cafe24 등)에서 동기화한 원본 상품 목록 (설정 화면의 상품 동기화 결과) |
| 카탈로그 동기화 | 상품 캐시 → 상품 지식 문서로 변환하는 작업. **미리보기 → 실행** 2단계 |
| 변형 접기(병합) | "립스틱-레드/립스틱-핑크"처럼 대시로 구분된 변형을 대표 상품 1건으로 묶는 것 |
| 큐레이션 유지 | 운영자가 손으로 다듬은 상품 문서를 동기화가 덮어쓰지 않고 보존하는 것 |
| 사용 가이드 | 상품 **유형별** 공통 사용법 문서 (예: "립 제품 사용법") — 상품 문서와 별도로 답변 근거가 됨 |

**절차 ① 카탈로그 동기화**: 문서 카드 헤더 → **[카탈로그 동기화]**
1. **미리보기**가 먼저 실행됩니다 — 스캔 수와 예상 결과(생성 / 수정 / 큐레이션 유지 /
   병합 흡수 / 변경 없음 / 보류)와 임베딩 배치 예상치, 병합 샘플 목록이 표시됩니다.
2. 병합 샘플에서 **다른 상품이 하나로 묶이지 않았는지** 확인한 뒤 **[실행]**.
3. 진행률 2줄(작성 / 임베딩)을 지켜보고, 완료 후 결과 표에서 **임베딩 실패 건수**를
   확인합니다 (실패 건은 검색이 안 되므로 재실행 필요).

**절차 ② 상품 CSV 가져오기**: **[상품 가져오기(CSV)]** → 파일 선택 → 결과 통계
(파싱/생성/수정/건너뜀/무효/임베딩됨)와 행별 오류(최대 20건 표시)를 확인합니다.
같은 상품을 다시 올리면 덮어쓰기(업서트)됩니다.

**절차 ③ 사용 가이드**: *사용 가이드* 카드에 상품 유형별로 작성됨/미작성 배지가
보입니다. **[작성]** → 제목·본문(20자 이상) 저장.

💡 **팁**
- **반드시 미리보기부터 보세요.** 잘못된 병합(서로 다른 제품 라인이 묶임)은 실행 전
  미리보기에서만 잡을 수 있습니다.
- 플랫폼에서 상품이 바뀌면 [설정]의 상품 동기화 → [지식]의 카탈로그 동기화 **2단계를
  순서대로** 실행해야 지식에 반영됩니다.
- 상품 설명이 빈약한 상점은 태그가 지식의 재료가 됩니다 — 플랫폼 쪽 상품 태그를
  정리해두면 답변 품질이 올라갑니다.

### 2.3 외부 소스 연동 (게시판 · Google Drive · Notion)

**용어**

| 용어 | 뜻 |
|---|---|
| 서비스계정 | Google Drive 연동에 쓰는 로봇 계정. 이 계정 이메일에 폴더를 공유해야 읽을 수 있음 |
| 통합(integration) | Notion에서 외부 도구 접근을 허용하는 단위. 대상 페이지에 "연결" 필요 |
| 동기화 결과 카운트 | 생성·수정·건너뜀·숨김 건수. `dropped`/`truncated`는 **일부를 가져오지 못했다는 경고** |

**절차**
1. **자격증명 등록** (소스 표 아래 카드 2종):
   - Google Drive: 서비스계정 키 JSON 붙여넣기 → 표시되는 **서비스계정 이메일에 대상
     폴더를 공유** → [연결 테스트]
   - Notion: 토큰(`ntn_…`) 등록 → 노션에서 대상 페이지/DB에 **통합을 연결** → [연결 테스트]
2. **[소스 추가]** → 유형 선택(board / gdrive / notion) → gdrive는 `폴더 ID`,
   notion은 `페이지·DB ID 또는 공유 URL` 입력
3. 소스 행의 **↻(동기화)** 실행 → *마지막 동기화* 열에서 결과 카운트 확인

지원 유형: 게시판(board) ✅ · Google Drive ✅ · Notion ✅ · GitHub 리포지터리 소스는 **지원하지 않습니다**.

💡 **팁**
- 동기화 결과에 빨간 **dropped/truncated** 경고가 보이면 페이지가 너무 크거나 깊어
  일부가 잘린 것입니다. 해당 문서를 열어 끝부분이 온전한지 확인하고, 원본을 나눠서
  다시 동기화하세요. Notion 실패는 *마지막 동기화* 칸에 사유가 함께 표시됩니다 —
  "통합에 공유되지 않았습니다"가 보이면 노션에서 페이지 ⋯ → 연결(Connections)에
  통합을 추가하세요.
- 동기화가 갑자기 **0건**을 가져오면(폴더 공유 해제, 통합 연결 해제 등) 기존 문서를
  숨기지 않고 그대로 둡니다 — 연결부터 복구하세요.
- 소스의 상태 셀을 클릭하면 활성↔비활성 토글됩니다. 비활성 소스는 동기화만 멈출 뿐
  이미 가져온 문서는 남습니다.
- 소스 이름 옆 아이콘의 **[전환 내역 보기]**: 동기화 실행 이력(성공/실패·생성/갱신/
  유지/숨김·색인·소요·사유)과 이 소스에서 전환된 문서 목록을 봅니다.
- **소스 삭제**는 안전합니다 — 소스만 지워지고, 그 소스의 문서는 삭제되지 않고
  **비활성화**되어 검색에서 빠집니다(문서 목록에서 다시 활성화 가능).

### 2.4 일괄 다운로드 ↔ 일괄등록 (CSV/XLSX 라운드트립)

문서 카드의 **[일괄 다운로드 ▾]**(CSV/Excel)와 **[일괄등록]**은 같은 컬럼 계약을
씁니다: `category · title · content`(필수) + `external_key · source_url`(선택).
**두 버튼은 그룹 탭을 선택해야 나타납니다**(전체 탭에서는 숨김 — 대상 그룹이
정해져야 하므로).

**절차**: 그룹 탭 선택 → [일괄 다운로드]로 현재 문서를 내려받아 수정 →
[일괄등록]으로 재업로드. 같은 `external_key`(없으면 **트림된 같은 제목**)의 행은
중복 생성 없이 기존 문서를 갱신하고, 바뀌지 않은 행은 무시됩니다.
결과 토스트: 생성·갱신·건너뜀 건수.

- 최대 5,000행 / 5MB. CSV는 **UTF-8만** 지원 — 한국어 엑셀은 "CSV UTF-8"로
  저장하거나 `.xlsx`를 그대로 올리세요.
- CounselInfo 탭에는 **범용 상담가이드**(바로 쓰는 기본 상담 KB) 다운로드 블록이
  있습니다 — 내려받아 기한·비용을 상점 정책에 맞게 고친 뒤 업로드하면 초기 지식이
  한 번에 채워집니다.
- 외부 소스(카탈로그·보드·노션·드라이브)에서 온 문서도 수정할 수 있지만 **다음
  동기화 때 덮어써질 수 있습니다** — 원본 쪽을 고치는 것이 원칙입니다.

### 2.5 AI 임포트 (파일·YouTube → 초안 → 보드)

**[AI 임포트]** — 파일(pdf·docx·xlsx·csv·md, 최대 15MB) 또는 공개 자막이 있는
YouTube URL을 올리면 AI가 내용을 **아티클 단위 초안**으로 분할합니다.

**절차**: 그룹 선택(상담매뉴얼/상품추천용/운영매뉴얼) → 파일 업로드 또는 영상 URL →
**[분석 시작]**(백그라운드 작업 — 화면을 떠나도 됩니다) → 초안 검토(선택·제목·카테고리
편집, "검수 필요" 배지 확인) → **[선택 N건 저장]**.

⚠️ 저장된 초안은 KB가 아니라 **보드에 게시**됩니다 — 보드에서 검토 후 KB로
채택하세요(§2.0). 스캔 PDF처럼 텍스트 층이 없는 파일, 자막 없는 영상은 분석할 수
없습니다.

## 3. 지식 검증·품질 관리

**용어**

| 용어 | 뜻 |
|---|---|
| 지식 QA 패널 | 고객 입장에서 지식에 질문해보는 테스트 패널 (오른쪽 고정) |
| 출처(citation) | 답변의 근거가 된 문서 목록. 유사도 수치와 함께 표시 |
| 충돌(conflict) | 두 문서가 **서로 모순된 내용**을 담고 있다고 탐지된 상태 |
| stale | 검토 주기가 지나 재확인이 필요한 문서 배지 |
| 지식 공백(gap) | 고객이 물었지만 지식에 답이 없던 주제 — 시스템이 문서 초안으로 제안 |
| 답변 제안(proposal) | 상담원의 실제 답변을 지식 문서로 승격하자는 제안 (사람 승인 필수) |
| 리비전(revision) | 문서의 변경 이력 스냅숏. diff 보기와 복원 지원 |

### 3.1 지식 QA 패널 — 등록 후 반드시 확인

**절차**: 에이전트 선택(**전체 (운영자 보기)** 또는 특정 에이전트 — 에이전트 범위
§3.5를 적용한 실제 시야로 테스트) → 질문 입력 → 답변 + **신뢰도 수치** + **출처
목록**(문서별 유사도) 확인 → 근거 문서가 틀렸으면 출처 옆 **[수정]**(해당 문서가
바로 편집 모드로 열림) → 고친 뒤 **[다시 질문]**으로 재확인.

💡 **팁**
- 답변에 **모더레이션 차단** 배지가 뜨면 금칙 규칙(§4.5)에 걸린 것입니다 — 실제
  고객에게라면 노출되지 않았을 답변입니다.
- 출처에 `conflicted`/`stale` 배지가 붙으면 그 문서부터 정리하세요. 신뢰도가 낮게
  나오는 주제는 문서가 없거나 고객 어휘와 동떨어진 경우가 대부분입니다.
- 정책을 바꿀 때마다 "고객이 물을 법한 질문 3개"를 QA 패널에 던져보는 습관이 가장
  저렴한 회귀 테스트입니다 (자동화는 §6.3 골든 질문).

### 3.2 충돌 검토

**절차**: 오른쪽 *지식 충돌 검토* 패널 → 항목별로 판정(**상충/중복/보완 관계**)과
두 문서의 유사도·판정 근거 확인 → 액션 선택:

| 액션 | 동작 |
|---|---|
| A 채택 · B 숨김 / B 채택 · A 숨김 | 선택한 쪽을 남기고 반대쪽을 비활성화 |
| 둘 다 유지 | 모순이 아니라고 판단 — 둘 다 활성 유지 |
| 충돌 아님 | 이 충돌 건을 닫음 |
| 이 쌍 재판정 | 문서를 고친 뒤 다시 판정 요청(판정 실패 건도 여기서 재시도) |

**[충돌 재탐지]**로 전체 문서를 다시 검사할 수 있습니다.

💡 **팁**: 충돌은 대개 **정책 개정 시 구버전을 안 내려서** 생깁니다. "A 유지"로 끝내지
말고, 남긴 문서에 개정일(적용 시작일)을 기록해 다음 개정 때 같은 일이 반복되지 않게
하세요.

### 3.3 검토 주기·stale 관리 / 변경 이력

- 문서 편집에서 `검토 주기(일)`를 설정하면 기한 경과 시 목록에 `stale` 배지가 붙습니다.
  문서 상세의 검토 상태 박스에서 **[검토 완료 표시]**를 누르면 기한이 다시 계산됩니다.
- 상세 창의 **변경이력 탭**에서 리비전별 diff를 보고 **[복원]**할 수 있습니다.

💡 **팁**: 배송비·프로모션처럼 자주 바뀌는 문서는 검토 주기를 30일 안팎으로 짧게,
법적 고지처럼 안정적인 문서는 길게 두면 stale 배지가 실질적인 할 일 목록이 됩니다.

### 3.4 지식 갭 제안 · 확정 지식 제안 (폐루프)

- **지식 갭 제안**(화면 상단, 건수가 있을 때만 표시): 에스컬레이션 다발 주제·근거
  문서 없는 인텐트·상담원 해결 답변이 지식베이스 후보로 쌓입니다. **[KB 문서로
  승인]**(제목·내용 편집 후 문서 생성) 또는 **[기각]** — 자동 반영은 없습니다.
- **확정 지식 제안**(대기 건이 있을 때 표시): 상담원의 실제 답변을 지식으로 올리자는
  제안. 질문·답변·출처 대화 링크를 확인하고 **[승인]** 또는 **[거절]**(사유는
  제안자에게 표시됩니다).

💡 **팁**: 이 두 개가 지식이 스스로 자라는 통로입니다. 주 1회 비우는 루틴을 만들면
"AI가 자꾸 상담원에게 넘겨요"의 근본 원인이 줄어듭니다. 승인 전 **개인정보(주문번호·
이름)가 답변에 남아 있지 않은지** 반드시 확인하세요 — 지식 문서는 모든 고객 답변의
근거로 재사용됩니다.

### 3.5 카테고리 에이전트 범위 (에이전트별 지식)

*카테고리* 카드의 각 행에 현재 범위가 버튼으로 표시됩니다 — **"모든 에이전트"**(기본,
빈 범위 = 전체 공개) 또는 **"에이전트 n/전체"**.

**절차**: 버튼 클릭 → **모든 에이전트(기본)** / **선택한 에이전트만** 중 선택 →
저장. 범위를 좁히면 그 카테고리의 문서는 선택된 에이전트만 인용할 수 있습니다
(답변 재사용도 같은 범위를 따릅니다).

💡 **팁**
- ⚠️ **나중에 만드는 에이전트는 좁혀진 카테고리를 보지 못합니다** — 새 에이전트를
  추가하면 범위를 다시 확인하세요.
- 카탈로그에서 생성된 카테고리(브랜드)는 항상 모든 에이전트가 사용하며 범위를 걸 수
  없습니다.
- QA 패널의 에이전트 선택(§3.1)으로 "이 에이전트가 실제로 무엇을 보는지" 확인하는
  것이 가장 확실한 검증입니다.

## 4. AI 설정
*(좌측 메뉴 **[AI 설정]** — 접근 권한: master/director)*

**용어**

| 용어 | 뜻 |
|---|---|
| AI 에이전트 | 페르소나·규칙 세트를 가진 상담봇 단위. 여러 개를 만들어 채널·페이지별로 다른 봇 운영 가능 |
| 기본 에이전트 | 별도 지정이 없는 위젯이 사용하는 에이전트 (항상 활성) |
| 진입점 스니펫 | 특정 에이전트로 위젯을 띄우는 설치 코드 조각 |
| 페르소나 / 응답 규칙 | 봇의 말투·원칙 서술 / 반드시 지킬 규칙 목록 (§0 파이프라인 ③에 주입) |
| 시나리오 버튼 | 위젯 하단 빠른 메뉴 버튼. 액션 7종 중 선택, **라벨은 언어별** 관리 |
| 기본 대화내용 | 샵톡이 기본 제공하는 **내장 스크립트 7종**의 응답 문구·후속 칩 편집 (§4.7) |
| AI 기능(function) | AI가 쓰이는 자리 5곳 (chat/rag/summary/assist/moderation) — 자리마다 엔진 지정 |
| 모더레이션 규칙 | 발신 메시지를 검사하는 금칙 규칙 (§0 파이프라인 ④) |
| 답변 재사용 | 승인된 과거 답변을 같은 질문에 LLM 호출 없이 재생하는 기능 |
| 변경 메모 | 페르소나·규칙 저장 시 남기는 한 줄 기록 — 설정 변경 이력에서 조회 |

### 4.1 AI 에이전트 (멀티 페르소나)

**절차**: *AI 에이전트* 카드에서 에이전트를 선택하면 아래 페르소나·응답 규칙 카드가
**그 에이전트의 것**으로 바뀝니다. **[추가]**로 이름·코드(소문자)를 정해 새 에이전트를
만들고, **[기본으로 지정]** / 활성 토글 / **[삭제]**를 관리합니다. 각 에이전트의
**진입점 스니펫**을 복사해 특정 페이지·채널에 설치하면 그 봇이 응대합니다.

에이전트 편집에서 고객 대면 정체성 2가지를 별도로 정합니다:
- **위젯 표시명** — 위젯 헤더에 표시(비우면 상점 표시명).
- **첫 응답 메시지** — 언어 탭별 작성. 이 에이전트가 배정된 세션의 첫 말풍선이며,
  비운 언어는 상점 공통 첫 메시지를 씁니다.

에이전트 카드 바로 아래 **"{에이전트}에 적용되는 설정"** 카드는 인사말·페르소나·
응답 규칙·노출 버튼이 **실제로 어떤 값으로 적용되는지**(기본값 폴백 포함) 읽기
전용으로 요약합니다 — 수정은 각 섹션에서 합니다.

💡 **팁**
- 에이전트는 **세션 시작 시 1회 배정**됩니다 — 대화 중간에 스니펫을 바꿔도 진행 중
  세션의 봇은 바뀌지 않습니다.
- 존재하지 않는 코드로 진입하면 기본 에이전트로 폴백하므로 위젯이 죽는 일은 없습니다.
- 여기의 "AI 에이전트"는 상담원(사람) 계정과 무관합니다. 사람 계정은 [사용자] 메뉴입니다.

### 4.2 페르소나·응답 규칙

**절차**: 페르소나 텍스트 작성 → **변경 메모** 입력 → 저장. 응답 규칙은 [규칙 추가]로
한 줄씩 (빈 줄은 저장 시 제거).

💡 **팁**
- 페르소나에는 정체성·톤("친절, 간결, 존댓말"), 규칙에는 **행동 제약**("환불 완료를
  단정하지 말 것")을 나누어 담으면 관리가 쉽습니다. 사실 정보(배송비 등)는 여기가
  아니라 **지식 문서**에 넣으세요 — 페르소나는 검색되지 않습니다.
- 저장 후 반영은 캐시 때문에 최대 60초 걸릴 수 있습니다.
- *설정 변경 이력* 카드에서 과거 리비전을 열어 **[에디터로 불러오기]** 할 수 있는데,
  불러온 것만으로는 적용되지 않습니다 — **저장까지 해야** 반영됩니다.

### 4.3 시나리오 버튼

**절차**: 상단 **라벨 언어** 탭(6개 언어)을 고른 뒤, 행마다 `라벨`(최대 60자) /
`동작` / `사용` 체크 / 순서(↑↓) / **[에이전트]**(이 버튼을 노출할 에이전트 —
모든 에이전트 공통 또는 선택한 에이전트만)를 편집합니다.
- **라벨은 언어별**입니다: 지금 선택한 언어 탭에만 적용되고 나머지 언어는 유지됩니다.
  기본 버튼 6종(배송 조회·취소/환불·제품 도움말·고객 지원 문의·제휴·내 주문)은
  6개 언어 라벨이 기본 제공됩니다.
- 라벨 아래 힌트가 버튼이 실제로 실행하는 **내장 스크립트**를 알려줍니다 —
  "내장 스크립트 없음"이면 라벨이 채팅 메시지로 전송되어 AI가 답합니다.
  스크립트 문구 편집은 §4.7 기본 대화내용에서 합니다.

동작 7종:

| 동작 | 위젯에서의 실제 동작 |
|---|---|
| 배송 조회 | 배송 정책 고정 답변 + 후속 버튼 |
| 취소/환불 | 취소·환불·반품 고정 답변 + 후속 버튼 |
| 상품 도움말 | 서브메뉴(사용법·성분·재입고 등) |
| 고객 지원 문의 | 연락처 남기기 폼 — 상담원 연결 경로 |
| 내 주문 | 본인확인 후 주문 탭으로 이동 |
| 제휴 | 제휴 안내 카드 |
| 메시지 보내기 | **라벨 문구를 그대로 질문으로 전송** → AI가 지식 기반 답변 |

**[답변 편집]**을 누르면 액션별 응답 문구를 **6개 언어 탭**으로 편집하고, 후속
칩(라벨·동작·URL)을 구성할 수 있습니다. 기본 제공 문구가 **필드에 채워진 채** 열리며 —
고치면 덮어쓰고, 그대로 두면 저장되지 않습니다. **[기본값으로 되돌리기]**로 언제든
초기화할 수 있습니다.

💡 **팁**
- 자주 묻는 질문을 버튼으로 만들려면 **메시지 보내기** 액션에 라벨을 질문 문장으로
  쓰세요 (예: "무료배송 기준이 뭐예요?").
- 버튼을 지우기보다 `사용` 해제로 숨기면 재활성화가 쉽습니다. **고객 지원 문의**는
  항상 켜두는 것을 권장합니다 — 고객이 상담원을 못 찾으면 이탈합니다.
- 고정 답변 문구와 지식 문서의 정책 내용이 **어긋나지 않게** 정책 개정 시 함께
  갱신하세요.

### 4.4 AI 기능 (엔진·파라미터)

**절차**: 기능별 행에서 적용 엔진 선택, `temperature`(0~1)·`max_tokens` 입력 후 개별
저장. 미지정 기능에는 `상속/기본/stub` 배지와 실제 적용 엔진명이 표시됩니다.

기능 5종의 쓰임새:

| 기능 | 실제 용도 |
|---|---|
| chat | 고객 메시지의 의도 분류 등 대화 제어 |
| rag | **지식 기반 답변 생성 — 고객이 보는 답변의 본체** |
| summary | 대화 요약 (이력·인계 브리핑) |
| assist | 상담원 콘솔의 AI 보조 |
| moderation | 문맥(context) 금칙 규칙의 LLM 판정 |

**폴백 사슬**: 선택 엔진 사용 불가 → 테넌트 기본 → 플랫폼 기본 → **stub**(데모 응답)
순으로 자동 강등되어 대화가 끊기지는 않습니다.

💡 **팁**
- **max_tokens**는 답변 길이 상한입니다 — 챗 답변은 512~1024면 충분합니다.
- ⚠️ **temperature는 Anthropic(Claude) 엔진에는 적용되지 않습니다.** 현행 Claude
  모델이 샘플링 파라미터를 거부하므로 시스템이 의도적으로 전송하지 않습니다. 입력해도
  무시되며, OpenAI 계열 엔진에만 적용됩니다.
- `stub` 배지가 남아 있으면 실서비스 품질이 아닙니다. 엔진은 두 곳에서 옵니다:
  **테넌트 자체 엔진**([테넌트 설정 → 기본 설정]의 *AI 엔진* 카드 — 내 API 키로
  등록, 플랫폼 엔진보다 우선, 비용은 우리 계정으로 청구)과 플랫폼 제공 엔진
  (플랫폼 관리자가 `/admin/ai-engines`에서 등록). 실제 사용량은 같은 탭의
  *AI 사용량* 카드에서 확인합니다(stub 폴백 횟수 경고 포함).
- 지식 검색용 임베딩 모델은 이 화면에 없습니다 — 전 테넌트 공용으로 서버에서
  관리합니다.

### 4.5 모더레이션(금칙) 규칙

**절차**: **[규칙 추가]** → 유형/범위/조치 선택:

| 항목 | 선택지 | 의미 |
|---|---|---|
| 유형 | 단어 / 문구 | 포함 매칭 (대소문자 무시) |
| | 정규식 | 패턴 매칭 (예: `\b수술\b`) |
| | 문맥(LLM) | "무엇을 차단할지"를 문장으로 쓰면 AI가 메시지마다 판정 |
| 범위 | AI만 / 상담원만 / 둘 다 | 어느 발신자의 메시지를 검사할지 |
| 조치 | 차단 | 메시지를 내보내지 않음 (AI 답변이면 상담원 인계로 전환) |
| | 마스킹 | 걸린 부분만 ▇▇▇ 처리 후 전달 |
| | 재작성 | AI가 안전한 문장으로 고쳐서 전달 |

💡 **팁**
- 이 게이트는 **끌 수 없으며**, 검사 자체가 실패하면 안전을 위해 **차단**으로
  처리됩니다. 상담원 메시지가 전송 거부되면(차단 안내) 표현을 바꿔 다시 보내세요.
- 문맥(LLM) 유형은 moderation 기능 엔진을 사용합니다 — stub 상태면 판정 품질이
  없으니 실엔진 연결 후 사용하세요.
- 과도한 단어 규칙은 정상 답변까지 막습니다. 먼저 **마스킹/재작성**으로 시작해
  로그를 보고 차단으로 올리는 순서를 권장합니다. 규칙 반영은 최대 60초입니다.

### 4.6 답변 재사용

**절차**: *답변 재사용* 카드에서 저장된 질답을 검색(활성만 필터), 항목별 편집/삭제,
**[전체 비활성화]**(확인 후)로 일괄 중지할 수 있습니다.

💡 **팁**: 재사용 답변은 같은 질문에 LLM 호출 없이 즉시 나가므로 빠르고 저렴하지만,
**정책이 바뀌면 낡은 답변이 그대로 나갈 수 있습니다.** 정책 개정 시 관련 항목을
검색해 수정하거나 비활성화하는 것을 개정 체크리스트에 포함하세요. 재사용 답변도
모더레이션은 통과하며, 카테고리 에이전트 범위(§3.5)도 따릅니다.

### 4.7 기본 대화내용 (내장 스크립트 7종)

*기본 대화내용* 카드는 샵톡이 기본 제공하는 **모든 내장 스크립트**를 보여줍니다 —
시나리오 버튼으로 실행되는 것뿐 아니라 **후속 칩으로만 도달하는 것까지** 포함해
7종입니다(취소/환불 · 주문 취소 · 환불 정책 · 반품/교환 · 배송 정책 · 주문 도움 ·
상품 일반 도움).

**절차**: 스크립트 행의 **[보기·편집]** → 언어 선택 → `고객 발화`(버튼을 누르면
고객이 입력한 것처럼 표시되는 문장) / `응답 문구` / `후속 칩` / `답변 후 이동`
(채팅 유지·내 주문 열기·문의 폼 열기·제휴 카드 열기·상담원 연결·URL 열기) 편집 →
저장.

💡 **팁**
- 각 행의 배지가 도달 경로를 알려줍니다: **"메뉴 버튼 · {동작}"**(시나리오 버튼으로
  실행) vs **"후속 칩 전용"**. 수정된 언어 수("n개 언어 수정됨")도 표시됩니다.
- 기본 문구가 필드에 채워진 채 열립니다 — 그대로 두면 저장되지 않고, 고치면
  덮어씁니다. **[기본값으로 되돌리기]**로 초기화.
- 고정 답변 문구와 지식 문서의 정책이 **어긋나지 않게** 정책 개정 시 함께 갱신하세요
  (§7 체크리스트).

## 5. 라이브챗 고객 대응 설정
*(**[테넌트 설정] → 상담원 연결** 탭 — 2026-10-24 기본 설정 탭에서 분리됨)*

**용어**

| 용어 | 뜻 |
|---|---|
| 에스컬레이션(인계) | AI가 대화를 상담원 대기열로 넘기는 것 |
| 핸드오프(상담 전환) | 인계 이후의 배정·시간·안내를 정하는 설정 묶음 |
| 영업시간 | 상담원이 응대하는 시간대. 밖이면 영업외 안내·이메일 접수로 전환 |
| SLA | 응답 목표 시간. 라이브챗 콘솔에서 지연 정도를 판단하는 기준 |
| 대기열(waiting) | 인계된 대화가 상담원 인수를 기다리는 상태 |

### 5.1 담당자·영업시간·영업외 안내

**절차**: *상담원 연결* 탭에서
1. **담당자 지정** — 인계를 받을 상담원 체크 (비우면 모든 상담원에게 알리고 먼저
   수락한 담당자가 응대)
2. **근무시간에만 상담원에게 연결** 토글 → 타임존·시작/종료 시각·요일, 필요 시
   **휴게시간** 토글(휴게시간 문의는 오프아워와 동일 처리)
3. **근무시간 외 전달 이메일** — 영업시간 밖 문의를 받을 주소 (SMTP 미설정 시 경고 표시)
4. **근무시간 외 고객 안내 문구** — 언어 탭별 작성(비우면 기본 문구)
5. **이슈 보드 SLA 목표시간** — 일반/긴급(시간, 1~168h, 기본 24h/4h) — 보드의 ⚠️/🔥
   지연 배지 기준
6. **정책 강제 핸드오프(deny-list)** — 키워드(쉼표 구분) + 문의 유형 + 담당 라벨 +
   **고객에게 보이는 방식** 규칙 등록. 방식 2종: **답변 안 함**(답하지 않고 즉시
   인계, 기본) / **답변 후 인계**(지식베이스로 먼저 답하고 그대로 인계) — 어느
   쪽이든 상담원은 호출되고, 생성되는 이슈에 유형·라벨이 자동 지정됩니다

💡 **팁**
- 영업시간의 **타임존**을 상점 기준으로 정확히 맞추세요 — 미국 상점을 한국 시간으로
  두면 안내가 반대로 나갑니다.
- 영업외 이메일 접수를 쓰려면 서버 SMTP 설정이 선행되어야 합니다. 경고가 보이면
  플랫폼 관리자에게 요청하세요.
- 담당자를 아무도 지정하지 않으면 인계 대화가 공용 대기열에만 쌓입니다. 최소 1명은
  지정해 두세요.

### 5.1a 상담카테고리·배정 규칙

1. **[상담카테고리 관리]**에서 고객이 고를 상담 주제(예: 예약·결제)를 만들고 **노출함**으로
   둡니다. 필요하면 ▸ *언어별 이름*에 vi/en 이름을 넣습니다.
2. **배정 규칙**을 위에서부터 씁니다. 규칙 = 상담카테고리 + 업무(키워드) + 고객 정보(권역·성·
   언어 등) → 담당자(팀 × 라벨 그룹 또는 개인). 조건이 모두 맞는 **첫 규칙**이 연결됩니다.
3. 규칙 위 **배정 확인**에 상담카테고리·권역 등을 넣어, 저장 전에 누구에게 가는지 확인하고
   **저장**합니다.

⚠️ 주의
- *업무* 줄의 라벨 칩은 정책 강제 핸드오프로 넘어온 대화에만 맞습니다. 상담원 그룹 라벨은
  *담당자*에서 고르세요(편집기에 경고가 뜹니다).
- 초대를 수락하지 않은 상담원은 배정되지 않습니다. 그룹에 활성 상담원이 0명이면 그 규칙은
  건너뜁니다.
- 고객이 상담카테고리를 고르지 않으면 상담카테고리를 비운 규칙만 맞습니다. 맨 아래에
  조건 없는 기본 규칙을 두면 안전합니다.

### 5.2 인계(에스컬레이션) 조건 이해

AI가 상담원에게 넘기는 경우:

| 트리거 | 동작 |
|---|---|
| **신뢰도 낮음** | 답변에 "상담원 연결을 도와드릴까요?"를 덧붙이고 대기열로 |
| **모더레이션 차단** | AI 답변 미노출, 상담원 연결 안내 후 대기열로 |
| **고객 요청** | 시나리오의 *고객 지원 문의* 또는 명시적 요청 → 즉시 대기열로 (노출된 상담카테고리가 있으면 위젯이 먼저 상담카테고리를 묻고 그 규칙으로 연결) |
| **정책 강제 핸드오프(deny-list)** | 「답변 안 함」 규칙: **AI 응답 없이 즉시** 대기열로. 「답변 후 인계」 규칙: 지식으로 먼저 답한 뒤 대기열로. 메시지는 정상 저장·표시되며, 이슈에 유형·라벨이 스탬프됨 (메시지를 막는 기능이 아님) |

💡 **팁**
- 신뢰도 임계값은 화면에서 조정할 수 없습니다(코드 정책) — 인계가 잦다면 임계값이
  아니라 **지식을 보강**하는 것이 올바른 대응입니다 (§3.1 QA 패널로 원인 확인).
- 인계된 대화의 처리(인수·AI 브리핑·종료·재배정)는 라이브챗 콘솔(`/live-chat`)에서
  합니다 — 통합 매뉴얼의 라이브챗 장 참조.

## 6. 검증·개선 루프
*(**[AI 설정]** 오른쪽 스튜디오 + 회귀 테스트 카드)*

**용어**

| 용어 | 뜻 |
|---|---|
| 미리보기 | 실제 고객 세션을 만들지 않고 봇과 대화해보는 테스트 패널 |
| AI 코칭 | 자연어로 "이렇게 답하게 해줘"라고 피드백하면 설정 변경안을 **제안**받고, 승인 시에만 적용되는 기능 |
| 제안(proposal) | 코칭이 만든 설정 변경안 카드. 적용/거절/되돌리기 가능 |
| 골든 질문 | 답변 품질을 계속 확인하고 싶은 대표 질문 목록 (회귀 테스트 입력) |
| 회귀 테스트 | 설정·지식 변경 후 골든 질문 전체를 다시 돌려 답변이 나빠지지 않았는지 확인 |
| 변동성 측정 | 같은 질문을 반복 실행해 답변이 얼마나 흔들리는지 보는 기능 |

### 6.1 미리보기

**절차**: 스튜디오의 **미리보기** 탭 → 언어 선택 → **[새 세션]** → 모드(고객/상담원)
선택 후 메시지 입력. 응답에는 담당 **에이전트 배지**와 **에스컬레이션 여부**가
표시됩니다. 각 응답의 **[이 답변 코칭]**을 누르면 그 대화 턴을 코칭에 첨부합니다.

💡 **팁**: 설정을 바꿨으면 저장 후 **[새 세션]**으로 시작해야 새 설정이 적용된
대화를 보게 됩니다. 언어를 바꿔가며 주요 질문을 확인하세요 — 답변 언어는 세션
언어를 따릅니다. 미리보기 세션은 **대시보드·통계의 대화 수에 집계되지 않습니다** —
마음껏 테스트하세요.

### 6.2 AI 코칭

**절차**: **AI 코칭** 탭 → 스레드 선택 또는 [새 스레드] → 미리보기에서 첨부한 참조
턴을 확인하고 자연어로 지시 (예: "환불 안내가 너무 길어. 3문장 이내로") → 생성된
**제안 카드**에서 변경 내용을 검토 → **[적용]** / **[거절]** / 적용 후 **[되돌리기]**.

💡 **팁**
- 코칭은 **승인 없이는 아무것도 바꾸지 않습니다.** 제안 카드의 실제 변경 내용
  (페르소나·규칙 diff)을 읽고 적용하세요.
- "배송비는 5만원 이상 무료" 같은 **사실 정보**는 코칭이 아니라 지식 문서에 넣을
  일입니다 — 코칭은 말투·행동 규칙을 다듬는 도구입니다.
- 문구가 조금 달라지는 것은 정상 변동입니다. **신뢰도 하락·에스컬레이션 증가**가
  진짜 이상 신호입니다.

### 6.3 회귀 검증 (골든 질문)

**절차**: *회귀 검증* 카드 → 골든 질문 등록(대표 질문 10~20개) → **[지금 실행]**
→ 최근 실행 목록에서 **[이전과 비교]**로 답변 변화를 나란히 확인. **[변동성 측정]**
으로 같은 질문의 답변 흔들림을 볼 수 있습니다. 여기 등록한 질문은 지식 보드의
**시뮬레이션 골든셋 A/B**(§2.0)에도 재사용됩니다 — 문서 채택 전 개선 폭을 재는
기준이 됩니다.

💡 **팁**
- 골든 질문에는 ① 매출에 직결되는 질문(배송·환불) ② 과거에 오답이 났던 질문
  ③ 정책 개정 대상 질문을 넣으세요.
- **대량 지식 변경·카탈로그 동기화·페르소나 개정 직후**에 한 번씩 돌리는 것을
  운영 루틴으로 삼으세요. 실행 결과의 `truncated` 배지는 질문 수가 실행 상한을
  넘어 일부만 실행됐다는 뜻입니다.

## 8. FAQ / 문제 해결

**Q. 문서를 등록했는데 AI가 그 내용을 모릅니다.**
① 보드에만 게시하고 **KB 채택을 안 했는지**(보드 문서는 채택 전에는 답변 근거가
아닙니다) ② 문서가 활성(노출 ON)인지 ③ 카테고리에 **에이전트 범위**가 걸려 지금
에이전트가 못 보는지(§3.5 — QA 패널에서 해당 에이전트로 확인) ④ QA 패널의 출처
목록에 그 문서가 뜨는지 확인하세요. 안 뜨면 제목·본문을 고객 어휘로 보강하세요.
카탈로그 동기화 결과에 임베딩 실패가 있었는지도 확인하세요.

**Q. AI 임포트를 했는데 문서 목록에 없습니다.**
AI 임포트 초안은 KB가 아니라 **보드에 게시**됩니다. 보드에서 검토 후 [KB 채택]을
해야 문서 목록·답변 근거에 나타납니다(§2.5).

**Q. AI가 자꾸 상담원으로 넘깁니다.**
QA 패널에서 해당 질문의 신뢰도·출처를 확인하세요. 근거 문서가 없으면 등록이 답이고,
있는데 신뢰도가 낮으면 문서를 쪼개고 어휘를 보강하세요.

**Q. 상담원 메시지 전송이 거부됩니다.**
모더레이션 차단입니다. 금칙 규칙(§4.5)에 걸린 표현을 바꿔 다시 보내세요. 규칙이
과하면 master에게 조치 완화(차단→마스킹)를 요청하세요.

**Q. 답변이 영어로만 나옵니다.**
답변 언어는 **고객 세션 언어**를 따릅니다. 미리보기에서 언어를 지정해 확인하세요.
페르소나를 한국어로 쓰는 것과 답변 언어는 무관합니다.

**Q. Google Drive/Notion 동기화가 0건입니다.**
폴더 공유(서비스계정 이메일) 또는 노션 통합 연결이 끊긴 경우가 대부분입니다.
자격증명 카드의 [연결 테스트]부터 다시 하세요.

**Q. 코칭 제안을 적용했더니 답변이 이상해졌습니다.**
해당 제안 카드의 **[되돌리기]**로 복구하고, *설정 변경 이력*에서 이전 리비전을
에디터로 불러와 저장하는 방법도 있습니다.

**Q. 같은 질문인데 답변이 매번 조금씩 다릅니다.**
LLM의 정상 변동입니다 (변동 폭은 §6.3 [변동성 측정]으로 확인). 문구가 아니라
**내용**이 달라지면 지식 충돌(§3.2)을 의심하세요. 참고로 temperature 조정은
Anthropic 엔진에는 적용되지 않습니다(§4.4).
