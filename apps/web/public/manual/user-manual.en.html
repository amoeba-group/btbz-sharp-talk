Getting Started

1.1 Accessing the console

  • Tenant console: https://shoptalk.amoeba.site/user/<slug> — a store-specific login address
  • Platform administrators: /admin/login
  • Invited accounts sign in first with a temporary password, then go through a forced change (10+ characters·3 character classes·no common passwords)
  • master/director·system administrators are required to enroll MFA (TOTP) — at enrollment the 10 recovery codes are shown only once

Full onboarding procedure: Quick Setup Manual, Ch. 1–2.

1.2 Roles & permissions (RBAC)

  • Ranks: master · director · manager · staff / duty labels: consult · accounting · operations
  • Menu visibility is 2-tier: ① the menus the platform administrator provides to the tenant → ② the tenant master's per-rank permissions + per-user exceptions (the Menu access card in [Settings]). Typing a URL directly is re-validated and blocked by the server
  • The owner-visibility policy (ACL) applies on top of feature permissions

02

Customer Widget

2.1 Screen layout

  • The launcher on the shop page (position·size·icon set by the tenant theme settings) → panel (full screen on mobile / floating card on desktop)
  • Header: store display name (or logo), language switcher (6 languages en/es/ko/vi/ja/zh — switching also updates the session language on the server, changing the AI answer language), settings (gear), close
  • Tabs: notifications / orders / chat — shown tabs·order·position (top/bottom) follow the tenant settings. With only one tab, the tab bar itself hides

2.2 Notifications & orders tabs

  • Notification tab chips: All · Events / order tab chips: Orders (order list) · Shipping · Reviews · Inquiries. Turning one tab off absorbs its chips into the remaining tab — disabling a tab never loses the feature
  • Items: icon·title·status badge·body·relative time·unread dot. The latest unread item is highlighted
  • Order detail: line items·totals·shipping-tracking stepper·track shipping·Ask about this order (feeds the order number into chat)·per-item review writing (1–5 stars + comment)
  • The inline order list shows only the recent window — "See more" links to the shop's own My Page (the order list on Cafe24, the account page elsewhere)

2.3 Chat tab

  • Top: AI-consultation disclosure + End chat link (only while in progress)
  • Consent banner: shown on first entry or when the notice version changes — before consent, personal-data features are restricted
  • Scenario buttons: the quick menu the tenant configured (6 defaults). Product help opens a submenu (usage·ingredients·exchange/return·restock). After an answer, quick chips (my orders/shipping/returns/connect to agent)
  • Identity verification, 2 methods: ① store login — redirect (default)/popup, Cafe24·Shopify login paths handled automatically, widget auto-reopens on return ② guest order lookup — order number+email (rate-limited)
  • Attachments: images ≤10MB (HEIC auto-converted) / files ≤20MB (pdf·txt·csv·docx·xlsx), max 5 per message
  • Consult category picker: if consult categories are shown, [Connect to an agent] first brings up a "What do you need help with?" card → connected to the group responsible for the chosen consult category. The same card appears when the AI hands off (one reconnect on the first pick while no agent has accepted). [Skip] connects as before (14.1)
  • Waiting indicators, 3 kinds: AI generating / agent responding / awaiting handoff
  • Closing·satisfaction: a closed conversation shows a satisfaction card (5-level emoji = 1–5 points) within 24 hours. Sending a new message starts a new conversation

2.4 Settings (gear)

  • Consent management: view status·time·version, withdraw (2-step confirmation — withdrawal stops the conversation), re-consent
  • After login: marketing opt-out (a single toggle — declines promotions·coupons·review requests; order·shipping notifications unaffected), do-not-sell/share (CCPA/CPRA), export my data (JSON), delete my data (2-step confirmation — on completion the widget resets to logged-out)
  • The category×channel subscription matrix was removed from the widget — relocated to store policy (the console's notification channel settings)
03

AI Response Flow (Summary)

Customer message → intent classification (identity-verification prompt if personal data is needed)
  → if policy-forced handoff (deny-list) matches:
      "No answer" rule → straight to an agent with no AI
      "Answer, then hand off" rule → answer from knowledge first, then hand off anyway
  → knowledge search (RAG) → answer generation (persona+rules, confidence scoring) → moderation
  → confidence sufficient: answer + sources to the customer / low·blocked·customer request: agent queue
  • Agent-sent messages pass moderation identically (non-bypassable; blocked on failure)
  • How to adjust each point: Knowledge & AI Manual

Live Chat Console

/live-chat · holders of the consult label

Three columns: queue (left) — conversation (center) — context (right). Lists auto-refresh every 5 seconds.

4.1 Queue (left)

  • Scope: All / Needs attention / Closed (default All — conversations the AI is handling are shown too). The Groups tab on the second row is session grouping (4.5)
  • Channel filter + AI-agent filter + customer name/email search. Channels: Widget·Telegram·Viber·Zalo·LINE·WhatsApp·WeChat·KakaoTalk·SMS·Email — btbz-relay conversations show their original messenger name. SMS is receive-only (badge)
  • Each row: session alias (editable inline), channel·status badges, the assigned AI-agent chip, an "auto-reply OFF" chip, the last message, elapsed time
  • Pin: hover a row for the pin icon — pinned conversations always sit on top, team-shared, max 3 per store (a 4th is refused)
  • The filter/search rows stay fixed while scrolling — only the inner area of each of the 3 panes scrolls

4.2 Conversation (center)

  • Auto-reply control: Follow channel default / Automatic / Send after approval / Off + state badge. Once an agent takes over, agent handling takes precedence
  • Buttons: [Accept] (take over) · [Hand back to AI] (only from agent state, confirmation modal) · [End] · [Sync] · [Pin/Unpin] · [Assign] (change the owner to another AI agent or human agent — an AI-agent change applies from the next response)
  • 4 customer-message actions (hover a customer bubble; hidden while the AI auto-answers): Translate (console-only translated bubble) · Look up in knowledge (copies into the right panel and queries) · Quote reply (quote chip → assembled on send) · File this message as an issue (excerpt+type+memo; added as a memo when an issue already exists)
  • Send-after-approval mode: review the AI draft in an editable panel (with confidence) → [Approve & send] (in the agent's name; moderation·audit identical) / [Discard]
  • Composing messages: text + attachments (same limits as the widget). A refused send = moderation block. The SMS channel is receive-only (composing disabled)
  • Under an AI bubble, [Save as knowledge] (master/director) — captures the answer as a knowledge document draft

4.3 Context (right)

  • AI briefing: summary·intent·sentiment·recommended actions (when a group is selected, this spot becomes the customer journey report panel — 4.5)
  • Knowledge lookup: ask the knowledge base directly mid-conversation → answer·sources (stale/conflict badges) → [Send to customer] / [Edit & send] / [Propose as knowledge] (queued for approval)
  • Customer card: name·email·phone·tier + customer matching/creation · recent orders card
  • Issue panel (native workflow): issue number·status·type·reopen count, [Resolve]/[Decline] (reason required), reassignment, event timeline

4.4 Handoff alerts·Alarm center·auto-wrap-up

  • Escalation alarm: on a new handoff, a popup within 10 seconds — the reason plus hotel·region·consult category, Assigned: agent name ("Everyone" when no rule matched), and the rule name. Visible to every agent; alarms assigned to another agent are marked Assigned to someone else
  • [Close] = marked read on your screen only (the assignee's alarm·re-alerts stay) · [Open chat] = goes to the conversation; if you are the assignee or the alarm is for everyone, it is acknowledged (re-alerts stop)
  • Header 🔔: unread count + latest 20 → View all opens the Alarm center (/live-chat/alerts): All/Assigned to me/Everyone·status·period·consult category filters, click a row to go to the conversation, [Acknowledge]
  • Alarm settings (personal): popup (All alarms / Only those assigned to me (incl. everyone) / Off) · sound (with preview) · browser desktop notifications (permission required) · email me when assigned. Even with the popup off, alarms stay in 🔔 and the Alarm center
  • The conversation header shows the consult category badge the customer picked (Consult: Payment) + a system line
  • Idle auto-wrap-up (server, widget channel only): 30 min silence on both sides → "Is there anything else we can help with?" → closed after 1 more silent minute. Conversations older than 7 days close quietly. Conversations awaiting an email reply are never auto-closed

4.5 Session grouping·customer journey report

  • [Select] in the list header → check 2+ sessions → [Create group]: timeline (one customer's sessions) / project (parties of one case) — new group or add to an existing one
  • Group room (the Groups tab): merged timeline of member sessions. Sending is 1:1 — pick a recipient first. Dissolving a group keeps every conversation and message
  • Customer journey report: [Generate report] → ① Summary ② Contact history ③ What they ask ④ Resolution time ⑤ Customer path (5A) ⑥ Needs (hypothesis) ⑦ Next actions. Numbers counted by code; only the narrative by AI. Two reports can be compared (deep-dive)
  • Writing criteria (section on/off·sample cap·banned phrases) live in Journey report criteria under [Tenant settings → Other settings] (master) — saving mints a new version; old reports keep theirs

Issue Board

/issues · native-workflow tenants only
  • Kanban columns: Open → In progress → Resolved/Declined → Closed (only allowed moves can be dragged — on touch, use the card's move selector)
  • Top KPIs: open·in progress·unassigned·average resolution time·reopen rate (30-second refresh)
  • Cards: issue number·type·SLA badge (⚠️ approaching / 🔥 exceeded)·reopen count·session alias·customer's last utterance·assignee·urgent/normal toggle
  • Declining requires a reason (policy-impossible/misassigned/spam + memo). Reopening is possible after resolve/decline
  • Card click → read-only preview of the last 10 turns (viewing is audit-logged) → [Open session]
  • [File this message as an issue] in live chat (4.2) also creates issues
  • SLA baseline hours (normal/urgent, 1–168h, defaults 24h/4h) are set on the [Tenant settings → Agent handoff] tab
  • The workflow mode (native or not) is the platform administrator's Plan/Add-ons setting (Ch. 16) — menu provided without the mode shows only a notice screen

Conversation History

/history
  • Filters: period · assignee (consult label) · status · escalation · message body search (runs via the button — audit-logged) · include preview conversations
  • Row click → full conversation: customer/assignee/channel/language/start·end + per-utterance bubbles. Every AI answer shows evidence-document chips (title+similarity, jumps to the knowledge document) and a confidence badge — you can trace why it answered that way. Handoff moments carry a reason badge

Work Log

/work-log

The audit trail of agent actions (an agent lens over the same store as the admin audit log). Filters: period·agent·action (accept/message sent/customer linked/customer created/closed/conversation viewed/full-text viewed). Columns: time·agent·action·target·result (success/failure).

08

Statistics

/statistics · one shared date filter (default 30 days)
  • 6 sections — Question analytics / Channels / Agents / Outcomes / Satisfaction / Hours
  • Question analytics: 4 sub-tabs (intent/knowledge used/keywords/similar-question groups) + trend chart. ⚠ rows = high escalation or low confidence — your knowledge-reinforcement priority list. Daily snapshots survive log deletion; a banner warns when aggregation stalls 2+ days
  • Channels: conversations·customer messages·messages per conversation (median)·handoffs — read the median first (one huge conversation skews the average)
  • Agents: an AI-agents table + a human-agents table (conversations·replies·resolved·satisfaction, rating counts alongside)
  • Outcomes: resolved (customer rated/agent closed/closed after confirmation) vs unresolved (in progress/no closure/customer spoke last) — the same definition as the journey report and dashboard
  • Satisfaction: average·responses·response rate·distribution + per-agent/per-session tables
  • Hours: weekday×hour grid — in the tenant's timezone (UTC warning when unset)
  • Channels·Agents·Outcomes·Hours compute from logs — history beyond retention is not queryable (Question analytics·Satisfaction persist as snapshots)

Dashboard

/dashboard

6 KPIs (each linking to its screen): conversations in progress · today's notifications · AI resolution rate · unresolved Top N · total conversations · total orders. AI resolution rate = the share of ended conversations whose question was not left unresolved (same definition as statistics Outcomes·the journey report) — conversation counts exclude preview sessions. Popular questions ranking, integration status (badge per provider — "connected" means the connection test passed, not merely saved), 5 most recent orders.

A read-only list of orders synced from the platform (order number·status·amount·item count·date).

Knowledge & AI Settings

Knowledge registration (manual/catalog/CSV/external sources), validation (QA panel·conflict review·gap proposals), AI settings (agents·persona·rules·scenarios·engines·moderation·answer reuse), and the improvement loop (preview·coaching·regression checks) are all organized in the Knowledge & AI Setup Manual.

  • The AI answers only from active knowledge documents — frequent handoffs mean missing knowledge
  • Knowledge is drafted·reviewed on the Smart Knowledge Board (/knowledge/board) first, then adopted into the KB (with pre-adoption simulation) — direct adds are for emergencies
  • 3 groups (CounselInfo/ProductInfo/OperationInfo) × categories — a category's agent scope can limit it to specific AI agents
  • Bulk tools: bulk download ↔ bulk import (CSV/XLSX round trip) · AI import (pdf·docx·xlsx·csv·md·YouTube captions → draft review → board publish)
  • All outbound messages (AI·agent) pass moderation — on error, safely blocked
  • AI coaching·settings changes go through an approval gate — review proposals before applying

14.1 Agent handoff — consult categories and routing rules

  • Consult category = the consult topic the customer picks in the widget. [Manage consult categories] in the routing rules header: code (cannot be changed after creation)·name·order, Shown/Hidden (only Shown appear on the widget card; new ones default to Shown), per-language names. One used by a rule·team·label cannot be deleted. 👁 on a rule chip = shown to customers
  • Routing rules: from the top, connected to the agent group (team × label)·individually designated agents of the first rule whose consult category · topic · customer information all match. If none, the assigned agents; if none either, everyone is notified
  • The Consult category line compares only the value the customer picked (no pick → only rules with an empty consult category) · label chips on the Topic line are for policy (deny) handoffs only — pick group labels under Assignee · Customer information: Region (North·North Center·Central·South Center·South)·province·language·verification level·customer tier/type·hotel·role·entry path
  • Example: Payment · South = Payment + Region South·South Center → team South × label accounting. When the customer picks a consult category, its rules are followed instead of previous-agent-first
  • Check routing: enter consult category·region·province·language → see, using the unsaved rules, who it goes to and why rules were skipped (consult category mismatch·region condition mismatch·0 assignable agents, etc.). No alarm is sent
  • Warnings (do not block saving): topic-label misuse · region name in the rule without a region·province condition · 0 assignable agents (members yet to accept their invitation are shown)

FAQ / Troubleshooting

Q. The bot keeps handing off to agents.
Missing knowledge is the most common cause. Find the cause via the ⚠ rows in statistics and the knowledge QA panel, then reinforce the documents. Also check whether the keyword matches the deny-list — a "No answer" rule skips the AI intentionally, and an "Answer, then hand off" rule calls an agent even after answering. The document's category may also carry an agent scope hiding that knowledge from the current agent.
Q. An agent's reply won't send.
That is a moderation block. Rephrase and retry; if the rules are excessive, ask the master to adjust them.
Q. A conversation closed by itself.
That is idle-conversation auto-wrap-up (30 min silence → notice → close). When the customer messages again, a new conversation starts.
Q. I can't see the issue board.
It is exclusive to tenants whose workflow mode is native — check the admin Plan/Add-ons setting says native. If the menu itself is missing, check the provided menus/rank permissions (2-tier).
Q. The settings screen looks different from older descriptions.
/settings has 8 tabs (Tenant settings, Ch. 14). Since 2026-10-24, agent handoff has its own Agent handoff tab; menu access is on the Other settings tab.
Q. A customer asked for an agent, but the consult category card doesn't appear.
Check in [Agent handoff → Manage consult categories] that at least one consult category is Shown. If none are shown, the conversation connects directly without the card.
Q. I created a rule, but conversations aren't assigned to the team I specified.
Enter the same conditions in Check routing above the rules to see why rules were skipped. Common causes: label chips on the topic line, a missing region condition, team members yet to accept their invitation (0 assignable agents).
Q. Dashboard/statistics numbers dropped.
Can be normal — conversation counts now exclude preview sessions, and with the unified "resolved" definition, conversations where the customer spoke last no longer count as resolved (Ch. 8·9).
Q. I changed widget settings but nothing changed.
The widget reads new settings from the customer's next session. Close and reopen the widget, or refresh.
Q. A customer isn't receiving notifications (email, etc.).
Check ① the channel is enabled in the console's notification channel policy ② the customer opted out of marketing (affects promotional messages only). A channel the store disabled cannot be enabled by the customer.
Q. I changed temperature but answers stayed the same.
temperature is not applied to Anthropic (Claude) engines (the model rejects it, so it is not sent). Only max_tokens is effective.
Q. It works even though there is no AI key.
Those are demo responses from the stub adapter. Be sure to register and assign a real engine before production.
Q. I hid a review but the customer still sees it.
That is by design — hiding only removes store exposure; the review stays visible to its author.
